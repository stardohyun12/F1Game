# Designer Report — Cycle 4 (2026-04-30 main)

## 선택한 각도
**후보 1 — OrderBoard 호버 → 마커 강조 UX 효과 (사용자가 호버 의도를 인지하나?)**

선택 이유: C3에서 "좋은 시각적 인과"로 한 줄만 언급되었으나 실제 인지 가능성은 검증되지 않음. C1·C2·C3은 정보 부재/단조 우열만 다뤘고, "이미 있는 좋은 신호의 인지율"은 사각지대. 카드와 마커는 화면 양 끝(우측 보드 vs 좌측 맵)에 분리되어 있어 동시 시야 확보가 의문.

## 분석

**메커니즘 (OrderBoard.cs:203~296):** 카드 호버 시 `OnCardHoverEnter` → 해당 인덱스의 마커는 `job.color` + dimmed=false, 나머지 마커는 `Color.gray` + dimmed=true. 호버 종료 시 `lastSelectedJob.color`로 리셋. 즉 **3상태 구조** — (a) 호버 없음: 선택된 주문 색만 표시, (b) 호버 중: 호버한 1개만 강조 + 나머지 회색, (c) 선택 후: 호버 종료 시 선택색 복귀.

**인지 갭 1 — 시야 분리.** 주문 카드는 화면 우측, 맵 마커는 좌측~중앙 (DeliveryPointMarker는 월드 좌표 기반). 신규 플레이어가 카드 위에 마우스를 올린 순간 시선은 카드 텍스트(보상/시간/화물)에 고정. **마커가 동시에 색을 바꾸는 것을 보지 못할 가능성이 매우 높음.** 호버→마커 인과는 "마우스를 카드 영역에서 떼서 맵을 보는 순간"에야 학습되는데, 그 시점에 마커는 이미 회색 폴백 또는 lastSelectedJob 색.

**인지 갭 2 — 회색 폴백의 의미 모호.** 비호버 상태에서 카드 3장이 있으면 마커도 3개여야 직관적이지만, 코드는 `lastSelectedJob.color` 단일 색으로 모든 마커를 칠함 (line 281). 즉 "어느 카드가 어느 마커인지" 1:1 매핑이 호버 중에만 노출. 호버를 떼면 정보가 사라짐. **결정에 필요한 정보가 호버라는 일시 행동 동안만 존재** — 비교 결정(카드 A vs B 어디가 더 가까운가?)은 두 카드를 번갈아 호버하며 단기 기억으로 비교해야 함. 인지 부하 큼.

**인지 갭 3 — 마커 색이 화물색인지 주문 식별색인지 모호.** `job.color`는 OrderJob SO의 단일 색 필드. 화물 5종 색상 표기와 분리되어 있는지 합쳐져 있는지가 카드 UI에서 안 보임. C3에서 "호버→마커 색 일치 강함"이라 평가했지만, 색 의미가 "주문 ID"인지 "화물 종류"인지 혼동 가능.

## 발견 (가치값 변경 X)
- 호버→마커 강조는 **시야 분리로 인해 인지율이 의도보다 훨씬 낮을 가능성**. 호버 중 카드 텍스트에 시선이 고정되어 마커 변화 미관찰.
- **상시 1:1 매핑 부재** — 비호버 상태에서 카드별 색 점이 카드 위에 작게라도 노출되면, 호버 없이도 "카드 A=빨강 마커=북동쪽" 매칭이 즉시 가능. 호버는 보조 강조로 격하.
- 회색 폴백은 호버 종료 직후 정보를 즉시 소실시켜 비교 결정에 불리. 이 메커니즘이 의도대로 작동하려면 호버 중 카드와 맵을 동시에 볼 수 있는 시선 경로가 필요한데, 우측 카드 패널 + 좌측 맵 레이아웃은 이를 어렵게 함.
