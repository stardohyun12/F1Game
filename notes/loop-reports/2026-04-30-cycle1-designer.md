# Designer Report — Cycle 1 (2026-04-30 main)

## 세션 16 후속(A) 리팩터 디자인 영향
- **결정 의식화**: 포장 선택이 OrderBoard와 같은 화면이 아니라 별도 모달(`PreRunSetupPanel`)로 분리됨. 주문 카드 클릭 → 포장 패널 Show → 출발 버튼이라는 3-step funnel로 강제됨. "그냥 카드 누르고 출발" 패턴이 차단되어, 매 런마다 포장 결정에 손이 한 번 더 가야 함 → 결정 의식화 ↑↑.
- **인지 부하**: 정보가 시간축으로 분할됨. 주문 카드 3장(화물/포인트/보상/시간)을 먼저 비교 → 결정 후 포장 카드 4장(배율/설명/가격)을 비교. 한 화면에 3×주문카드 + 4×포장카드 = 7카드 동시 노출이 사라져 "decision overload" 완화. 단점: 주문 카드 시점에서 "이 화물에 어떤 포장이 적합한가" 사전 계산이 어려워짐. 화면 전환 후에야 cargoTipText("→ 급가속·급제동 금지")로 환기됨.
- **결정 트레이드오프 가독성**: `totalCostText`가 "포장비 ₩X / 예상 보상 ₩Y" 1줄로 노출 → 트레이드오프가 한 줄에 명시됨. 카드별 배율(×1.0~×2.0) + 가격이 4장 횡렬 비교 → 가격↔자유도 곡선이 시각적. 가독성 ↑.

## 포장 vs 업그레이드 시간축 충돌 — UI 영향
- **출발 화면 "포장비 ₩X / 예상 보상 ₩Y"**: 포장 비용이 즉시 보상 대비로 계산됨. 효과 — 플레이어가 "이 런에서 ROI"만 본다. 예: Hardcase ₩800 vs baseReward ₩500이면 즉시 손해로 보임 → Hardcase 회피 압력.
- **갭 — 업그레이드 비용은 어디에도 없음**: 정산에서 업그레이드를 사려면 자금 누적이 필요한데, 출발 화면에는 "장기 자금 풀"이 보이지 않음. 즉 단기(이번 런 ROI)만 보이고 장기(업그레이드 저축)는 안 보임 → Hardcase가 "안전 보험"이 아니라 "낭비"처럼 보임. 시간축 충돌(이전 cycle 2에서 발견)이 UI에 그대로 노출됨.
- **현재 보상 vs 포장비 비교만으로는 화물 파괴 시 페널티가 안 보임**: 보상 ₩500이 보장 보상처럼 표시되지만 실제로는 포장 부족 시 데미지로 까임 → "예상" 단어가 약함. 단 가치값/문구 변경 제안은 본 사이클 금지.

## 새 디자인 갭 (있으면, 가치값 변경 제안 X)
1. **주문 카드와 포장 카드 사이 "화물 ↔ 포장 적합성" 시각 신호 부재**: 계란/유리/활어/케이크 4종은 각자 극민감 축이 다른데(Shock/Impact/Spin/Tilt), 포장 4종은 단일 임계 배율만 적용. UI에서 "이 화물에는 이 포장이 특히 좋다" 매칭 힌트가 없음 → 결정이 "비싼 거=안전" 단순화로 수렴. PackingTier.cs 주석에도 "Phase 2: 포장 종류별 차등"이 적혀 있어 의도적 미구현이지만, 현재 UI는 차등이 있는 것처럼 4카드를 동등 노출 → 디자인 의도와 표현 mismatch.
2. **OnCancelClicked 흐름의 결정 보존 부재**: 취소 시 OrderBoard.Open()으로 돌아가지만 selectedTier는 초기화됨(다음 Show에서 defaultPacking으로 리셋). 같은 주문을 다시 골라도 포장 선택이 휘발 → 비교 탐색(주문A→포장→취소→주문B→포장) 시 인지 부하 증가. 이건 코드 동작 관찰이지 가치값 변경 아님.
3. **cardsSpawned 영구 보존이 화물 변경 비반응 위험**: 카드는 1회 인스턴스화 후 재사용. PackingCardUI.Bind는 tier 텍스트만 표시하고 화물별 가이드는 표시 안 함 → 화물이 바뀌어도 포장 카드 설명은 동일 ("일반 주행 안전" 등). 화물 종속 안내는 cargoTipText 한 곳뿐. 정보 분산.
