# 3D 포장 미니게임 — 설계

## Context

세션 21에서 기획서 W1~W6 순서를 폐기하고 다시 우선순위를 짰다. 결론: 차고/부품 복원은 도현이 추후 직접 결정, 즉시 작업은 **3D 포장 미니게임 하나**.

마이크로 루프 USP(한 잡의 깊이)를 만드는 시스템. 기존 4단계 PackingDef SO 시스템(D-049)을 **갈아치움**. 정식판에서 실제 3D 모델(가전·F1 부품 등)로 확장될 자리.

데모 데드라인 2026-06-24 (6주) 유지. 본 미니게임 단독 추정 1.5~2주 + 정산 통합 0.5주.

## 시스템 개요

잡 선택 후, 운전 진입 전 단계.

```
[잡 보드 — 1 택배 = 1 목적지]
   ↓ 선택
[3D 포장 미니게임]  ← 본 문서
   ↓ "출발" 확정
[운전 → 배송 → 정산]
```

한 잡당 물건 1~3개 결합 가능. 각각 따로 포장 (한 미니게임 안에서 물건 전환 탭으로).

## 화면 구성

작업대 도제 (가운데 화물, 좌우 사이드 패널).

```
┌────────────────────────────────────────────┐
│ ◀물건 1/3▶            [출발하기]            │  ← 상단: 물건 전환 + 확정
├────────────┬──────────────────┬────────────┤
│ 재료 선반   │                  │ 비용 표시  │
│            │                  │            │
│ ┌────────┐ │   [3D 화물 모델]  │ 부블랩 ₩200│
│ │부블랩 1│ │   가운데 작업대   │ 폼     ₩0  │
│ │ ₩50/회 │ │                  │ 하드    ₩0 │
│ └────────┘ │   (WASD 회전)     │ ───────── │
│            │                  │ 합계  ₩200 │
│ ┌────────┐ │   마우스 누르며   │            │
│ │폼 2    │ │   드래그하면      │ 평균 커버  │
│ │ ₩120/회│ │   랩 띠 펼침      │ ████░░ 67%│
│ └────────┘ │                  │            │
│            │                  │            │
│ ┌────────┐ │                  │            │
│ │하드 3  │ │                  │            │
│ │ ₩300/회│ │                  │            │
│ └────────┘ │                  │            │
│            │                  │            │
│ 랩 폭 ▬▬▬   │                  │            │
└────────────┴──────────────────┴────────────┘
```

ResultPanel/PreRunSetupPanel 패턴 그대로 (procedural UGUI, UITheme.Active 색상).

## 인풋 모델

음식 랩 두르는 메타포 — **점 페인트가 아니라 일정 폭의 띠를 감음**.

- **WASD** = 3D 화물 회전 (yaw/pitch)
- **마우스 좌클릭 누름 시작** = 랩 띠 시작점 고정
- **누른 채 드래그** = 마우스 경로 따라 일정 폭의 띠가 표면에 펼쳐짐 (raycast로 hit UV들을 모아 두께 있는 strip 생성)
- **떼면** = 띠 한 조각 종료. 다음 누름 = 새 띠 시작
- **1/2/3** = 재료 전환 (부블랩/폼/하드케이스)
- **마우스 휠** = 랩 폭 (띠의 굵기)
- **R** = 회전 리셋 (편의)

시간 제한 없음. calm crafting.

## 게임 룰

### 재료 3종

| 재료 | 비용/회 | 보호도 | 시각 |
|---|---|---|---|
| 부블랩 | 싸 | 약 | 옅은 파랑·반투명 |
| 폼     | 중 | 중 | 노란·불투명 |
| 하드케이스 | 비싸 | 강 | 진회색·불투명 |

비용 = 칠한 면적 × 단가. 보호도 = 충격 흡수율(0~1).

### 덧칠

같은 부위 위에 다른 재료 덧칠 가능. **최상위 재료만 보호도 적용**. 아래 레이어 비용은 이미 지불 (낭비 가능성).

### 완료 조건

자유. 0%부터 100%까지 어디서든 "출발" 가능. 포장 정도 = 손상 차단율.

### 충격 → 손상 매핑

기존 CargoBox 손상 인과(D-068)와 통합:

```
차 G → 박스 슬라이드 → trunk 벽에 박음
   ↓
충격 방향 벡터 → 화물의 정렬된 면(또는 가장 가까운 표면 영역) 결정
   ↓
그 영역의 wrap 상태 (재료 최상위 + 커버리지) → 흡수율 계산
   ↓
흡수 못한 만큼 손상 누적 → 정산 시 보상 차감
```

화물 자체에 면 단위가 아니라 텍스처 단위로 wrap 상태가 있으므로, 충격 지점 = 충격 방향 벡터를 화물 mesh에 raycast해서 UV 좌표 추출 → 그 좌표 주변 반경의 wrap 상태 평균.

> 메타포 주의: 입력은 "랩 띠 펼치기"지만 충격 흡수 계산은 "그 지점 픽셀 평균"으로 동일. 즉 사용자에게 보이는 행위(띠)와 손상 계산(픽셀 평균)은 분리. 띠가 굵을수록 한 번에 더 큰 영역이 칠해지므로 자연스럽게 같은 결과.

## 기술 구현 핵심

**Texture painting 패턴 (랩 띠 변형)**:
- 각 화물에 wrap-state RenderTexture (예: 256x256) 부착. R/G/B 채널 = 각 재료별 커버리지.
- 마우스 누른 동안 매 프레임 raycast → hit.textureCoord 샘플 누적.
- 인접 두 샘플을 잇는 사각 strip을 RenderTexture에 그림 (= 띠 한 조각). 두께 = 랩 폭. 브러시 stamp 아님.
- 셰이더로 wrap-state를 화물 표면에 시각 오버레이 — 가장자리는 깔끔한 직선 (랩 느낌). 페더링 X.
- 커버리지 % = R/G/B 채널 비제로 픽셀 카운트 / 총 픽셀.

Unity primitive (Cube, Sphere)는 UV 있어 그대로 동작. 추후 실제 모델은 UV 있는 mesh만 import하면 swap.

## 기존 시스템과의 통합

| 항목 | 처리 |
|---|---|
| `PackingDef` SO 4종 (None/Bubble/Foam/Hardcase) | **삭제**. 새로 만드는 `WrapMaterialDef` SO 3종으로 대체. |
| `PreRunSetupPanel`의 4단계 카드 UI | **삭제**. 3D 포장 화면으로 교체. |
| `CargoBox.protectionMultiplier` (1.0~2.0) | **갈아치움**. `WrapState` 컴포넌트가 충격 방향+UV로 흡수율 동적 계산. |
| `CargoShakeSimulator`의 손상 계산 | 흡수율을 입력으로 받아 손상 차감. 인터페이스 변경 0.5일. |
| `OrderJob.pointCount` 다중값 | **1 고정**. 한 잡 = 한 목적지. 다만 잡당 물건 1~3개 결합은 `OrderJob.itemCount` 신규 필드로. |

## 위험

- **Texture painting 셰이더** — 처음 만들 시 1~2일 슬립 가능. 검증 안 되면 mesh face 단위 fallback (6면 큐브 → 6 셀, 구 → 12 셀 등). UV-paint가 진척 안 보이면 fallback로 빠질 결정 포인트 = day 3.
- **충격 방향 → UV 매핑 정확도** — raycast 안 맞는 케이스 (충격 지점이 화물 안쪽 또는 모서리). 어림셈 fallback: 충격 방향에서 가장 가까운 표면 normal과 일치하는 면.
- **데모 일정 전체** — 본 미니게임 1.8주 + 나머지(차고·맵해금·내비·박스크기·폴리시·QA·Steam 자산) ≈ 6주 한계. 양보 결정은 도현이 차후.

## 검증

- unity-cli `exec`로 `WrapState` 컴포넌트가 RenderTexture 그리는지 확인.
- unity-cli `editor play`로 Cube 페인트 → 출발 → 한 런 → 정산 풀 사이클.
- 손상 차감이 wrap 상태에 비례하는지 ResultPanel 숫자로.
- 메모리: 256x256 RGB24 RenderTexture × (잡당 최대 3물건) = 약 600KB. 무난.
