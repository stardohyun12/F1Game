# GDD — 코어 루프

## 마이크로 루프 (한 런 내부)

한 런 = 한 그랑프리 = 약 5~10분.

```
1. 주문 보드 오픈    (~30초)
2. 주문 선택         (~1분)    ← 결정 1: 무엇을 배달할지
3. 경로 계획         (~1~2분)  ← 결정 2: 어떻게 돌지
4. 출발 세팅         (~30초)   ← 결정 3: 타이어/연료 세팅
5. 주행              (5~8분)   ← 실시간 컨트롤 + 피트 타이밍
6. 정산 화면         (~30초)
7. 업그레이드 상점   (~1분)    ← 결정 4: 무엇에 투자할지
```

**한 런에서 플레이어가 내리는 핵심 결정 = 4개.**
이게 로그라이트의 결정 밀도. 너무 적으면 지루, 너무 많으면 과부하.

## 주행 단계 세부 루프 (가장 긴 구간)

```
배달지 도착 → 배달 완료 연출 → 다음 배달지로 출발
  ↑                                   ↓
  └─────── 피트스탑 (선택적) ──────────┘
```

매 배달지 사이 구간 동안 플레이어가 실시간으로 관리하는 것:

- **속도 vs 안전** (화물 데미지 누적 감시)
- **코너 진입 속도** (타이어 마모 vs 통과 시간)
- **부스트 사용 타이밍** (연료 관리)
- **피트 필요성 판단** (남은 거리 예측)

## 매크로 루프 (세션 전체)

```
[신규 런 시작]
  ↓
[마이크로 루프 N회 반복]
  ↓
세션당 3~5런 플레이
  ↓
[언락 요소 해제]
  - 새 서킷
  - 새 차량
  - 새 업그레이드
  ↓
[다시 신규 런]
```

## 진행 단위

- **런 (Run)** — 1회 배달 투어. 5~10분.
- **시즌 (Season)** — 여러 런의 묶음. 최종 보스/목표 존재. (MVP 이후 기능)
- **커리어 (Career)** — 전체 게임. 차량/서킷/팀 전부 해제.

MVP에서는 "런 반복 + 영구 업그레이드" 구조만 구현.
"시즌" 구조는 MVP 이후 확장.

## 실패 조건

한 런은 다음 경우 실패로 처리:
- **연료 고갈** → 견인. 시간 대량 손해 후 다음 배달지부터 재개.
- **화물 전파** → 그 화물은 환불. 다른 배달은 계속.
- **시간 초과** → 런 종료, 남은 주문 실패 처리.

**"런 중 게임오버는 없다."**
무조건 끝까지 가서 정산을 받는다. 로그라이트 텐션은 "얼마나 잘 끝냈나"에서 나온다.

## 성공 지표

한 런의 성공 = 다음 세 가지의 함수:
1. **수익** (화물 완수 × 화물별 보상)
2. **평판** (배송 속도, 화물 무결성)
3. **효율** (연료 소비, 타이어 소비 대비 수익)

플레이어 스타일에 따라 어느 지표를 중시할지 다름.
업그레이드 경로가 스타일별로 분기.

## 루프가 재밌기 위한 조건 (개발 중 계속 체크)

- [ ] 계획 단계에서 **실제 고민**이 발생하는가?
- [ ] 주행 중 **계획을 수정할 순간**이 있는가?
- [ ] 같은 지도여도 **매 런이 다르게** 느껴지는가?
- [ ] 실패한 런도 **무언가 배웠다는** 느낌이 드는가?
- [ ] 업그레이드 하나가 **다음 런의 감각을 바꾸는가**?
