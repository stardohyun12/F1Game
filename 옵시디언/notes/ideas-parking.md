## 창업 아이디어 (게임과 별개 — 데모 이후 검증)

### 멀티에이전트 "작업실" 시각화 앱 (2026-05-23, 도현)
- AI 에이전트 여러 명을 *실제 사무실 직원처럼* 보여주는 시각 인터페이스 — 누가 무슨 일을 하고, 진행 상황·역할·결과물이 공간(책상/방)으로 보임.
- 계기: Claude Code 터미널이 글 위주라 답답 → 멀티에이전트가 "표"가 아니라 "사람들이 사무실에 있듯" 보이면 좋겠다.
- 시장성: 멀티에이전트 오케스트레이션 시각화는 뜨는 분야 (Agent View 등 초기 단계). 차별점 = 공간/캐릭터 메타포.
- **상태: 보류.** 지금 만들면 게임 데모(D-32, 6/24) 죽음 = ExulMundi 스코프 함정. 데모 이후 또는 B트랙(하네스 연구)으로 따로 검증. PoC는 brainstorm Visual Companion에 office-v2.html로 맛보기 존재.

## v1 MVP 이후 고도화 파이프라인 (세션 13 기록)

> 도현이 세션 13에서 제안한 방향성. MVP 완성 후 v2에서 이 4개를 묶어 **"Pacific Drive 스타일 허브 + 운송 시뮬"** 레이어로 통합 검토.

### H1. 허브 씬 (별도 씬) — **✅ 세션 14 MVP 편입 (D-040)**
- **상태:** 4주차 "허브 → 런 → 허브" 메타 루프와 통합 확정. 도현 결정 "시작 전 + 정비 장소로".
- **설명:** 메인 주행 씬과 분리된 "차고/창고" 씬. 런 시작 전 여기서 화물 선택/배치/차량 튜닝 → 런 씬 전환 → 완료 후 허브 복귀 정산.
- **왜 지금 아닌가:** 씬 분리는 데이터 전달(ScriptableObject persistence or save system) + 씬 전환 UX + 2개 씬 동시 유지보수 비용. 2주차 시스템 재미 검증 전 도입하면 완성 실패 리스크.
- **예상 이관 시기:** 4주차 "허브 → 런 → 허브" 메타 루프와 통합. 그때 자연스럽게 포함.
- **참조:** Pacific Drive의 "차고 → 탐험 → 차고" 구조, Forza Horizon의 "Festival Site".
- **GDD 영향:** `GDD/overview.md` USP ① "결정 밀도"의 **상위 결정 공간**이 됨 (런 밖 결정도 의미 있어짐).

### H2. 차량 내부 화물 공간 + 배치 UX
- **설명:** 차 뒤쪽에 고정된 격자 공간 (예: 4×3 셀). 허브 씬에서 화물을 드래그로 배치 → 무게 중심, 셔크 노출 방향, 적재량이 배치에 따라 달라짐. Tetris-like 퍼즐.
- **왜 지금 아닌가:** (1) 배치 UX 구현 시간 2~3일, (2) 무게 중심을 차량 물리에 반영하려면 Rigidbody.centerOfMass 튠 + 각 화물 Rigidbody 또는 지표. 2주차 스코프 초과.
- **예상 이관 시기:** v2. H1 허브 씬과 함께. MVP에서는 "A/B/C 주문 선택" 만으로 결정 밀도 확보.
- **참조:** Death Stranding 배낭, Easy Delivery Co. (ResearchFindings), Pacific Drive 차고 인벤토리.

### H3. Shock 시스템 물리 고도화
- **설명:** 현재(MVP 계획)는 "가속도 누적 지표" 단일 숫자. 고도화 버전은 화물별 Rigidbody + 내부 공간 Collider + 실시간 충돌 시뮬. 흔들림이 **보이고** 들림.
- **왜 지금 아닌가:** (1) 물리 성능 — 화물 N개 × Rigidbody Update, (2) 튜닝 복잡도 폭증, (3) MVP "Shock 민감도" 기획은 **지표 기반이 충분**하다고 결정 (D-030, claude-web-findings 리서치).
- **예상 이관 시기:** v2. H2와 세트. 공간이 있어야 물리 시뮬 의미 있음.
- **트레이드오프 메모:** 물리 방식이 실감나지만 시스템 예측 가능성 ↓ → 유저가 "왜 이 런 실패했지" 감지 어려워짐. Feedback 연출(카메라 쉐이크 + SFX)과 세트여야.

### H4. 맵 높낮이 (경사/언덕)
- **설명:** Kenny `road-slant*` / `tile-slantHigh` 에셋으로 오르막/내리막. 세션 11 D-034 카탈로그에 실측 완료.
- **왜 지금 아닌가:** TileMapAuto가 Y=0 고정 → 구조 리팩토링. 차량 경사 물리 재튜닝(기어 변속 + 연료 소비 곡선) = 추가 튜닝 loop 2~3회.
- **예상 이관 시기:** 3주차 "경로 계획" 단계에 자연 통합. 경사 = 연료↑ 속도↓ = 경로 선택지 다양화. 지금 넣으면 확장, 그때 넣으면 MVP.
- **선행 필요:** TileMapAuto에 Y offset 전달 메커니즘 + Cell의 "시작 Y / 끝 Y" 필드 (경사 타일 전용).

### H5. Roundabout 3×3 (Tier B from D-034)
- **설명:** Kenny `road-roundabout.fbx` (3×3 셀) 도입. 맵 중심 Downtown Hub 앵커로 적합.
- **왜 지금 아닌가:** 현재 TileMapAuto는 1×1 셀 가정. 3×3 멀티셀 처리는 BuildingPlacer처럼 별도 분기 필요. 기존 교차로 제거 + 셀 3×3 확보 + 주변 도로 접속 로직 = 반나절 작업.
- **예상 이관 시기:** 세션 13 이후 맵 대확장 시 우선 후보. "Downtown에 가면 큰 원형 광장" = 지형적 앵커 강화.

### H6. 물건 선택 + 포장 레이어 (허브 씬 계획 단계 확장) — 세션 14 신규
- **설명:** 도현 세션 14 아이디어 — "물건을 고르고 어떻게 포장할지까지 게임의 재미 요소로". 런 시작 전 허브(H1)에서:
  (1) 배달할 물건 종류 선택 (Fragile/Heavy/Liquid/Electronics 등 특성 다름)
  (2) 포장 방식 선택 (박스 크기/쿠션/테이프 감기 등)
  (3) 포장 품질 + 물건 특성이 주행 중 Shock 저항에 직접 영향
- **왜 지금 아닌가:** MVP 화물은 박스 1종 스코프. H1 허브 씬 편입(D-040) 후 자연스럽게 얹을 레이어.
- **예상 이관 시기:** MVP 4주차 허브 씬 첫 버전 완성 직후 (5주차~). USP ② "결정 밀도" 직접 강화.
- **설계 힌트:**
  - 물건 종류 × 포장 품질 = 2축 결정 매트릭스. 단순 합산이 아닌 **trade-off**: 좋은 포장 = 비용↑ + 적재 공간↑ / 나쁜 포장 = 절약하지만 파손 위험.
  - 허브 씬 UI: 주문 카드 선택 → 물건 고르기 패널 → 포장 단계(미니 퍼즐 or 선택지) → 출발.
  - 주행 중 HUD는 변화 없음 (Integrity 그대로) — 선택이 시작 상태 값과 damage 계수에 반영.
- **참조:** H1 허브 씬, H2 차량 내부 배치 UX, H3 Shock 물리 고도화. USP ② 결정 밀도.
- **관련:** D-040, CargoBox MVP(박스 HP 100), 세션 14 도현 발언.
