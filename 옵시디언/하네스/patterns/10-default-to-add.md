# 10. Default to Add

## 증상
사용자가 "이거 좀 정리해" / "애매한 것 손봐" 모호하게 요청. AI는 90% 확률로 **기능 추가** 방향을 고름. 새 시스템 도입, 새 UI 패널, 새 옵션. 정작 필요한 건 dead code 삭제·중복 제거·UI 거짓말 정리였음. 코드베이스 점점 부풂.

## 왜 발생 (AI 한계)
- AI는 "도움이 되라"로 학습됨. 추가가 더 "도움"으로 느껴짐.
- 삭제는 "사용자가 원하는 게 맞나" 불안. 추가는 안전한 default.
- 사용자 요청이 모호하면 add 쪽 해석이 default. "정리" 같은 단어를 "확장"으로 잘못 읽음.

## 회피책
- **즉시**: 사용자가 "정리"·"청소"·"애매한 거"·"중복"·"단순화" 같은 단어 쓰면 → **삭제·축소 모드**로 명시 전환. 추가 제안 금지.
- **워크플로**: 매 PR/커밋에 "added X lines / removed Y lines" 비율 봄. 정리 작업인데 net add면 의심.
- **AI 룰**: 모호한 요청 받으면 "정리(delete)인가 / 확장(add)인가" 한 번 확인. 또는 두 옵션 둘 다 제시.
- **사용자 룰**: "기능 추가는 잠시 멈추고, 지금 코드에서 dead/중복/거짓말 5개만 찾아줘" 같은 명시 프롬프트.

## 적용 신호
- "이거 좀 정리" / "이상한 것 손봐" / "애매" / "지저분" 요청
- AI가 새 file/component/class 만들면서 "정리 끝" 보고
- TODO·FIXME·"폐기됨"·"Task XX 미완" 주석이 코드에 깔려 있을 때
- 코드 라인 수가 monotonic 증가만 할 때
- "이번 PR은 net negative line count여야 한다" 명시할 수 있는 작업
