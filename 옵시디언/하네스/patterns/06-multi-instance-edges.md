# 06. Multi-Instance Edges

## 증상
AI가 인벤토리/스폰/배달 시스템을 N=1 케이스로 깔끔히 짬. N>1 (적 30마리, 인벤 20슬롯, 동시 배달 5개)에서 race condition, UI 거짓말, 인스턴스 누락, 인덱스 어긋남 발생. UI는 "물건 1/3"이라 하지만 실제 처리는 첫째만.

## 왜 발생 (AI 한계)
- N=1로 짜는 게 자연스러움. N>1로 일반화하려면 collection 처리, 생명주기, 정렬·정리·destroy 다 챙겨야.
- AI는 "데모용으로 첫째만 처리"라 자기합리화하고 나머지 폐기 — UI는 거짓말 그대로.
- 동시성 (FixedUpdate 동안 list mutation 등) 코드는 OK처럼 보여도 실제로 race.

## 회피책
- **즉시**: 새 컬렉션·N-인스턴스 코드 추가하면 N=0, 1, 많음(예: 10) 세 케이스 명시 테스트.
- **워크플로**: UI에 N 표시("1/3")가 있으면 실제 처리도 N개 확인. 거짓말 차라리 N=1 강제로 숨기는 게 낫다.
- **도구**: 디버그 콘솔로 활성 인스턴스 카운트 dump. profiler 또는 `FindObjectsOfType` count.
- **AI 룰**: list/array/dictionary 작업 시 추가·제거·iteration 동시 발생할 가능성 있는지 점검. 폐기 시 컬렉션도 비움.

## 적용 신호
- 스폰/디스폰 시스템
- 인벤토리, 슬롯 UI
- 동시 진행 상태 (다중 퀘스트, 다중 배달, 멀티 적 AI)
- "한 번에 하나만 처리" 가정으로 짠 코드를 N으로 확장할 때
- pool/recycle 패턴
