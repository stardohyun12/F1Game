# 07. System Boundary Handoff

## 증상
전투·인벤·세이브·UI·오디오 각 시스템은 단위 테스트 통과. 그런데 시스템 사이를 넘는 데이터(드롭 아이템 → 인벤, 세이브 → 로드, 레벨 전환 → 영속 상태)가 누락·중복·타입 mismatch·생명주기 어긋남. 게임 안에서 "무언가 빠진 것 같다" 느낌만 남음.

## 왜 발생 (AI 한계)
- AI는 한 시스템 코드에 집중하면 그 시스템의 input/output 인터페이스 명세를 추측으로 가정.
- "이 메서드 호출하면 인벤에 들어가요" 했지만 실제 인벤 시스템은 다른 시그니처 기대.
- 핸드오프는 양쪽 시스템 모두 읽고 통합해야 하는데 AI는 한 시스템씩 처리 경향.
- DontDestroyOnLoad, event subscribe/unsubscribe, save 직렬화 새 필드 — 한 곳만 고치고 다른 쪽 깜빡.

## 회피책
- **즉시**: 시스템 간 데이터 흐름 변경 시 양쪽 코드 read + 인터페이스 명세 확인. 한 쪽만 보고 짜지 말 것.
- **워크플로**: 시스템 경계는 명시적 contract(interface/struct/event) 정의. 둘 다 그 contract 참조.
- **도구**: 핸드오프 단계마다 log 한 줄 (`Debug.Log("[Handoff] X → Y, payload=...")`). 흐름 추적.
- **AI 룰**: "A를 변경했으니 B에서도 받는 쪽 확인" 자체 체크리스트. save 필드 추가 시 → 로드 측, 마이그레이션, 기본값 셋 다 확인.

## 적용 신호
- 세이브/로드 — 새 필드 추가 직후
- 씬 전환 — 영속 상태가 빠지는지
- 이벤트 구독 — `OnDestroy`에서 unsubscribe 누락
- 상태 머신 전이 — entry/exit 양쪽 처리
- 인벤·전투·UI·오디오 등 시스템 다수가 같은 데이터에 닿을 때
