## 패턴 카탈로그 (이 프로젝트에서 본 것)

### 적용됨

- **Service Locator** — `Services.Cargo` 같은 정적 레지스트리. Find 회피의 게임 친화 방식. [[code/Core/Core]]
- **Composition Root** — `GameContext.Awake`에서 모든 와이어링. [[code/Core/Core]]
- **DIP (Dependency Inversion)** — 12 인터페이스. 단 일부 누수 (다음 Phase 7에서 해소).
- **Template Method** — `BarHUDBase` abstract hook + Update 흐름 고정. [[code/UI/BarHUDBase]]
- **Modifier Chain (Strategy + Registry)** — `ICargoModifier` 리스트를 순서대로 적용. [[code/Cargo/Modifiers/ICargoModifier]]
- **Pub/Sub Mediator (Event Bus)** — `AudioCueBus` 정적 핸들러 맵. [[code/Audio/AudioCueBus]]
- **Data Lookup (정적 매핑)** — `CargoTypePresets` / `TireTypePresets` Get(enum). [[code/Cargo/CargoTypePresets]], [[code/Tires/TireTypePresets]]

### 적용 안 됨 (대기/검토)

- **MVP / Model-View-Presenter** — ResultPanel God class 분할 (Phase 8).
- **DTO** — `IRunSummary` (Phase 7).
- **ScriptableObject 데이터 분리** — `CargoCatalog` SO (post-MVP).

## 학습 흐름 권장

1. 새 패턴 이름이 나오면 → 이 MOC에서 검색.
2. 적용된 코드 노트 → 옵시디언 백링크로 호출자 즉시 확인.
3. Phase 노트 → *왜* 도입했고 *함정*은 뭔지 학습.
4. 다른 시스템에서 같은 패턴 보일 때 → 이 카탈로그가 인덱스 역할.
