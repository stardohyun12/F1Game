# PitCrew — 로컬 AI 팀 워크스페이스

Claude Code, Codex, OpenAI 호환 대화 제공자를 역할별로 연결하는 로컬 앱입니다.
**http://localhost:7878/** 에서 사용합니다. 이전 팀 화면·관제탑은 **/legacy** 에 남아 있습니다.

## 실행

`PitCrew.cmd`를 더블클릭하거나 프로젝트 루트에서 실행합니다.

```powershell
powershell -NoProfile -File tools/studio-dashboard/start.ps1
# 웹 UI 재시작 (독립 실행 서비스의 작업은 유지)
powershell -NoProfile -File tools/studio-dashboard/start.ps1 -Restart
```

첫 실행은 Python 가상환경과 고정 버전 의존성을 설치합니다. Python 3.11+와 설치·로그인된
Claude Code / Codex CLI가 필요합니다. 서버는 창을 숨겨 실행하며 브라우저를 닫아도 작업을 계속합니다.
다른 프로그램이 포트를 점유하면 종료하지 않고 오류를 표시합니다.

Windows 로그인 후 자동으로 서버를 켜려면 다음을 한 번 실행합니다. 현재 PC에는 등록되어 있습니다.

```powershell
powershell -NoProfile -File tools/studio-dashboard/install-autostart.ps1
# 자동 실행 해제: 위 명령에 -Remove 추가
```

로그인 후 같은 주소로 접속하면 됩니다. 저장소를 옮기면 다시 등록하세요.

개발용 별도 포트:

```powershell
$env:PITCREW_PORT='7879'
tools/studio-dashboard/.venv/Scripts/python.exe -X utf8 tools/studio-dashboard/server.py
```

## 사용하는 흐름

1. 왼쪽에서 기획·개발·검토 역할을 선택합니다. `+`로 역할을 더 만들 수 있습니다.
2. **설정**에서 제공자, 모델, 추론 강도, 역할 지시와 자료를 저장합니다.
   Codex는 실제 `model/list`의 모델·설명·지원 추론 강도·서비스 티어를 표시합니다.
   Claude는 SDK 초기화 응답의 모델·실제 모델 ID·effort·adaptive thinking 옵션을 표시합니다.
   목록 외 모델 ID는 고급 입력으로 지정할 수 있습니다. 목록은 접근 권한/잔여 한도를 보장하지 않습니다.
3. 메시지를 보내면 스트리밍 응답과 도구 활동이 표시됩니다. 실행 결과의 보고 모델은 오른쪽에서 확인합니다.
4. **전체 공통 컨텍스트**는 현재 프로젝트 모든 역할의 다음 입력에, 개별 자료는 해당 역할의 다음 입력에 포함됩니다.
5. 메시지의 **전달**은 다른 역할의 입력창에 원문을 첨부합니다. 확인 후 보내기를 누릅니다.
6. **연결한 대화**는 선택한 동료의 최근 대화를 다음 입력마다 첨부합니다. **비교**로 두 대화를 나란히 봅니다.
7. **대화 가져오기**에서 기존 Claude/Codex 대화와 Claude 서브에이전트 기록을 열람합니다.
   설정에서 표시 이름을 바꿀 수 있습니다. 외부 대화의 맥락을 새 역할로 전달해 계속 작업할 수 있습니다.
8. **보관**은 삭제가 아닙니다. 왼쪽 **보관된 대화**에서 복원합니다.

## 입력창: `/` 명령·스킬, `@` 참조, 이미지

- **`/`** 를 입력하면 이 에이전트가 실제로 실행할 수 있는 명령·스킬이 뜹니다.
  - Claude: 사용자·프로젝트 스킬과 명령(`~/.claude/skills`, `.claude/skills`, `commands`), 첫 실행 뒤에는 Claude Code 가 보고한 전체 목록(내장 `/context`, `/compact` 등 포함). `/이름` 으로 보내면 Claude Code 가 그대로 실행합니다.
  - Codex: `skills/list` 로 받은 스킬이 `$이름` 으로 들어가고, 보낼 때 Codex 의 스킬 입력으로 전달됩니다.
  - PitCrew 동작: `/research`(저비용 리서치), `/handoff`, `/attach`, `/model`, `/find`, `/compare`, `/flow`, `/add-cli`, `/clear-queue`.
  - Claude 는 사용자·프로젝트 설정을 읽어 스킬을 쓰지만 **기존 훅은 꺼서**(`disableAllHooks`) Claude Code 자동화가 두 번 돌지 않습니다.
- **`@`** 로 팀원(그 대화의 최근 내용을 이번 메시지에 참조)이나 프로젝트 파일(경로 참조, 이미지는 이미지로)을 붙입니다.
- **이미지**: 붙여넣기(입력창, 또는 다른 입력칸이 아닌 대화 화면 어디서나 Ctrl+V)·끌어놓기(대화 어디에나)·📎. 보낸 메시지 안에 썸네일로 보이고, 클릭하면 크게 봅니다.
  Claude 는 이미지 블록, Codex 는 `localImage` 입력, ACP 에이전트는 image 블록으로 실제 이미지를 받습니다.
  답변 속 `![](D:/.../x.png)` 같은 로컬 이미지도 대화 안에 표시합니다(프로젝트·PitCrew 폴더 안 파일만).
- 입력창의 **＋** 에 첨부·참조·명령·끝나면 넘기기·리서치가 모여 있습니다. `/` 메뉴 맨 위에는 최근 성공적으로 쓴 명령 3개가 보입니다(브라우저에만 저장).
- 입력창 오른쪽에서 **모델**과 **권한 모드**(읽기/작업/전체 권한)를 바로 바꿉니다. 작업 중에는 잠깁니다.
  읽기 모드는 멈춰서 묻지 않습니다: Claude 는 읽기 도구(+ 이 대화에서 미리 허용한 도구)만, Codex 는 읽기 전용 샌드박스에서 승인 없이 실행합니다.
- 답변에 마우스를 올리면 그 턴의 **모델 · 비용 · 입력(캐시)→출력 토큰**(제공자 보고값)이 보입니다.
- `Ctrl+O` 도구 활동 요약/자세히, 파일 편집은 `+N −N` diff 로 보입니다. 내 메시지의 **다시 사용**은 입력창에 넣기만 합니다.

## 누가 누구에게 넘겼는지

- 받은 쪽 메시지에는 출처(← 누구의 인계·리서치·메시지)가, **보낸 쪽 대화에는 그 시점에 ↗ 한 줄**(결과를 넘김·리서치를 맡김·메시지를 전달·참조로 쓰임)이 표시됩니다. 누르면 받은 메시지로 이동합니다.
- 전체 관계는 `/flow`(팀 흐름)에서 종류별로 봅니다. 기록에서 계산하므로 실제로 일어난 관계만 나옵니다.
- 에이전트가 API 로 다른 대화에 보낼 때는 `origin:{agent, name, kind:'message'}` 를 함께 보내면 같은 방식으로 기록됩니다.

## 팀장과 팀원

- 팀 설정에서 **팀장**을 고르면(팀원 중 한 명), 사이드바에 `팀장` 배지가 붙습니다.
- **알림은 팀장에게서만**: 팀원의 완료·중단은 팝업·Windows 알림 없이 받은함에만 남습니다. 팀원이 **승인/질문을 기다리거나 실패하면** `팀명 · 팀원` 으로 알립니다.
  팀장이 맡긴 일이 아직 팀원에게 남아 있으면 팀장의 중간 완료도 알리지 않고, 보고가 다 모여 팀장이 끝냈을 때 한 번 알립니다.
- **Claude 팀장은 직접 맡깁니다**: `팀원에게 맡기기`(delegate) 도구로 팀원에게 일을 보내고(권한 확인 없음, 한 턴 최대 8건),
  팀원이 끝나면 그 보고가 팀장 대화로 자동으로 돌아옵니다. 팀장 턴 중이면 대기열에 들어갔다가 이어서 처리됩니다.
  Codex·ACP 팀장은 아직 맡기기 도구가 없어 알림 규칙만 적용됩니다.
- 여러 팀의 팀장이면 그 팀들의 팀원 모두에게 맡길 수 있습니다. 맡긴 일이 **실패·중단되면 그 사실이 팀장에게 보고**되어 팀장 답에 반영됩니다(리서치 요청도 같음).
- 폭주 방지: 사용자 요청 하나에서 시작한 흐름은 순환 위임(맡긴 쪽에게 다시 맡기기) 불가, 최대 4단계, 맡기기 20건까지입니다(실행 서비스 재시작 시 집계 초기화).
- 팀장·팀원은 이번 턴 컨텍스트의 `team` 항목으로 자기 역할과 팀원 목록(또는 팀장 이름)을 받습니다.

## 팀 목표 (리서치 → 개발 → QA)

- `/goal` 또는 입력창의 **팀 목표**에서 목표와 완료 기준(한 줄에 하나), 리서치·개발·QA 팀을 정합니다. `/goal 목표 내용`은 내용을 채워 설정 창을 엽니다. `/cycle`도 새 팀 목표를 엽니다.
- 기본은 **목표 완료까지**입니다. 최대 1~3회로 제한할 수도 있으며, 한도에서 기준 미달이면 완료 대신 일시 정지합니다. 실행 실패·재시작으로 끊긴 단계는 재개 전까지 멈춥니다.
- 각 단계는 그 팀의 **팀장**에게 갑니다(팀장이 팀원에게 나눠 맡기면, 팀원 보고가 다 모인 뒤에 단계가 끝납니다). 앞 단계의 보고가 다음 단계의 입력이 됩니다.
- 개발과 QA는 서로 다른 팀장이 맡습니다. QA는 각 기준에 `기준 N: 충족 — 근거` 또는 `기준 N: 미충족 — 이유`, 마지막 줄에 `판정: 통과` / `판정: 수정 필요`를 씁니다. 기준별 근거가 빠지거나 미충족이면 완수하지 않고 수정으로 돌아갑니다.
- 탭 아래 **진행 막대**에 단계별 상태·경과가 실시간으로 보이고, 단계를 누르면 그 대화가 열립니다. **자세히**는 단계별 결과, **중단**은 다음 단계로 넘기지 않게 합니다.
- 목표 칩은 선택한 대화가 속한 팀의 목표를 표시합니다. 상세 화면에 기준별 QA 판정과 근거가 남으며, 과거 기준 없는 실행은 검토 확인이 필요한 것으로 표시합니다.
- `/codex-goal`은 별도의 Codex 자체 목표 조회·설정입니다. 팀 단계나 위임으로 기존 Codex 세션을 재개할 때 자체 목표가 active이면 먼저 일시 정지해 두 실행이 겹치지 않도록 합니다.
- 알림은 사이클이 끝나거나 멈출 때 **한 번**만 옵니다(단계 사이의 인계는 조용합니다). 팀 간 인계는 협업 보기에 주황 화살표로 보입니다.

## 협업 보기와 알림

- 대화 머리의 **협업**(또는 `/flow`)을 누르면 팀별 지도가 열립니다. 팀마다 한 열(팀장 위, 팀원 아래, 팀 밖), 카드에 상태와 맡은 일.
  화살표는 누가 누구에게 넘겼는지 — 파랑=맡김, 초록=결과 보고, 보라=리서치. 굵을수록 자주, 점선이 흐르면 지금 진행 중. 오른쪽은 최근 주고받은 것(누르면 그 메시지).
- 위쪽 탭은 **팀별로 묶여** 보이고, 팀 이름을 누르면 그 팀으로 사이드바가 바뀌고 팀장 대화가 열립니다.
- **알림은 사슬이 끝날 때 한 번**: 응답이 필요할 때(승인·질문)는 항상, 완료는 이 대화가 요청한 답이 더 오지 않고 대기열도 비었을 때만.
  결과가 다른 에이전트에게 넘어간 턴(맡긴 일·리뷰)은 알리지 않고, 받은 쪽이 끝낼 때 알립니다.

## 저비용 리서치 (`/research`)

주제를 적으면 사용량이 낮은 모델(Claude Haiku · low 웹 리서치, Codex Luna · low 로컬 조사)이 사실과 출처만 모아
**요청한 대화로 그 요청의 결과만** 돌려보냅니다. 웹 담당은 읽기 모드에 웹 검색·웹 읽기만 허용되어 승인 대기로 멈추지 않습니다.
받은 결과의 핵심 주장은 출처를 확인한 뒤 쓰세요.

## 다른 에이전트 CLI (ACP)

[ACP(Agent Client Protocol)](https://agentclientprotocol.com)를 말하는 CLI 를 붙일 수 있습니다. Gemini CLI 가 설치돼 있으면 자동으로 나타납니다(`gemini --acp`).
다른 CLI 는 에이전트 설정의 **＋ 다른 에이전트 CLI 연결** 또는 `/add-cli` 에서 명령을 입력해 연결 확인(초기화만, 모델 호출 없음) 후 등록합니다.
권한 모드는 Gemini 기준 읽기 → `--approval-mode plan`, 작업 → 승인 요청, 전체 → `--yolo` 로 대응합니다.
Gemini 는 로그인이나 `GEMINI_API_KEY` 가 필요합니다. 없으면 대화에 방법이 안내됩니다.

## 대기열·인계·첨부·확인 필요

- **대기열**: 작업 중에도 입력할 수 있습니다. 보내기 버튼이 `대기열에 추가`로 바뀌고, 지금 작업이 끝나면 순서대로 자동 전송합니다(최대 10개).
  입력창 위에서 항목을 **편집**(입력창으로 꺼내기)·삭제할 수 있습니다. 실패·중단으로 끝나면 자동 전송을 멈추고 `이어서 보내기`를 표시합니다.
- **끝나면 넘기기**: 이 대화가 대기열까지 모두 **완료**되면 마지막 보고(최대 12,000자)를 붙여 다른 팀원에게 자동으로 보냅니다.
  받는 쪽이 작업 중이면 그쪽 대기열에 들어갑니다. 실패·중단이면 보내지 않고 보류합니다. 규칙은 한 번 실행되면 사라집니다.
- **승인**: 카드에 동작·대상·이유가 먼저 나오고, 원문은 접혀 있습니다. `이 대화에서 ○○ 계속 허용`을 체크하면 같은 도구는 다시 묻지 않습니다.
  거절은 기억하지 않습니다. 입력창 위 `계속 허용` 칩의 ×로 취소합니다.
- **첨부**: 📎 버튼, 이미지 붙여넣기(Ctrl+V), 끌어놓기. 파일은 `.runtime/uploads`에 저장되고(20MB·10개), 메시지에 경로 목록이 붙어 에이전트가 파일 도구로 엽니다.
- **확인 필요**: 다른 대화를 보는 동안 끝나거나 실패하거나 응답을 기다리는 대화는 상단 `확인 필요 N`과 카드·탭의 점으로 남습니다. 그 대화를 열면 사라집니다.
- **Windows 알림**: 브라우저가 닫혀 있거나, 탭이 가려져 있는데 브라우저 알림이 꺼져 있으면 트레이 알림으로 알려줍니다. 누르면 해당 대화가 열립니다.
- **찾기**: `Ctrl+K` 이름·역할로 대화 찾기, `Ctrl+Shift+F` 현재 대화 본문 찾기(접힌 도구 결과 포함, ↑↓ 이동), `Alt+I` 입력창.

## 도구 활동과 알림

- 연속된 도구 실행은 한 줄로 접힙니다(예: `✓ 도구 4개 · Bash · Read · Grep · 실패 1`). 실행 중에는 현재 도구와 설명이 보입니다.
  펼치면 호출마다 이름·설명·입력·결과가 한 행으로 묶여 있습니다. 긴 결과는 **전체 결과 보기**로 불러옵니다.
- 도구가 만든 이미지(스크린샷 등)는 `.runtime/media/`에 파일로 저장되고 대화에 썸네일로 표시됩니다.
- 상단 **알림 켜기**를 누르면, 탭이 가려져 있을 때 작업 완료·실패·중단·승인/질문 대기를 브라우저 알림으로 받습니다.
  알림을 누르면 해당 대화로 이동합니다. 탭 제목의 `(N)`은 알림 설정과 관계없이 표시됩니다.
- 화면은 바뀐 부분만 다시 그립니다. 작업 중에도 텍스트 선택·펼친 항목·스크롤이 유지됩니다.

## 실행·권한·기록

- 기본은 읽기/분석 모드입니다. 실제 수정은 설정에서 작업 모드로 바꿉니다.
- Codex는 `untrusted` 승인 정책과 read-only/workspace-write 샌드박스를 사용합니다.
  Claude는 SDK `can_use_tool` 콜백으로 요청을 전달하고 읽기 모드에서는 쓰기/셸 도구를 비활성화합니다.
- 필요한 승인·질문은 대화 아래 표시됩니다. 파일 변경 승인에는 도구가 보고한 변경 제안을 첨부합니다.
  승인은 해당 요청 1회에만 적용됩니다. 중단하면 턴을 interrupt하고 대기 승인을 거절합니다.
  이미 수행한 파일 변경을 되돌리지는 않습니다.
- Claude는 `setting_sources=[]`로 기존 자동화 훅을 중복 실행하지 않습니다. 루트 AGENTS.md/CLAUDE.md는
  작업 컨텍스트에 명시적으로 포함합니다. 별도 플러그인/MCP 설정은 자동 복제하지 않습니다.
  Codex는 설치된 app-server의 기본 구성을 사용합니다.
- 모델·역할·공유 문서 변경은 다음 턴부터 적용됩니다. 진행 중인 턴의 설정은 바꿀 수 없습니다.
- 각 입력에는 당시의 **컨텍스트 스냅샷과 실행 설정**을 저장합니다. 내부 사고나 현재 모델의 전체 컨텍스트를 표시하는 기능은 아닙니다.
- 외부 기록은 `외부 대화` 상태로 표시합니다. 최근 로그라는 이유로 실행 중/완료라고 추측하지 않습니다.

## 다른 AI 연결

`providers.example.json`을 `providers.local.json`으로 복사해 수정합니다. 새로고침 후 제공자에 나타납니다.
Ollama 예제가 들어 있으며, 다른 OpenAI 호환 서버도 등록할 수 있습니다.

```json
{
  "providers": [{
    "id": "my-provider",
    "name": "내 대화 모델",
    "baseUrl": "https://YOUR-PROVIDER/v1",
    "apiKeyEnv": "MY_PROVIDER_API_KEY",
    "defaultModel": "YOUR-MODEL-ID",
    "models": ["YOUR-MODEL-ID"]
  }]
}
```

키 값은 JSON에 넣지 않습니다. 지정한 환경변수를 서버 실행 환경에 설정하세요. 브라우저에 키를 전달하지 않습니다.
`models`가 비어 있으면 `/models`를 조회합니다. `/chat/completions` SSE 스트리밍이 필요합니다.
이 어댑터는 대화 전용이며 로컬 파일 도구를 제공하지 않습니다. 제공자별 인증/요금/모델 라이선스는 별개입니다.

## 데이터와 한계

- 대화·실행 상태·역할·자료: `.runtime/hub.sqlite3` (SQLite WAL). 로그: `.runtime/server.*.log`.
- 입력 중 초안/선택/참조: 브라우저 localStorage.
- `.runtime/`, `.venv/`, `providers.local.json`은 Git에서 제외합니다. 백업은 서버를 종료한 뒤 `.runtime` 전체를 복사합니다.
- Hub 대화는 최근 300개 항목을 표시하고 JSON 내보내기는 전체 저장 기록을 포함합니다.
- 외부 기록은 최근 1 MB에서 최대 160개 항목, 세션 목록은 Claude 25개·Codex 25개,
  Claude 부모별 팀원은 최근 16개입니다. 연결한 오래된 세션은 별도로 다시 찾습니다.
- 외부 앱 대화를 강제로 resume하거나 기존 프로세스에 입력을 주입하지 않습니다.
- 연결한 동료 컨텍스트는 각 최근 12,000자, 최대 8개입니다. 자동 대화 무한 루프는 없습니다.
- 파일 작업은 같은 프로젝트에서 수행됩니다. 동시 파일 변경 충돌을 자동 병합하지 않습니다.
- 서버 비정상 종료 시 진행 상태를 interrupted로 복원합니다. 기록은 남지만 작업을 자동 재실행하지 않습니다.
- localhost 단일 사용자 도구입니다. Host/Origin/Sec-Fetch-Site와 변경 요청 토큰을 검사하며,
  기존 생성 HTML에는 sandbox CSP를 적용합니다. 인터넷 공개 서버용은 아닙니다.

### 연결이 지연될 때
화면은 자동으로 다시 동기화하며, 입력이 없다는 이유로 AI 작업을 중단하지 않습니다. 조회가 12초 이상 멈추면 요청을 해제하고 최대 30초 간격으로 계속 재시도합니다. ‘지금 다시 연결’로 즉시 재시도할 수도 있습니다. 전송 응답이 유실된 명령은 자동 재전송하지 않으므로 대화 상태를 확인한 뒤 다시 보내세요.

GitHub 원본 비교, 채택한 원칙, 적용 범위와 검증 방법은 [RESILIENCE.md](RESILIENCE.md)에 정리했습니다. 서버 프로세스 자체가 종료되었다면 `PitCrew.cmd`로 다시 실행해야 합니다.

### 독립 실행 서비스 관리
현재 구조는 `브라우저 → 화면 서버(server.py) → 실행 서비스(runtime.py) → Claude/Codex`입니다. 화면 서버 재시작은 작업과 승인 대기를 유지합니다.

- 실행/연결 복구: `PitCrew.cmd`
- 화면만 재시작: `powershell -NoProfile -File tools/studio-dashboard/start.ps1 -Restart`
- 실행 서비스 재시작: `tools/studio-dashboard/.venv/Scripts/python.exe tools/studio-dashboard/runtime.py --restart`
- 실행 서비스 종료: 위 명령의 `--restart` 대신 `--stop`. 작업 또는 승인 대기 중이면 종료를 거절합니다.
- 화면의 **팀 상태 · 전체 보기**에서 역할·하위 에이전트·대기 요청을 확인합니다. 외부 팀원은 기록 열람입니다.
- 테스트 격리는 `PITCREW_RUNTIME_DIR`와 `PITCREW_PROVIDERS_FILE` 환경변수로 별도 데이터/제공자 설정을 지정합니다. 기본 실행은 기존 `.runtime/hub.sqlite3`와 `providers.local.json`을 그대로 사용합니다.


## 팀 구성과 기존 대화 가져오기

왼쪽 **팀 만들기 · 관리**에서 팀 이름, 공통 목표, 기존 팀원을 선택합니다. 팀 선택으로 대화를 필터링하며, 선택한 팀에서 추가하는 새 에이전트는 그 팀에 포함됩니다. 같은 에이전트를 여러 팀에 넣으면 모든 소속 팀의 공통 목표가 다음 입력에 포함됩니다. 팀 구성만으로 다른 대화 내용이 자동 공유되지는 않습니다.

**대화 가져오기**에서 이 프로젝트의 로컬 Codex/Claude 기록을 검색하고 최대 30개를 선택해 한 번에 팀에 연결합니다. Claude 하위 에이전트는 별도 체크로 표시합니다. 이미 연결된 기록은 재사용하고 보관된 기록은 복원합니다. 가져온 직후에는 읽기 전용입니다. 대화 아래의 **원래 세션 이어서 사용 → 이 세션에서 계속하기**로 같은 세션 ID의 입력을 활성화할 수 있습니다.

팀 관리의 **대화 공유 연결**에서 받는 에이전트와 참고할 대화를 고릅니다. 다음 입력에 최근 기록을 첨부하며 자동으로 실행하거나 메시지를 전송하지 않습니다. 최대 8개 대화 연결, 팀당 50명입니다.


## 원래 CLI 세션 재개

Codex는 공식 `thread/resume` 뒤 `turn/start`, Claude Agent SDK는 `resume=<session_id>, fork_session=False`를 사용합니다. 요약을 새 채팅에 붙여 넣는 방식이 아닙니다. 프로젝트와 원본 UUID를 확인하고, ID가 달라지면 중단하며 새 세션 생성으로 자동 우회하지 않습니다. 원본에 새 턴이 기록됩니다. 모델은 기록에서 확인 가능한 마지막 모델을 사용하며 UI 설정에서 변경할 수 있습니다.

가져온 카드의 ID, 팀 소속과 연결은 유지됩니다. 화면은 연결 시점의 최근 1 MB 원본 기록(최대 160 메시지)과 이후 PitCrew 메시지를 표시합니다. 네이티브 CLI가 로드하는 세션 맥락은 이 화면 표시 범위와 별개입니다. 다른 앱에서 나중에 추가한 턴은 재개 시 CLI가 읽지만 기존 화면 스냅샷에는 자동 합쳐지지 않습니다.

같은 PitCrew 실행 서비스 안의 중복 세션 연결과 동시 실행은 거부합니다. 다른 앱 프로세스의 동시 실행까지 감지/잠금하지는 않으므로 원래 앱의 해당 작업을 마친 뒤 사용하세요. 실행 중인 하위 에이전트나 앱 전용 동적 도구를 인계하는 기능은 아닙니다. Claude 하위 에이전트 기록에는 직접 재개 버튼을 표시하지 않습니다. 파일 작업 권한은 읽기 모드로 시작하며 필요한 경우 설정에서 바꿉니다.

공식 근거: [Codex App Server](https://learn.chatgpt.com/docs/app-server), [Claude SDK sessions](https://code.claude.com/docs/en/agent-sdk/sessions). 별도 라이브 재현: `.venv/Scripts/python.exe live_resume_check.py codex` 또는 `claude` (모델 사용량 소모).


## 여러 프로젝트와 사용량

왼쪽 **프로젝트 관리 ＋**에서 기존 로컬 폴더의 절대 경로와 표시 이름을 입력하면 바로 전환됩니다. Git 저장소가 아닌 일반 폴더도 지원합니다. 프로젝트별 SQLite DB, 팀·대화·공유 컨텍스트, CLI 실행 cwd와 AGENTS.md/CLAUDE.md, 기존 세션 검색 범위를 분리합니다. 기본 F1Game 데이터는 이동하지 않고 보존합니다. 추가 프로젝트는 `.runtime/projects/<id>/hub.sqlite3`에 저장됩니다. 프로젝트를 전환하거나 웹 UI를 재시작해도 다른 프로젝트의 진행 중 작업을 유지합니다. 실행 서비스 종료는 모든 프로젝트가 유휴 상태일 때만 가능합니다.

상단 **Codex · Claude 사용량**에서 로그인한 계정 전체의 사용률과 초기화 시각을 봅니다. 계정 사용량은 다른 앱과 프로젝트에서 사용한 양도 포함하며 프로젝트별 비용 합계가 아닙니다. Codex는 설치된 app-server의 공식 `account/rateLimits/read`, Claude는 Orca에서도 사용하는 구독 OAuth usage endpoint를 읽습니다. Claude endpoint는 공개 SDK의 보장된 계약이 아니므로 사용 불가/조회 제한 상태를 명시합니다. 5분 캐시, 동시에 한 번 조회, Retry-After 준수, 이전 값의 시각 표시를 적용합니다. 조회에 모델 호출을 사용하지 않으며 인증 정보를 브라우저나 로그에 반환하지 않습니다. 로그인 갱신/변경은 원래 CLI에서 합니다.

화면은 밝은/어두운 테마를 지원하며 모바일에서는 ☰로 프로젝트와 대화 목록을 엽니다. 테마와 마지막 프로젝트, 대화 초안은 브라우저에 보존됩니다. 제품 원칙과 참고/검증 기록은 PRODUCT_PLAN.md를 참고하세요.
