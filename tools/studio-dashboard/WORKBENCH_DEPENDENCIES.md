Workbench dependencies (2026-10-18)

- pywinpty 3.1.0: MIT, https://github.com/andfoy/pywinpty . Windows ConPTY subprocess, installed in the existing dashboard virtualenv. The upstream Python spawn/write/read example was reproduced before adapting it to bounded buffers and project ownership. Pass an argv list: round-tripping through Windows quoting and shlex corrupts quoted Python/Claude arguments. Set TERM=xterm-256color for the Codex TUI.
- @xterm/xterm 6.0.0: MIT, https://github.com/xtermjs/xterm.js . Vendored only package/lib/xterm.js, package/css/xterm.css and LICENSE from npm pack --ignore-scripts. License: web/xterm-LICENSE.txt. Tarball npm SHA1: 93637b0f2ee3a70718b5746a27c9c506af16745b. No dependency install scripts executed. Terminal output is untrusted: no custom HTML or link handlers, no clipboard integration or arbitrary executable endpoint. OSC 10/11 color queries are consumed without replies to avoid late query responses appearing as input in the Windows Codex prompt.
- Pillow 13.0.0: HPND, https://python-pillow.github.io . Validates actual image format before provider delivery. Existing immutable artifact registry is reused.
- Unity 6000.3.19f1: existing licensed installation and project. No new Unity package or external asset dependency. Existing F1Game prefab, material shader and ArcadeCarController reused in Assets/PitCrewTrial. https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Camera-overrideSceneCullingMask.html informed render isolation; real inspection showed a dedicated GameObject layer was also needed here. That layer must be restored to layer 0 for physics in the standalone scene.

Runtime CLI supports Windows only, one native session per logical project, and is independent from structured provider sessions. Browser reconnect survives; service restart does not restore an OS process. Native CLI output stays in a 1,000,000-character in-memory ring, and ended sessions are bounded to six. Existing runtime maintenance refuses restart while any native CLI is alive. Native CLI still uses installed provider configuration, credentials and approval UI; this is not a separate sandbox or a capability improvement claim.
