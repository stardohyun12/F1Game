# 실제 Codex·Claude 협업 검증 — 2026-10-15

프로젝트 **실제 협업 검증 B0D2FEAF**, 팀 **기획 → 구현 → 검토**에 결과를 남겼습니다.
기존 사용자 작업 대화에 테스트 입력을 보내지 않고, 실제 CLI/SDK로 별도의 원본
대화를 만든 뒤 가져왔습니다. 가짜 응답이나 모의 제공자를 쓰지 않았습니다.

## 확인한 흐름

1. Claude 원본 대화에 `usageLabel(value)` 요구사항과 무작위 요구코드를 저장했습니다.
2. Codex 원본 대화에는 별도의 구현코드를 기억시켰습니다.
3. 실제 Edge 브라우저에서 팀 생성, 두 원본 기록 가져오기, 각각 **원래 세션 이어서 사용**,
   양방향 **대화 공유 연결**을 클릭했습니다. 팀 공통 자료에 제3의 팀코드를 넣었습니다.
4. Codex에 코드들을 다시 알려주지 않고, 연결된 Claude 요구사항으로 구현하도록 했습니다.
   결과에 원래 기억한 구현코드, 상대의 요구코드, 팀코드가 모두 나타났습니다.
5. 생성된 함수의 숫자/문자열/null/undefined/NaN/Infinity/경계값 등 10개 사례가 통과했습니다.
6. Claude가 연결된 Codex의 최신 구현과 구현코드를 읽고 원래 요구사항에 맞는지 검토해
   **검토 통과**로 답했습니다. 두 제공자 모두 가져오기 전후의 네이티브 세션 ID가 같았습니다.
7. 각 입력에 저장된 컨텍스트 스냅샷에 상대 대화와 팀 공통 자료가 포함됨을 확인했습니다.

검증 코드: `live_team_flow_check.py` (`prepare`는 실제 제공자 사용량을 소비합니다).
결과: `.runtime/team-flow-B0D2FEAF/verified.json`.

## 수정 및 범위

- 프로젝트 이름을 직접 지정해도 상단에는 폴더명 `project`만 나오던 문제를 수정했습니다.
  프로젝트 선택기와 상단 제목이 같은 표시 이름을 사용하며 경로는 툴팁으로 확인합니다.
- 설정 저장 창이 먼저 닫히면서, 직후 다른 대화를 선택하면 늦은 갱신이 선택을 되돌리는
  문제를 재현했습니다. 저장·갱신·선택 반영 후 창을 닫도록 바꿨습니다. 같은 브라우저
  시나리오를 다시 실행해 역할 이름 저장 직후 전환과 결과 비교가 통과함을 확인했습니다.
  브라우저 오류는 없었으며 `.runtime/team-flow-verified.png`에 비교 화면을 저장했습니다.
- 테스트 스크립트는 공개 API에 없는 파일 경로 대신 원본 로그의 세션 메타데이터로
  가져올 대화를 찾도록 고쳤습니다. 이 실패는 제품의 가져오기 오류가 아니었습니다.
- Windows 시작프로그램 등록 누락은 `install-autostart.ps1`로 해결했습니다.
  실제 등록된 바로가기로 서버가 없는 상태에서 실행하고, 중복 실행해도 PID가 유지됨을
  확인했습니다. 실제 재부팅/로그아웃은 수행하지 않았습니다. 자세한 범위는 `AUTO_RECOVERY.md`.
- Python 회귀 테스트 30개와 Node 회귀 테스트 11개가 통과했습니다. 격리된 서비스 종료 후
  자동 복구, 세션 ID 보존, 중단된 요청을 중복 전송하지 않는 동작도 포함합니다.

이 검증은 대화·코드 작성·검토의 컨텍스트 공유를 확인합니다. 원래 앱 전용 도구나 실행 중인
하위 에이전트까지 인계한 것은 아닙니다. 공유는 선택한 대화의 최근 내용을 다음 입력에
첨부하는 방식이며, 모델 내부의 전체 컨텍스트나 모든 생각을 공유하는 기능은 아닙니다.

기존의 `thread/resume` 및 Claude 세션 재개 경로와 명시적 컨텍스트 첨부를 재사용했습니다.
로그인 실행은 Microsoft의 [공식 Startup 폴더 방식](https://support.microsoft.com/en-US/Windows/Experience/Startup-Boot/configure-startup-applications-in-windows)을
현재 가상환경과 watchdog에 적용했습니다. 외부 구현 코드나 추가 패키지는 도입하지 않았습니다.
