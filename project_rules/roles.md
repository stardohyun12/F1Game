# 역할 분리 운영 모델 (도현 결정 2026-05-25) [project]

> 배경: 룰을 메모리에 박아도 행동이 안 바뀜(증명됨). "멀티에이전트 쓰자" 합의도 그 순간
> "내가 빨리 하면 돼"가 이겨서 안 지켜짐. 강제 장치 없는 합의·룰은 작동 안 한다.
> 해법: 관심사를 **구조(분리된 역할)**로 강제. 작성자≠판정자를 구조로 만든다.
>
> 도현 진단 3종(이게 이 모델이 막아야 하는 것):
> ① 목표만 보고 주변을 헤집음 (시킨 지점만 파고 그 변경이 다른 걸 깨는 걸 안 봄)
> ② 게임 기본 흐름을 무시하고 명령 수행 (포장 단계가 통째로 빠진 걸 못 봄)
> ③ 혼자 과대평가 "됐다" (정적 스샷 보고 OK, 도현이 플레이하면 깨져 있음)

## 핵심 강제 규칙

**코딩(나)은 기획 에이전트 + 그래픽 에이전트가 통과시키기 전엔 "됐다"도, 커밋도 못 한다.**

이게 유일한 강제 장치다. 나머지는 다 이걸 돕는 도구.

## 세 역할

| 역할 | 누가 | 담당 | 막는 것 |
|---|---|---|---|
| **코딩** | 나(메인) | 구현만. 판정 금지. | — |
| **기획 에이전트** | 컨텍스트 0 서브에이전트 | 게임 흐름·주변 무결성. "이 변경이 흐름을 깨나? 다른 걸 헤집었나? 빠진 단계는?" | ①② |
| **그래픽 에이전트** | 컨텍스트 0 서브에이전트 | 시각 판정. 스샷만 보고 어색/깨짐. 외부 눈. | ③ |

- **기획·그래픽은 컨텍스트 0**(내가 뭘 의도했는지 모름) — 작성자 편향 차단.
- Unity 에디터는 1개라 **Play 검증은 직렬**(병렬 Play 금지). 정적 분석 에이전트는 Play 금지 명시.

## 자동검사(회귀 하네스)는 유지 — 각 역할의 도구

작동이 증명된 부분(`scripts/regression-check.sh` + `HarnessChecks`). 버리지 않는다.
오늘 추가로 잡힌 것: OrderBoard 배선 / 주문 목적지 / (예정)풀 루프 완결성.
이건 기획 에이전트가 "흐름 무결성"을 판정할 때 쓰는 객관 도구다.

## 폐기: "내가 지켜야 할 룰"

자기검증 3종·멀티에이전트 트리거(D-074) 등 **메모리에만 있고 행동 안 바뀐 룰**은 이 모델로 대체.
지킬지 말지가 내 의지에 달린 룰은 작동 안 한다 — 게이트(통과 전 커밋 불가)로 바꾼다.

## 작업 루프 (모든 변경에 적용)

1. **코딩**: 구현.
2. **자동검사**: 회귀 하네스 통과.
3. **기획 게이트**: 서브에이전트가 흐름·주변 무결성 판정 → FAIL이면 수정 후 재판정.
4. **그래픽 게이트**(화면 변경 시): 서브에이전트가 스샷 판정 → FAIL이면 수정 후 재판정.
5. 둘 다 통과해야 "됐다" 보고 + 커밋.

큰 작업은 위 게이트 에이전트들을 작게 쪼개 병렬/직렬 디스패치.

## AionUi 팀 모드 매핑 (2026-10-18 도현 결정)

위 세 역할을 Claude 서브에이전트가 아니라 **AionUi 팀의 분리된 팀원**(별도 프로세스·컨텍스트 0·판정자는 다른 모델)으로 수행한다. 운영 규약은 `PIPELINE.md`.

| roles.md 역할 | AionUi 팀원 | 백엔드 |
|---|---|---|
| 코딩 | 게임 프로그래밍팀 | Claude |
| 기획 에이전트 | 게임 기획팀 | Claude |
| 그래픽 에이전트 (+ 모델러) | 게임 아트팀 | Codex |
| 회귀 하네스 실행·Play 검증 | 게임 QA팀 | Codex |
| 배분·기록·보고 | 게임 총괄 PD (팀장) | Claude |

핵심 강제 규칙은 그대로다. 프로그래밍팀은 기획·아트·QA 게이트 PASS 메시지가 태스크에 붙기 전엔 "됐다"도 커밋도 못 한다. 판정자가 다른 모델(Codex)이라 작성자 편향 차단이 한 단계 더 강해진다. 에디터는 1개이므로 `PIPELINE.md` §4 에디터 토큰을 따른다.
