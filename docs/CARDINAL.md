# 카디널 작업 방식 (2026-11-03, D-281) — 한 장

도현: "약간 소드아트 온라인처럼 … 그런식으로 워크플로우 구성해서 만들어보자".
이 장이 유일한 기준. 옛 방식(PIPELINE·FLOW·WORKFLOW-v2·카드)은 `archive/harness-v1/`에 보관.

## 0. 한 문장
세계는 **명세(글)**에만 존재한다. 씬·대사·소품은 명세에서 **생성**되고, **검사**가 거르고, **도현이 한 판** 해서 판정하고, 그 판정이 명세로 돌아간다. 누구도 씬을 직접 찔러 고치지 않는다.

## 1. 구성 (카디널 = 코어 + 생성기 + 검사 + 작가 + 관찰)
- **코어 `world/SPEC.md`** — 장소·주민·물건·흐름(방→정비소→보관소→포장→카트→문 앞→귀가)·규칙(돈·파손·일정)·톤·금지·이름. 사람이 읽는 글. 도현이 고친다.
- **생성기 `tools/world/`** — 명세 → 씬 배치·소품·주문·대사 데이터. 좌표는 생성기가 정한다(모델이 숫자를 직접 쓰지 않음).
- **검사** — 불변 조건(`WorldInvariants`, 씬) + 규칙 테스트(순수 C#, Play 없이) + 훅(봇·대기·잠근 파일). 버그 1개 고치면 조건 1개 추가.
- **작가** — 언어 모델(구현 일꾼 1명). 과제 = 명세의 한 부분을 세계에 반영하기. 시작 글은 브리프(명세 발췌 + 세계 스냅숏 + 파일 지도)뿐.
- **관찰** — 도현 한 판 메모(막힌 곳·본 곳·판정) → `world/SPEC.md` 「판정 기록」절로. 다음 과제 문맥에 들어간다.
- **카야바 = 도현** — 컨셉·취향·"이건 이 세계가 아니다".

## 2. 사람 3
- 도현: 매일 한 판 → 메모 3줄 → 명세 고침.
- PD(Hermes 대화): 메모 → 과제 1개 → 결과 그림 3장 보고. 하루 1번 봇 한 바퀴. 묻는 건 2지선다 1개.
- 구현 1(Claude Code, 기능 단위 세션 이어감): 한 번에 1개, 끝까지. 아트·리서치는 과제 안에 한 줄로.

## 3. 상태 = `docs/NOW.md` 하나
지금 만드는 것 1 · 다음 3 · 도현 판정 대기 · 마지막 한 판 메모. PD 가 매 턴 갱신. 화면·보드·텔레그램 묶음 없음.

## 4. 과제가 끝나는 조건
컴파일 0 에러 · 불변 검사 통과 · 규칙 테스트 통과 · 구현이 찍은 그림 3장(1×) · 보고 4줄(한 것/확인/증거/남은 것). 그 다음은 바로 도현 플레이. 블라인드 검증·클립·왕복 없음.

## 5. 남긴 도구 (이것만)
`scripts/team.sh`(구현 호출) · `scripts/run_task.sh`(과제 1개 실행: 스냅숏→브리프→구현→검사→커밋→NOW 갱신) · `scripts/brief.py` · `scripts/world_snapshot.sh` · `scripts/world_check.sh` · `scripts/ucli-http.sh` · `scripts/tg_notify.py` · `.claude/hooks/guard-pre.py`.

## 6. 하루
아침 도현 한 판 → 낮 구현(에디터는 구현 전용, PD 는 읽기만) → 저녁 PD 보고 그림 3장 + 다음 1줄. 한 줄 흐름이 끝까지 이어질 때까지 병렬 없음.

## 7. 첫 과제
