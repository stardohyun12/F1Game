# 우리 게임 코드가 어떻게 생겼나 — 도현용 (2026-11-03)

> 읽는 법: 위에서 아래로 10분. 용어는 처음 나올 때 쉬운 말로 먼저 쓴다. 코드 줄은 전부 실제 파일에서 그대로 가져왔다(경로·줄 번호 있음). 끝에 「맞혀 보기」 3개가 있는데 맞춰도 틀려도 괜찮다.

---

## 1. 한마디로

게임 코드는 **7개 층으로 쌓은 케이크**다. 아래층은 위층을 **모른다**. 위층만 아래층을 쓴다.
그래서 포장을 고칠 때 포장 파일만 열면 되고, 다른 층이 깨질 수 없다. 거꾸로 쓰면 컴파일러가 빨간 줄로 막는다 — 글로 적힌 규칙이 아니라 **기계가 막는 규칙**이다.

```
 7  Debug          디버그 창 · 봇 · 검사            ← 뭐든 봐도 된다(맨 위)
 6  Presentation   도트 화면 · 노을 · 소리 · 손      ← "그리기"만
 5  Stages         하루 흐름(아침→정비소→…→일기)     ← 단계 8개, 서로 모름
 4  Interactables  손에 닿는 물건(쪽지·상자·카트·문) ← 물건 하나 = 파일 하나
 3  Signals        신호(쪽지 집음! 건넴! 노을!)       ← 층 사이를 잇는 유일한 줄
 2  World          데이터(장소·주민·물건·수치)        ← 아직 비어 있음(다음)
 1  Core           규칙(돈·파손·달력) — Unity 없음    ← 1초에 테스트 17개
```
폴더는 `F1/Assets/Scripts/` 아래 층 이름 그대로다. 층마다 `PitCrew.<층>.asmdef` 파일 하나가 "나는 누구를 볼 수 있다"를 선언한다.

## 2. 먼저 찍어 보기 — "쪽지를 집으면 무슨 일이 일어나나"

네가 칠판 앞에서 **E** 를 누른다. 그 한 번에 이런 일이 순서대로 난다. 어느 층이 어느 일을 하는지 보자.

1. **(5 Stages)** 감독이 매 프레임 "지금 시선 끝에 물건이 있나" 묻는다. `Stages/DayDirector.cs`
2. **(4 Interactables)** 쪽지가 "나야, 안내 글은 'E 쪽지 집기'야" 하고 답한다.
3. **(6 Presentation)** 화면이 그 글을 칩으로 그린다. 화면은 쪽지가 뭔지 모른다 — 글자만 받아 그린다.
4. 네가 E → **(4)** 쪽지가 **신호**를 쏜다: "쪽지 집음".
5. **(5)** 보관소 단계가 그 신호를 **듣고** "전표를 손에 들어라" 한다.
6. **(6)** 화면이 손에 든 전표를 그린다. 소리가 종이 소리를 낸다(둘 다 같은 신호를 들음).

쪽지는 감독을 모른다. 단계는 화면을 모른다. 화면은 쪽지를 모른다. **신호 하나로 연결**된다.

## 3. 실제 코드 보기 (3곳)

### 물건 하나 = 파일 하나 — 쪽지
`F1/Assets/Scripts/Interactables/Note.cs`
```csharp
public override string Prompt => Live ? "E 쪽지 집기" : "";          // :10
public override void Use() => SignalBus.Raise(Signal.NotePicked, "쪽지", Target);   // :12
```
- `Prompt` = 화면에 띄울 안내 글. 빈 글이면 칩이 안 뜬다.
- `Use()` = E 를 눌렀을 때. **딱 한 줄: 신호를 쏜다.** 다음에 뭘 할지는 쪽지가 정하지 않는다.
- 모든 물건이 같은 세 가지만 가진다(`Interactables/IInteractable.cs:10-12`): `Prompt`(안내 글) · `CanUse`(지금 되나) · `Use`(E).

### 단계는 신호를 듣는다 — 보관소
`F1/Assets/Scripts/Stages/Stage_Depot.cs`
```csharp
Listen(Signal.BoardOpened, _ => Enter());                                   // :35  칠판을 열면 이 단계로 들어온다
Listen(Signal.NotePicked, a => { if (a is HeldPaper n) PickNote(n); });     // :36  쪽지 신호 → 손에 든다
```
- `Listen` = "이 신호가 오면 이걸 해라". 단계는 쪽지 파일을 열어 본 적이 없다.
- 단계 8개가 전부 이 꼴이다: `Enter`(들어올 때) · `Tick`(매 프레임) · `Exit`(나갈 때) + `Listen` 몇 줄.

### 규칙은 Unity 없이 — 화물 상태
`F1/Assets/Scripts/Core/HandoverTier.cs`
```csharp
public const float OkMin = 0.8f;                                            // :9   80% 이상 = 멀쩡
public const float DentMin = 0.4f;                                          // :11  40% 이상 = 조금 상함
public static readonly float[] Pay = { 1.0f, 0.7f, 0.3f };                  // :14  받는 돈 배율
public static int Of(float integrity01) => integrity01 >= OkMin ? 0 : integrity01 >= DentMin ? 1 : 2;  // :18
```
- 숫자가 **여기 한 곳**에만 있다. 밸런싱 = 이 파일 숫자 바꾸기.
- 같은 폴더 `Core.Tests/CoreRulesTests.cs:7-14` 에 테스트가 있다. 예: `Tier_80이상_멀쩡`, `Pay_첫배달_멀쩡_1200`. Play 없이 1초에 17개가 돈다. 숫자를 잘못 바꾸면 여기서 먼저 빨갛게 뜬다.

## 5. 앞으로 이걸 어떻게 쓰나 (카디널과 이어짐)

### 네가 하는 것 (매일 같음)
1. 한 판 → 메모 3줄(막힌 곳·좋은 곳·싫은 곳).
2. 그 메모는 `world/SPEC.md` §10 「판정 기록」에 원문으로 들어간다. 규칙이 바뀌면 §1·§7 에.
3. 결과 그림을 보고 "통과 / 수정(이유) / 버림".

### PD 가 하는 것
- 메모 한 줄 → 위 표로 **층과 파일을 고른다** → 과제 한 장(`tasks/NN-*.md`): 여는 파일 · 바꿀 동작 · 안 됐으면 실패할 검사 1개.
- 팀원은 브리프(과제 + 명세 발췌 + 세계 스냅숏 + 파일 지도)만 읽고 그 파일만 고친다.
- 끝 조건은 자동: 컴파일 0 · Core 테스트 17 · 불변 검사 16 · 전후 Play 로그 같음(동작 바꾸는 과제면 "달라져야 하는 줄"만 다름).

### 구조가 자라는 방향 (순서대로)
1. **2층 World 채우기** — 지금 코드에 박힌 좌표·이름·주문을 데이터 에셋으로 빼고, `world/SPEC.md` 에서 **생성기**가 만든다. 그러면 "줄리아 집 위치", "오늘 주문 3개"는 코드가 아니라 명세 한 줄.
2. **길·배치도 생성기로** — 네가 느낀 "부자연스러운 길"은 손으로 고치지 않고 길 규칙(이어짐·곡률·폭)을 명세에 적고 다시 깐다.
3. **검사가 자란다** — 버그 하나 고칠 때마다 불변 조건 하나(16 → …). 네 메모가 검사로 바뀌면 같은 버그는 다시 안 온다.
4. **테스트가 자란다** — 규칙이 Core 로 들어갈수록 Play 없이 확인되는 양이 는다. 에디터는 점점 "보는 용도"가 된다.

### 하지 않는 것
- 감독(OnFootDirector)에 기능을 다시 얹지 않는다. 지금 219줄이고, 그대로 둔다.
- 숫자를 게임 코드 안에 쓰지 않는다(Core/World 만).
- 화면 코드가 게임 상태를 뒤지지 않는다(신호·칠판만).
- 디버그 코드를 게임 코드에 섞지 않는다.

## 6. 📖 단어장

- **층(layer)**: 케이크 한 단. 아래만 본다.
- **asmdef**: 층마다 있는 파일. "이 층은 누구를 볼 수 있다"를 적는다. 어기면 컴파일 에러.
- **신호(Signal)**: "쪽지 집음!" 같은 외침. 쏘는 쪽은 누가 듣는지 모른다.
- **물건(Interactable)**: E 로 뭘 할 수 있는 것. 안내 글·되나·E 세 가지만 안다.
- **단계(Stage)**: 하루의 한 토막(아침·정비소·보관소·포장·주행·문 앞·귀가·하루 끝). 들어올 때·매 프레임·나갈 때.
- **감독(Director)**: "지금 몇 단계인지"만 아는 219줄. 예전엔 1,747줄이었다.
- **Core**: Unity 없는 순수 규칙. 테스트가 1초에 돈다.
- **불변 조건**: "부두 끝엔 난간이 있다"처럼 항상 참이어야 하는 것. 과제 끝마다 자동 검사(16개).
- **파일 지도**: `docs/world/CODEMAP.md` — 파일 하나하나가 어느 층에서 뭘 맡는지. 팀원 브리프에 자동으로 붙는다.
