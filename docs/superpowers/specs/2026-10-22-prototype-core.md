# 프로토타입 스펙 — 핵심 메커니즘 + 최소 맵 (마감 2026-11-05)

상태: **READY** · 근거 D-117

## 1. 핵심 재미 (한 문장)

> **F1 차로 깨지기 쉬운 화물을, 시간 안에, 깨뜨리지 않고 배달한다.** — "빠르게 vs 조심히"의 긴장.

- 풍경 = 재미의 무대·보상(굽은 해안길에서 속도를 늦출 이유). 동사는 아님.
- 포장 = 피트스탑. 출발 전 제한 시간 안에 화물을 감싸는 정비 순간.

## 2. 한 판 (목표 5분)

```
긴급 전화(상황·배달지·제한 시간) → 수락 = 시계 시작 → 포장(피트스탑) → 주행(화물 HP) → 배달 → 정산 → 부품 1개 수리 → 다음 판
```

- D-118: 시계는 전화 수락부터 돈다. 목표 시간 = 포장 여유 40s(가설) + 주행 목표(거리 × 1.35 ÷ 55km/h). 안이면 시간 보너스, 넘으면 0, 2배면 종료.
- 전화 문구 = `OrderJob.callerName`·`urgentSituation` (비우면 화물별 기본 문구). UI `Order/UrgentCallPanel.cs`.

| 단계 | 플레이어 결정 | 쓰는 기존 코드 |
|---|---|---|
| 긴급 전화 | (지금은 수락만 — 두 통 중 고르기는 보류) | `Order/OrderBoard`, `OrderJob.timeLimitSec·baseReward` |
| 포장 | 빨리 대충 vs 꼼꼼히(시간 소모) | `Packing/*`, `WrapState` |
| 주행 | 코너·오르막 속도 | `ArcadeCarController`, `Cargo/CargoBox`(HP), `CargoShakeSimulator` |
| 정산 | — | `RunController.EndRun`, `ResultPanel` |
| 수리 | 다음 판 체감할 부품 1개 | `Upgrades/UpgradeSystem`(차고) |

정산 공식(가설): `보상 = baseReward × 화물 무결성% + 시간 보너스(제한 시간 안이면)`. 화물 0% = 그 화물 0원, 판은 계속(core-loop.md "런 중 게임오버 없음").

## 3. 프로토타입에서 끄는 것

연료 · 타이어 종류/펑크 · 경로 계획 화면 · 구역 해금 · 부스트 · 교통신호. 코드는 지우지 않고 꺼 둔다(플래그/씬에서 비활성).

## 4. 최소 맵

- 한 줄 코스: 가게(항구) → 해안 굽은 길 → 헤어핀 오르막 → 언덕 마을. 배달지 3~5곳, 편도 2~3분.
- 조건은 셋만: ① 끝까지 박힘 없이 달린다 ② 코너·오르막이 화물을 흔든다 ③ 바다가 보이는 구간이 1곳 이상.
- 실제 지도와의 일치도(OSM 이탈·R1 등)는 측정하지 않는다. 생성기 개선 중지.

## 5. 확정 (도현, 2026-10-22)

1. 1~3일차 메커니즘 시험 = **ComplexTrack**(이미 배선됨). 최소 맵은 4일차(10/25)부터.
2. 수리 = **서스펜션(흔들림 감소) vs 엔진(속도) 중 플레이어가 고름.** 판마다 "조심히 쪽 강화 vs 빠르게 쪽 강화" 선택이 핵심 긴장과 같은 축.
