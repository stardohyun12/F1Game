**객체 단위 정의.** FBX 노드 × 재질 칸 = 한 행. 한 메시로 합친 정비소(`garage_v5_combo`, 칸 11개)와 우체국 몸체(`Q4_PostOffice_body`, 칸 6개)는 칸별로 나눴다. 키트 시험 집(`art/source/kit-shared-v2/proof.fbx`, 노드 239개)은 같은 부품 이름끼리 묶었다(23행).
**영역.** 각 행의 UV 삼각형을 텍스처에 칠한 마스크다(= 그 객체의 UV 섬). 반복 UV 는 접었다. 투명(α<128)은 색 지표에서 뺐다.
**한계.**
- 잔결·반점은 **텍스처 기준**이다. ART-RULES 의 1px 반점 ≤0.3% 는 원래 **화면(720 컷) 지표**다. 기준 집 텍스처도 3.8% 라서 텍스처 단계 게이트로는 쓰지 않았다(경고만).
- 구운 빛은 면마다 0.2m 흐린 휘도를 평면 맞춤해 본 근사다. 원형 얼룩은 평면 잔차의 둥근 어두운 덩어리다.
- 원통은 링 정점이 규칙 각도로 도는 섬만 잡는다. 방(room)에서는 원통이 하나도 안 잡혔다(없거나 비정형).
- 작은 물건(64px/m) 판정 = 소품 노드이면서 섬 크기 ≤1.5m. 건물 부재(트림·벽)는 32px/m.
- 정비소의 props·details·sign·posters 는 자기 .gpl 이 없다. `scene-albedo-kit/garage_baked32.gpl` 로 대신 쟀다(json `gpl_proxy: true`).

## 6. 체계적 빈틈 (고르게 안 들어간 이유)

1. **결 넣기가 팔레트·반점 규칙을 깼다.** 키트 원본(시험 집)은 팔레트 일치 100%, 벽 색 9개, 반점 0~3%다. 같은 텍스처의 라이브러리 사본(보관소·우체국)은 `grain_1736`(±6% 명도 4단을 곱함) 뒤 **벽 팔레트 13% · 바닥 4~6% · 지붕 33% · 트림 29~76%, 벽 색 67~99개, 반점 10~12%**가 됐다. 근사 일치(채널 차 ≤6)는 75~96% — 팔레트 "밖"이 아니라 "칸 사이"로 밀렸다. 결 단계 색을 .gpl 에 넣거나, 결 뒤에 다시 양자화해야 한다.
2. **결 수치는 "겨우 통과"로 맞췄다.** 보관소·우체국·정비소 큰 면의 잔결 중앙값이 0.028~0.031 이다. 기준 p25(0.027~0.029)에 딱 붙어 있고, 기준 중앙값 0.098 의 1/3 이다. 반면 **방(room)은 0.08~0.16**으로 기준 중앙값 근처다 → 방만 결이 진하고 나머지는 옅다. 한 동네 안에서 질감 세기가 3배 차이 난다.
3. **기준 자체가 둘로 갈린다.** 기준 house_shop.png 의 큰 회벽 칸은 거의 단색이다(행 잔결 0.005, 단색 칸 48%, UV 붕괴 47%). 텍스처 전체 0.099 는 나무판·셔터·아틀라스 가장자리 칸에서 나온다. 기준 화면의 벽 결은 **셰이더 `_SN` 0.04 + 정적 그레인**이 만든다. 그래서 "기준 벽만큼 결"이라는 지시를 텍스처에 쓰면 근거가 흔들린다. 텍스처 결 목표와 화면 결 목표를 따로 적어야 한다.
4. **글씨·아이콘·데칼은 세상 텍셀 격자가 아니다.** `icons.png` 143~223px/m, 보관소 데칼 212px/m, 우체국 데칼 83px/m, 키트 벗겨짐 데칼 90~106px/m 다. 규칙(lessons 12: 같은 텍셀 밀도 픽셀 글씨)과 APPLY(간판 32 · 포스터 64)를 어긴다. 글씨 행 13개 중 7개만 통과했다. 아이콘 텍스처는 팔레트 칸도 없다(0%).
5. **보관소·우체국은 텍스처 7장이 바이트까지 같다**(md5 동일: wall·floor·roof·trim·decals·icons). 그래서 1번과 4번 결함이 두 번 나온다. 한 번 고치면 둘 다 고쳐지지만, 두 건물이 같은 색·같은 결로 보이는 것도 같은 원인이다(APPLY 의 "색·UV 시작점·데칼 조합을 달리" 규칙은 UV 로만 지켜진다).
6. **정비소만 다른 체계다.** 재질 11개가 공용 `SceneA7Lit` 대신 포크 `A7LitPoint_garage.shader`(점광원 4단 + `_Emit`)를 쓴다. 렌더 큐도 기본(-1)이다(다른 건물 2450). 자기 .gpl 이 없고(props·details·sign·posters), 있는 `dirt_baked32.gpl` 도 지금 흙 텍스처와 0% 일치(굽기 시절 팔레트). 반대로 **보관소 `Q3_lamp` 는 공용 셰이더라 빛이 안 난다** — "전등은 실제로 빛이 나게"(lessons 12)가 정비소에만 적용됐다.
7. **작은 물건 64px/m 가 들쭉날쭉하다.** 방 소품 64 ✓, 보관소 택배 64 ✓, 정비소 props 64 ✓. 하지만 **우체통 32**, 보관소 앞 상품·포장대 32(공용 wall.png 를 그대로 씀), 그리고 **보관소 내부는 벽·트림·지붕이 64**(밖은 32)다. 한 건물 안에서 안팎 밀도가 두 배 다르다.
8. **원통 16면 규칙은 6개 중 2개만.** 정비소 8면·6면, 보관소 10면(앞 상품·내부), 우체국 12면. 16면을 지킨 건 정비소 타이어 쪽(62개)과 보관소 내부 1개뿐이다.
9. **UV 붕괴(한 점 색)가 남아 있다.** 정비소 전등(`Garage_Lamp_Emit`) 100%, 보관소 앞 상품 바닥칸 100%, 정비소 간판 15%, 키트 문손잡이 100%. "단색 채우기 금지"(lessons 1)의 숨은 구멍이다.

## 7. 게이트 스크립트 — `tools/art/check_rules.py` (작성함, 읽기 전용)

- 구성: `tools/art/check_rules.py`(측정·판정·표·시트) + `tools/art/_rules_bpy.py`(Blender 헤드리스: 노드 × 재질 칸 면 덤프, 섬 크기, 원통 링).
- 실행:
  - 전체: `python -X utf8 tools/art/check_rules.py --json <out.json> --md <out.md> --sheet <out.png>`
  - 한 건물: `--only depot` (room · garage · depot · postoffice · kit; 기준 ref 는 늘 같이)
  - 게이트: `--gate` → 게이트 규칙 위반이 하나라도 있으면 exit 1, 위반 수 출력.
  - Blender 다시 안 돌리기: `--dump <앞서 만든 덤프 json>`. Blender 경로는 환경변수 `BLENDER`(기본 `D:/Tools/Blender/blender.exe`).
- 새 건물 추가: 파일 맨 위 `B` 사전에 한 줄(fbx · 텍스처 폴더 · .gpl · 재질 이름→텍스처 규칙).
- 쓰는 곳: 지정한 출력 경로만. 에셋·F1/·art/export 는 안 건드린다.
