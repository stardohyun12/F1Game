01이게 어떤 게임?

당신은 망한 F1 팀의 마지막 멤버다. 차고에는 망가진 머신만 남았다. 돈을 벌어야 부품을 복원할 수 있다. 그래서 잠시 배달 운전사가 된다.

한 런은 5~15분. 도시에서 주문 카드를 고르고, 화물을 직접 트렁크에 포장·배치하고, 경로를 짜고, 차를 몰아 배달한다. 운전이 거칠면 화물이 깨진다. 완주하면 정산금이 들어오고, 그 돈으로 F1 부품을 한 조각씩 복원한다.

엔진이 돌아오고, 변속기가 살아나고, 마침내 머신이 가동되면 — 그랑프리로 복귀한다. 배달은 수단, F1 복귀가 목적이다.

02왜 이 게임인가

시장에 이 4가지를 동시에 만족하는 게임이 없다.
USP 1

한 런 5~15분

커피 한 잔, 출퇴근 한 정거장. 90분짜리 Pacific Drive도, 무제한 EDC도 아닌 딱 한 결정 단위. 결과까지 보고 닫는다.

USP 2

한 런에 결정 4개

주문 / 포장 / 경로 / 업그레이드. Crazy Taxi는 0~1개. 카드 로그라이트(Slay the Spire)급 결정 밀도를 운전 게임에.

USP 3

Burnout급 운전감

아케이드 드리프트, 즉각 피드백. 시뮬레이션 아님. 운전 자체가 재미. "조작감만으로도 한 시간 굴림"이 1주차 검증 통과 조건이었다.

USP 4

매 런이 다른 빌드

로그라이트 정산. 업그레이드가 다음 런 감각을 바꿈. EDC같은 단방향 진보 아님. 매번 새로 짠다.

03이런 사람이 산다

코어 타겟 4그룹. 모두 Steam 인디 게임 정기 구매자.
PERSONA 01

출퇴근 게이머

지하철 한 정거장, 카페 한 잔, 점심 후 15분. "5분만 더"가 가능한 한 런 단위를 찾는 직장인. Vampire Survivors / Slay the Spire를 정기 구매.

PitCrew: 한 런 5~15분 = 딱 그 사람들 시간 단위.
PERSONA 02

모터스포츠 팬

F1 시즌 매주 챙겨봄. F1 Manager / Forza에 관심은 있지만 시뮬은 부담. "F1 분위기는 있는데 가볍게 즐기는" 게임을 찾는 사람.

PitCrew: F1 머신 복원 = 모터스포츠 정서 + 아케이드 부담 없음.
PERSONA 03

배달/물류 시뮬 애호

Easy Delivery Co. / Mail Time / Death Stranding 같은 "운송이 주제"인 게임 좋아함. 비전투 게임에 친화. 코지하지만 약간의 긴장은 원함.

PitCrew: 배달 + 화물 깨질까 걱정 = 정확히 그 정서.
PERSONA 04

로그라이트 빌더

매 런 다른 빌드 짜는 재미. Slay the Spire / Hades / Balatro 코어 팬. "정산 → 다음 런 감각 변화"가 메인 동기.

PitCrew: 부품 복원이 차 감각 바꿈 = 로그라이트 정산 직격.

05핵심 시스템

단순한 메커니즘 9개. 조합으로 깊이 발생.
[ 3D 포장 화면 — Bubble/Foam/Hardcase 진행 ]

3D 포장 미니게임

화물마다 4채널 포장. 클릭·드래그로 직접 감싸기. 깨지기 쉬운 와인병은 풀세트, 무거운 박스는 minimal. 비용·시간·보호 사이 trade-off.

✅ 구현 완료
[ 트렁크 배치 화면 — 큐브 N개 드래그 ]

트렁크 자유 배치

1~3개 화물을 직접 트렁크 바닥에 놓는다. Q/E/R로 90도 회전. 빈 공간 = 화물 슬라이드 위험. 빽빽이 채우면 충돌 적지만 시간 ↑.

✅ 구현 완료
[ 운전 + 화물 슬라이드 데모 ]

아케이드 드리프트 + 화물 물리

Burnout 풍 운전. 급제동·코너에서 화물이 트렁크 안에서 미끄러진다. 충돌 누적 → 화물 손상 → 정산금 ↓.

✅ 구현 완료
[ 도시 + 미니맵 + 화살표 ]

도시 · zone 해금 · 내비

다운타운에서 시작. 자금이 모이면 항구·공업 zone 자동 해금. 미니맵·방향 화살표로 헤매지 않음.

✅ 구현 완료 · 맵 확장 진행중
[ 차고 + F1 머신 부품 진행도 ]

F1 머신 복원 (메타 게임)

정산금으로 부품 한 조각씩 구매. 엔진 → 변속기 → 서스 → 에어로 → 타이어 → 도색. 부품마다 차 감각 변화. 완전 복원 → 그랑프리 모드 해금.

🔴 핵심 진행 작업 (이번 주)
[ 정산 화면 — 7카드 결과 ]

로그라이트 정산

한 런 끝마다 7카드: 수익 · 거리 · 손상 · 보너스 · 평판 · 연료 · 시간. 합산 자금으로 다음 런 결정.

S6아키텍처 원칙

왜 이렇게 짰는가. 다음 시스템 추가할 때 따라야 할 패턴.

Services DI (Composition Root)

GameContext.Awake에서 14 시스템을 Services static 컨테이너에 주입. 각 시스템은 인터페이스로 상호 참조. singletons 없음, 테스트 가능. 세션 18~19 리팩토링.

ScriptableObject = 데이터 진리원

TrackLayout, OrderJob, ZoneRegistry, CargoTypePresets는 모두 SO. 코드 하드코드 금지 (asset.md). 새 잡 = 새 SO 1개, 코드 변경 0.

Modifier Chain (Phase 3)

화물 baseline → 포장 multiplier → 업그레이드 additive 합성. 각 modifier는 단일 클래스. 새 채널 추가 = chain에 modifier 1개 추가.

Template Method (Phase 2)

화물 손상 계산이 모든 화물 종류에 공통 흐름. CargoType.OnImpact가 templateMethod, 종류별 override가 frame-by-frame.

AudioCueBus (단일 채널)

모든 사운드 트리거가 AudioCueId enum + AudioCueBus.Publish()로 통과. 호출처에서 AudioSource 직접 안 쓴다. clip swap 한 곳에서.

Editor 자동 빌드

TileMapAuto / BuildingPlacer / SetupOrderSystem가 SO 변경 시 씬을 자동 재구성. 씬 manual 편집 최소. RunFullRebuild로 일괄.

검증 자동화

TrackConnectivityVerifier BFS, BuildingPlacer.VerifyPlacements bounds 검사. 자동 빌드마다 실행. 침묵 실패 방지.

RunMetricsRecorder

매 런 자동 측정 (시간·거리·잡·결과) → CSV. 밸런스 결정의 근거는 추측 아닌 데이터. 세션 26 도입.
