# 스튜디오 소통 규약 (파일 버스)

> 독립 인스턴스끼리는 직접 소켓이 없다(메인↔PM). 그래서 **파일에 적어 소통한다** — 안 사라짐.
> 핸드오프(일감 전달)는 한 방향이지만, **메시지 버스는 양방향**이다.

## 누가 어느 파일로 소통하나

| 파일 | 소유 | 쓰는 사람 | 읽는 사람 | 방향 |
|---|---|---|---|---|
| `docs/studio/bus.md` (메시지 버스) | 공용 | 메인·PM | 메인·PM | **양방향** |
| `backlog.md` (루트) | PM | PM | 전원 | PM→전원 |
| `docs/CONTROL.md` | PM/공용 | PM, 메인 | 도현 | →도현 |
| `tools/studio-dashboard/activity.jsonl` | hook 자동 | hook | 대시보드 | →대시보드 |
| 디스패치 브리프 (`docs/studio/briefs/<slug>.md`) | PM | PM | 메인 | PM→메인 |
| 게이트 판정 | 게이트 | 게이트 서브 | 메인 | 게이트→메인 |

## 메시지 버스 사용 (양방향)

- 형식: 맨 아래 한 줄 append — `- [MM-DD HH:MM] 보낸이→받는이: 내용`.
- **각자 작업 사이클 시작에 버스 끝을 확인**하고, 나에게 온 미응답 메시지에 답한다.
- 긴 내용(브리프·스펙)은 버스에 쓰지 말고 파일로 만든 뒤 "X 만듦, 경로 …"로 알린다.
- 한계: 두 인스턴스가 실시간 폴링은 안 함 → 소통은 *턴 기반*(각자 움직일 때 버스 확인). 비동기 협업엔 충분.

## 디스패치 브리프 형식 (작업당 1장)

```
# <작업 제목>
- 현상: (지금 무엇이 문제/목표인가)
- 원인 가설: (PM이 추정하는 root cause, 있으면)
- 완료 조건: (무엇이 되면 끝인가 — 측정 가능하게)
- 관련 파일/메뉴: (메인이 바로 찾게)
- 게이트: 화면? 흐름? (어느 게이트 타는지)
```

## 계급별 라우팅 (모든 변경이 풀코스 타지 않음)

| 변경 종류 | 경로 |
|---|---|
| 오타·docs·hook-only | 메인 혼자 |
| 한 시스템, 화면 안 건드림 | 메인 + 기획 게이트 |
| 화면 / 배선 / 새 시스템 | 풀코스: PM 브리프 → 메인 구현 → 게이트 둘 → QA 실플레이 → 커밋 |

## 게이트 판정 형식

`PASS` 또는 `FAIL` + 좌표(어디가 왜). 느낌("좀 어색") 금지 — 구체 위치.

## 불변 규칙

- 게이트(판정자)는 컨텍스트0 = 매번 백지 서브에이전트. 메모리 로드 금지.
- 제안자(PM·리드)는 메모리 로드 O.
- Unity 에디터 1개 → Play는 직렬. 게이트 서브는 Play 금지.
- "좋다" 사인은 도현만. 에이전트는 "안 깨짐"까지.
