# 속도감(F1 더 무비) + 규모감(Easy Delivery Co) — 근거 문서

작성: 리서치팀, 2026-10-23 (PD 과제 20261023-1655, D-126). 질문: 두 레퍼런스에서 무엇을 가져오고, 960×540 Point 렌더와 충돌하는 건 무엇이며, 맵 끝 옹벽·노란 가드레일을 어떻게 바꾸나.
표시: [확인] 원문을 읽음 · [2차] 요약/검색 스니펫/리뷰 · [측정] 리포에서 직접 확인 · [계산] 내가 계산 · [추정] 내 추론 · [미확인] 못 찾음.

## 0. 먼저 — 전제 정정 두 가지
1. **EDC 의 "속도감"은 근거를 못 찾았다.** 80.lv 개발 기사에 속도·카메라·도로 설계 언급이 **없다**(읽고 확인). 리뷰는 오히려 "레트로한 덜컹거림", "눈둔덕에 튀고 빙판에서 미끄러지고 고속에서 빙그르르 돈다"(촉감 묘사)라 하고 최고속도 수치도 없다 → [Useapotion](https://www.useapotion.com/2026/03/easy-delivery-co-review-cozy-courier-shifts-in-an-eerie-snowy-town/) [2차]. 도현이 EDC 에서 느낀 "속도감"이 정확히 어느 장면인지 모르면 가져올 요소를 못 정한다 → 물어볼 것(§6).
2. **EDC 의 "규모감"을 만든 방법도 개발자 원문에는 거의 없다.** 안개 거리·원경 실루엣·맵 경계 처리는 80.lv 에 **언급 없음** [확인]. 아래 EDC 쪽 손잡이는 "확인된 2가지 + 리뷰에서 읽히는 것 + 내 추정"의 합이다.

**핵심 충돌 정리**
- **모션블러는 쓰지 않는 쪽이 근거와 맞는다**: 효과 근거가 약하고(Disney 무효, Aalborg 역효과) 우리 렌더 규칙과 충돌할 가능성이 높다. 단 "충돌한다"는 건 *내 추정*이고 시험 캡처로 확인된 적 없다.
- **안개 vs 속도감은 서로 당긴다**: 규모감을 위해 안개를 짙게 하면 대비↓ → 체감 속도↓ 가능성(2차 근거). → "근경은 속도, 원경은 규모"로 **거리 구간을 나눈다**(§4 규칙 1).
- 2차 보고에서 "후처리가 켜져 있으면 Nearest 가 안 먹는다"는 우려는 **해소**: 프로그래머 팀이 게임 뷰 캡처로 짝수 픽셀 쌍 100% 동일(정확한 2배 Point)을 확인 → `docs/team/reports/programmer-20261023-1527.md:22` [측정, 남의 보고].

| 0~40m | **속도 층**: 대비 높음, 스침 물체 촘촘 | 안개 영향 없는 구간에서 광학 흐름 확보 |
| 40~120m | **전환 층**: 안개가 서서히, 물체는 건물·나무 | 시야 차단·실루엣 |
| 120m~ | **규모 층**: 안개색에 녹는 실루엣만 | 끝을 가림 |

## 5. 현재 맵 끝 옹벽·노란 가드레일 → 대체안

현재 [측정] (`F1/Assets/Editor/BuildMapBoundary.cs`): 맵 둘레 `MinX −9..MaxX 183`, `MinZ −9..MaxZ 135`(192×144m, 줄 18). 옹벽 높이 1.1m·두께 0.8m, 충돌 박스 1.6m (줄 22). **레일 색 (0.86,0.64,0.18) = 채도 높은 노랑**(줄 39). 기둥 6m 간격(줄 23). 둘레 전부 같은 벽, 바깥 바닥 80m 폭 + 북쪽 해저 280m까지, 장식 바위 70개(충돌 없음).

**왜 규모감을 해치나 [추정]:** 직선·고채도 노랑이 **지도의 끝을 선으로 그어 준다**. 안개로 아무리 가려도 가까이 가면 "벽에 갇힌 사각형"으로 읽힘. 규모감의 반대.

| 안 | 내용 | 규모감 | 비용 | 위험 |
|---|---|---|---|---|
| **A. 색부터 바꾸기** | 레일·덮개를 안개색 쪽으로 채도↓(콘크리트 회색 계열 한 색), 레일 제거 | 약간↑ | 낮음 (상수 수정+재생성) | 벽 자체는 남음 |
| **B. 방향별 처리 (추천)** | **북=바다**: 옹벽 제거, 부두 끝·방파제 낮은 턱(충돌 별도, 시각은 낮게) + 수평선. **서·동·남=시야 차단 띠**: 언덕·나무·건물·해안 절벽을 20~80m 폭으로 이어 붙이고 충돌은 그 앞에 보이지 않게. 바깥은 안개 | ↑↑ | 중간 | 띠 배치 노력, 충돌 틈 점검 |
| **C. 소프트 경계** | 경계 근처에서 속도 감소+화면 페이드로 되돌려 보냄. 시각 벽 없음 | ↑↑↑ | 높음 | 이 생성기를 만든 이유(코드 주석: 바닥 바깥에 콜라이더가 없어 차가 떨어졌음)를 지키려면 보이지 않는 콜라이더를 병행해야 함 |

**추천:** 우선 **A 를 즉시**(상수만 바꿈) + **B 를 단계적으로**. 이유: 북쪽은 이미 바다/해저가 깔려 있어(줄 48) 옹벽을 걷어내도 자연 경계가 있고, 나머지 3면만 띠로 막으면 된다. 근거는 일반론+Firewatch 층 구조 [2차]이며 **EDC 가 실제로 어떻게 경계를 처리하는지는 확인 못 했다.** 시험 후 도현이 1× → 흑실루엣 → 4× 로 판정할 것.

⚠ 주의: `BuildMapBoundary` 는 "MapBoundary" 루트를 지우고 처음부터 다시 만든다(줄 29-30) → 수동으로 손본 건 날아간다. 수정은 상수/스크립트 쪽에서.
