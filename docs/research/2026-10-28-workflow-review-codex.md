# PitCrew 아트 제작 워크플로우 평가 — 2026-10-28

지금은 제작 루프보다 복구 루프가 크다. 도현이 아트 방향뿐 아니라 누락된 재료 처리, 겹친 면, 통으로 합친 택배까지 찾아내고 있다. PD는 이를 다시 과제로 번역하고, 끊긴 작업을 발굴하고, 서로 다른 화면을 설명한다. 팀원 수나 모델 성능부터 바꿀 문제가 아니다.

**조사 범위와 판정 방식**

- 요청한 문서, 역할·교훈 전부, artlive 당일 보고 11개, 현재·archive JSONL 전부를 읽었다. 실행기·로그 변환기·검사기·판정기·임포트 코드도 대조했다.
- 비용은 10월 28일 KST 과제 구간부터 각 로그의 마지막 종료까지 집계했다. artlive는 20:00:05까지다. 날짜 없는 live.log는 보고 파일명과 원본 Claude 세션의 UTC 시각으로 확인했다.
- 아래 **확인**은 파일·로그·저장 이미지에서 직접 확인한 내용이다. **보고**는 팀원의 주장이다. 효과·소요 시간은 **제안/추정**이다. 시간은 담당자 1명의 구현·확인 시간이며 도현 대기는 제외했다.
- Unity·Blender·검사기·VLM을 실행하지 않았다. 저장된 감사 JSON은 다시 집계했다. 전/후 이미지 두 장은 직접 열었다. 에셋의 현재 실행 품질을 새로 인증한 보고가 아니다.

새 유료 도구·모델·에셋 도입은 권하지 않는다. 기존 bpy·Unity·뷰어를 사용한다. 사진 CC0와 팩 CC0/CC-BY·출처 장부 정책은 유지한다. 외부 코드나 이미지를 이 보고에 복사·설치하지 않았다. 원본 제작 워크플로우를 실행 재현한 것도 아니다.

실행 순서는 **1·2·10으로 작업 상태와 비용부터 신뢰 가능하게 만들고, 보관소 하나에 3–8을 적용해 재생성·검증까지 닫는 것**이다. 9는 기존 점수 문턱 제거부터 한다. 열 가지 도구를 동시에 새로 만드는 프로젝트로 키우지 않는다.
