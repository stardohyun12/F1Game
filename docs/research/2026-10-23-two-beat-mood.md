# 두 박자 분위기 ("갈 땐 급하게 → 돌아오는 길이 보상") — 근거 문서

작성: 리서치팀, 2026-10-23 (PD 과제 20261023-1642). 질문: D-125 경험 문장을 실제로 해낸 게임이 있는가, 무엇으로 두 박자를 나눴는가.
표시: [확인] 원문을 읽음 · [2차] 요약/리뷰/뉴스 · [측정] 리포에서 직접 확인 · [추정] 내 추론 · [미확인] 못 찾음.

## 0. 먼저 — 전제에 대한 정직한 정정
- **"일과 귀가가 다른 분위기를 낸다"고 개발자가 직접 말한 게임은 찾지 못했다.** [미확인] 아래 사례는 전부 *한 조각*(시간대에 따라 색이 변함 / 조용한 구간을 일부러 둠 / UI 를 없앤 모드)만 뒷받침한다. 두 박자를 하나의 설계로 묶은 1차 발언은 없다.
- 따라서 이 문서의 "손잡이"는 **사례에서 뽑은 것(요소별 근거)** 과 **우리 프로젝트에 이미 있는 레버(리포 확인)** 를 합친 것이며, 조합 자체는 **[추정]** 이다. 검증은 프로토에서 도현이 직접 보는 수밖에 없다.

## 4. "돌아오는 길"이 루프에 들어가려면 — 최소 기능 [추정]

1. **시간제한 없음** — 귀가 구간에선 타이머·정산 감점이 없어야 "보상"이 된다.
2. **화물이 없다** — 파손 걱정이 없는 상태 자체가 안도의 원천(구조에서 나오는 장점, 별도 연출 불필요).
3. **보상이 손에 잡힘** — 바다·빛이 보이는 것만으론 약하다. 구간 끝에 정산 화면이나 다음 주문 수락이 *귀가 끝에서* 일어나게 하여 "끝나면"이 문장대로 읽히게.
4. **길이 상한** — 귀가가 길면 지루해진다. 구간 길이/시간은 모르는 값이라 **프로토에서 30·60·90초 3안을 도현이 직접 비교** 권장(숫자는 시험안일 뿐 근거 없음).
5. **건너뛰기 선택지 or 빠른 귀환** — 반복 플레이에서 보상이 짐이 되지 않게 하는 안전장치(도현 결정 사항).
6. **측정 가능한 기준** — 같은 장소 스크린샷 2장(갈 때/올 때)을 흑실루엣 판정에서 구분 가능한가.

## 5. 형용사/금지어 초안과 사례의 일치 (한 줄 의견)
"따뜻한·바쁜·바랜"은 **갈 때 박자와 EDC·기쿠지로 계열 색(바랜 따뜻함)과는 맞지만, '돌아오는 길'의 기우는 노란 빛은 '바랜'보다 '황금빛·느긋한'에 가까워** 두 박자에 같은 형용사를 쓰면 한쪽이 틀린다 → 박자별 형용사 쌍으로 쪼갤 것을 제안(예: 갈 땐 *바쁜·바랜*, 올 땐 *따뜻한·느긋한*). 금지어 "깨끗한·귀여운·웅장한"은 Easy Delivery Co·Firewatch 가 칭찬받은 방향(낡고 낮은 채도)과 일치하나, "귀여운"은 Mail Time 처럼 **팔리는 편안한 배달 게임의 핵심 형용사**라서 금지 여부는 도현 판단 사항(근거는 약함).

## 6. 모르는 것
- 일/귀가 두 박자를 개발자가 직접 설계 의도로 말한 1차 발언 — **못 찾음.**
- Death Stranding "도착 시 곡이 흐른다"는 설계 — 출처 없음.
- 카메라 FOV·속도로 감정을 가른 사례 — 못 찾음.
- Easy Delivery Co 의 시간대 색 변화가 *긴장 → 안도*로 설계됐는지 — 아님(조명 규칙 설명뿐).
- 비게임 3개의 장면 분석 1차 자료, 안정적 이미지 직링크(저작물이라 링크는 위키 문서 수준).
- 현재 `MoodController` 가 시간대 전환(갈 때→올 때)을 지원하는지, 값이 어디까지 바뀌는지 — 이번에 코드를 읽지 않음. 아트/프로그래머 팀 확인 필요.
