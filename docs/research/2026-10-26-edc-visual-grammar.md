## 0. 한 줄 답

**EDC 는 "화면 격자 하나 + 표면은 큰 얼룩만"이고, 우리는 "화면 격자 + 텍셀 격자 + 사진 점무늬"다.**
EDC 표면의 1픽셀 반점은 0~0.2%, 우리 인도·풀은 1.2~5.8% [측정]. EDC 는 디테일이 픽셀보다 크고, 우리는 디테일이 픽셀과 같은 크기라 "때"로 읽힌다.
Look4 는 반대로 큰 면(벽·도로)을 완전 단색으로 만들어(중간주파 0.00~0.45) "그림판"이 됐다. EDC 는 그 사이 — 큰 얼룩(8~40px 대역 std 3.6~11)은 있고 점은 없다.

---

## 1. 측정 방법 (짧게)

1. **내부 해상도**: 세로·가로 경계 강도 프로필을 분수 주기(1.8~14px, 0.01 간격) DFT 로 훑어 가장 센 주기 = 픽셀 계단 크기.
2. **내부 해상도 판**: 블록 중앙 3×3 중앙값으로 한 칸에 한 픽셀만 뽑음(JPEG 잔물결 제거). 이후 통계는 모두 이 판에서.
3. **표면 잡음**: 같은 재질 영역을 잘라 (a) 1px 반점 % = 3×3 중앙값에서 휘도 ±12 넘게 튄 픽셀, (b) 중간주파 = 가우시안 0.7−3 차의 std(2~8px 무늬), (c) 저주파 = 가우시안 3−12 차의 std(8~40px 얼룩), (d) 1px 색잡음 = 색차(R−G, B−G)의 고주파 std.
4. **색 수**: RGB 를 채널당 4bit(16단)로 묶어 화면 90% 를 덮는 칸 수(`cover90`). JPEG 라 "고유색" 대신 이걸 쓴다.
5. **디더**: 평평한 영역의 잔차(원본−블러) 자기상관. 체커 디더면 가로·세로 1칸 상관이 음수, 대각 1칸이 양수.

## 2. EDC 9장 — 항목별 판독

### 2.1 내부 렌더 해상도 [측정 + 개발자 + 2차]
| 장 | 원본 | 계단 크기(px) | 내부 해상도 |
|---|---|---|---|
| 01·04·05 | 1920×1080 | 4.22 | 455×256 |
| 02·06·07 | 1920×1080 | 4.24 | 453×255 |
| 08 | 2560×1440 | 5.63 | 455×256 |
| 03 (가게 실내) | 1920×1080 | 4.85 | 396×223 |
| 09 (밤 개 NPC) | 1920×1080 | 5.63 | 341×192 |

- 9장 중 7장이 **456×256** 이다. 개발자 발언 "made-up 456x256 resolution screen" 과 같다 [개발자: 80.lv]. 스팀 토론도 내부 해상도 456×256 이라 한다 [2차].
- 03·09 는 더 거칠다(396, 341 폭). 옛 빌드나 연출 컷일 수 있다 [추정].
- 1080p 화면에서 4.2배 비정수 확대다. 그래도 계단 위상이 고르다 → 최근접(Point) 확대 [측정].
- 우리 캐처(1280×720)는 계단 2.0px = 640×360. 실제 1080p 게임에선 960×540 (`PC_RPAsset` renderScale 0.5). **EDC 보다 가로 2.1배, 픽셀 수 4.4배 많다.**

### 2.2 색 수·양자화 [측정]
- 화면 90% 를 덮는 4bit 색 칸: 낮 눈길 02·06·08 = 12~17, 밤 01·05·07·09 = 4~14, 붉은 건물 거리 04 = 43.
- 우리: a_car 29~34, b_street 23~27, c_town 42~44, f_grass 43~52.
- 안개 하늘 세로 그라데이션: 한 줄당 평균 0.06~0.23 레벨씩 변함, 영역 안 휘도 고유값 27~53개 → **색 깊이를 줄이지 않았다**(PS1 15bit 면 8레벨 계단이 보여야 한다).
- 즉 EDC 의 "적은 색"은 양자화가 아니라 **장면이 한 색조(안개=앰비언트)로 묶여 있어서**다.

### 2.3 디더 [측정]
- 세계(눈·하늘·도로·벽)에는 **디더 없음**. 평평한 영역 잔차 상관이 가로 +0.14~+0.44(부드러움), 체커 흔적 없음.
- 예외 1장: 07(오두막 실내)의 **비네트 띠**에만 2×2 체커(가로 −0.55, 세로 −0.46, 대각 +0.41), 진폭 ±1~2 레벨 → 눈에 거의 안 보이는 밴딩 방지용 [측정]. 세계 표면에는 없다.

### 2.4 텍스처 밀도·필터·종류
- 도로·눈밭 안쪽은 여러 픽셀에 걸친 **부드러운 그라데이션**(바퀴 자국 줄무늬)이다. 차 바로 앞에서도 텍셀 네모가 안 보인다 [측정: 비교 시트].
- → 세계 텍스처는 바이리니어+밉맵이거나, 아주 저주파(디테일이 화면 픽셀보다 큼)라 Point 여도 네모가 안 보인다 [추정]. **화면을 거칠게 만드는 것은 오직 456×256 화면 격자**다.
- 환경 = 실사진 포토배시, 차·화물·캐릭터 = 손 픽셀아트 [개발자: 80.lv, 위키]. 화면에서도 그렇게 읽힌다: 나무는 사진 잘라낸 알파 카드(01·02·08), 절벽은 사진 질감(06), 상자는 단색 면 + 송장 라벨 한 장(04).
- 붉은 벽(04)은 벽돌 무늬가 없다. 거의 한 색 + 큰 얼룩(중간주파 3.1, 저주파 3.6) [측정].
- 표면 수치(내부 해상도 기준):

| 표면 | 1px 반점 % | 중간주파(2~8px) | 저주파(8~40px) | 중간/저 비 | 1px 색잡음 | 채도 |
|---|---|---|---|---|---|---|
| EDC02 눈길 도로 | 0.0 | 1.44 | 4.15 | 0.35 | 0.59 | 0.025 |
| EDC06 도로 | 0.0 | 2.09 | 5.97 | 0.35 | 0.65 | 0.033 |
| EDC04 붉은 벽 | 0.1 | 3.10 | 3.61 | 0.86 | 0.91 | 0.373 |
| EDC04 눈길 | 0.1 | 4.05 | 9.28 | 0.44 | 0.85 | 0.057 |
| EDC03 실내 바닥 | 0.2 | 6.07 | 11.43 | 0.53 | 1.16 | 0.165 |
| EDC05 밤 자갈(전조등 속) | — | 4.99 | 4.86 | 1.03 | — | — |

### 2.5 대비·채도 [측정]
- 낮 장면 휘도 p5~p95: 02 = 63~170, 06 = 71~164, 08 = 138~215. 좁다(폭 77~107). 우리 a_car Look0 = 48~185(폭 138).
- 채도 평균: 낮 0.03~0.04, 거리 04 = 0.12, 밤 0.13~0.25. 07 의 0.56 은 거의 검정에 가까운 초록 비네트 때문(밝기 10~20)이라 의미 없음.
- 고채도는 **작은 사람 물건만**: 붉은 미등, 파란 자판기, 노란 모닥불, 주황 상자. 화면 몇 % [추정].

### 2.6 안개 [측정 + 개발자]
- 하늘 꼭대기 중앙값: 낮 155·155·155 / 159·159·154 / 181·180·175, 밤 38·38·44 / 33·32·38. **회색 무채색, 하늘 = 안개 = 지평선.**
- 개발자: "그림자·해 없음. 시간대에 따라 바뀌는 앰비언트 한 색. 안개도 같은 색" [개발자: 80.lv].
- 가시거리: 02 에서 30~40m 뒤 나무가 이미 반쯤 씻김, 08 은 20m 안 나무도 실루엣만 [추정: 나무 크기 기준 눈대중].
- 눈 입자는 낮엔 배경보다 조금 어둡게, 밤엔 조금 밝게 [개발자].

### 2.7 조명 [측정·관찰 + 개발자]
- 실시간 그림자 없음. 객체 대비는 SSAO 를 약하게 [개발자].
- 밤 장면만 **빛 웅덩이**: 전조등 앞 땅 원뿔(05), 모닥불 바닥 원(01, 반지름 ≈ 사람 키 1.5배 [추정]), 랜턴 원(09), 자판기 파란 발광(05). 원 가장자리는 부드러운 그라데이션, 디더 없음.
- 면 음영은 거의 안 보인다. 트럭 흰 차체 옆·뒤 명도 차가 작다 → 음영은 텍스처에 그려 넣음 [개발자 "shade objects within their textures"].

### 2.8 PS1 특성
| 특성 | EDC | 근거 |
|---|---|---|
| 낮은 내부 해상도 | 있음, 456×256 | [측정][개발자] |
| 정점 흔들림/스냅 | 있음. 캐릭터 애니메이션에 일부러 "가짜 반올림 오차·지터" | [개발자: 80.lv] / 경사·고개에서 모델이 어긋나는 지터 불만·옹호 [2차: 스팀 토론] |
| 어파인 텍스처 왜곡 | 정지 화면에선 **못 봄**. 03 가게 바닥 타일 줄이 곧다 | [측정 한계] |
| 색 깊이 축소·디더 | **없음**(비네트 1곳 제외) | [측정] §2.2·2.3 |
| Z 파이팅·틈 | 9장에선 못 봄 | [관찰] |
| CRT 필터 | 선택 옵션(끌 수 있음), 덧씌우기 | [2차: 스팀 토론] |
| 텍스처 최근접 필터 | 세계 텍스처엔 **안 보임**(부드러운 그라데이션), UI·손픽셀만 각짐 | [측정][추정] |

→ EDC 의 "PS1 느낌" = **해상도 + 안개 + 평평한 빛 + 저폴리 + 캐릭터 지터**. 디더·색 깊이·텍스처 네모는 쓰지 않았다.

### 2.9 폴리 밀도 [추정]
- 집 = 상자 + 지붕 한 장(06 오두막). 나무 = 사진 알파 카드 2~3장. 전봇대 = 기둥 + 선(선은 1px 검정, 처지는 곡선).
- 트럭 = 상자형, 바퀴 단면 각진 원(8~12각). 수백 tris 대 [추정].
- 지형 = 큰 삼각형. 눈길 가장자리가 직선 조각으로 꺾인다(06 오른쪽).

### 2.10 사람(NPC) [관찰 + 위키]
- **사람이 아니다.** 의인화 고양이·개(위키: anthropomorphic cats).
- 머리 = 몸 높이의 40~50%(약 2등신) [추정]. 몸 = 어두운 단색 덩어리(검정·남색). 얼굴 = 흰/갈색 면 + 픽셀 점 2~3개(눈 둘, 입 하나). 볼터치·음영 그라데이션 없음.
- 귀여움은 "형태"가 아니라 **그래픽**에서 온다: 어두운 실루엣 + 밝은 머리 + 점 눈. 지터 애니로 "뭔가 이상함"을 섞는다 [개발자].
- 우리에게: 비례(2등신)는 **가져오지 않는다**(도현이 4~5등신 귀여움도 거부). 가져올 것은 "단색 실루엣·점 얼굴·그라데이션 없음·지터".

### 2.11 차 [관찰 + 개발자]
- 혼다 Acty 경트럭 [위키]. 흰 단색 차체 + 픽셀로 그린 문틈·창·번호판. 손픽셀 텍스처 [개발자].
- 미등·전조등만 고채도 발광(안개 속에서 가장 밝은 점). 차체 마모·사진 질감 없음.
- 화면 점유: 02 폭 21%·높이 37%, 06 폭 17% [추정: 확대판에서 눈대중 박스]. 우리 a_car = 폭 26%·높이 29%. 비슷하다.

### 2.12 UI [관찰]
- 돈 팝업(04)·대사(03)는 **내부 해상도 그대로**의 흰 비트맵 고정폭 글꼴 + 어두운 그림자. 세계와 같은 픽셀 크기.
- 아이콘(09 음표)도 같은 격자. HUD 는 거의 없음(미니맵 없음 — similar-games §8).
- 단, 스팀에서 "픽셀이 너무 커서 두통" 불만이 있다 [2차]. 글자 가독성은 우리가 지켜야 할 하한.

## 5. 왜 EDC 의 거친 저해상도는 더럽지 않고 우리 것은 더러운가 (측정 근거)

1. **디테일 크기 대 픽셀 크기.** EDC 표면 무늬는 8~40px 얼룩이 주(중간/저 비 0.35~0.86). 우리는 2~8px 잔무늬가 같거나 더 크다(0.93~1.93). 사람 눈은 픽셀 크기의 무늬를 "얼룩·때"로, 픽셀보다 큰 무늬를 "재질"로 읽는다 [추정: 지각 해석, 수치는 측정].
2. **고립된 반점.** EDC 0~0.2%, 우리 인도·풀 1.2~5.8%. 사진을 32px/m 로 줄이면 자갈·풀잎·얼룩이 각각 1텍셀 점으로 남는다. 그것이 Point 로 화면에 그대로 찍힌다.
3. **점에 색이 섞임.** 1px 색잡음 EDC 0.6~1.2, 우리 풀 2.7. 초록 위 적갈 점 = 보색 점이라 더 지저분하다. 32색 팔레트로 맞추면 가까운 두 색이 아니라 먼 색으로 튀는 점이 생긴다 [추정: retro_clean 6단계 팔레트 맞춤의 부작용].
4. **격자 둘.** EDC 는 화면 격자 하나만 각진다. 우리는 32px/m 텍셀이 Point·밉맵 없음이라, 가까운 땅은 텍셀 2~3px 네모, 먼 땅은 텍셀이 픽셀보다 작아 깜빡이는 잡음이 된다 [추정: 960×540·세로 FOV 72° 가정, 5m 에서 ≈74px/m, 15m 에서 ≈25px/m].
5. **장면이 한 색조로 묶이지 않음.** EDC 는 하늘=안개=앰비언트 무채색이라 모든 면이 한 명도 사다리에 앉는다(채도 0.03). 우리는 파란 하늘·초록 풀·라임 밭·주황 차가 섞여(채도 0.16~0.31, 색 칸 2배) 작은 점이 더 튄다.
6. **Look4 가 반대로 틀린 이유.** 반점은 풀·인도에 그대로 남겼고(오히려 1.2→2.5%, 4.7→5.8%), 큰 면(벽·도로)은 저주파까지 지워 0.0 이 됐다. "점은 남기고 얼룩은 지움" = EDC 와 정확히 거꾸로다. 그래서 더럽기도 하고 그림판이기도 하다.

**처방 한 줄:** 무늬는 지우지 말고 **키운다**(8~40px 얼룩으로), 점은 **없앤다**, 색은 **한 색조로 묶는다**, 거칠기는 **화면 해상도 하나로만** 낸다.

## 6. 결론 — Unity "Look 5 EDC-PS1" 규칙 12개

각 규칙: 수치 / 바꿀 곳. 검사 수치는 `_analysis/regions.py` 방식(내부 해상도 판 기준)으로 잰다.

1. **렌더 해상도 480×270 고정, 최근접 확대.**
   EDC 456×256 에 가장 가까운 16:9 정수배(1080p 4×, 1440p 5.33× 비정수 허용 — EDC 도 4.22×). 화면 크기와 무관하게 고정.
   → `F1/Assets/Scripts/Debug/LowResRenderTest.cs`(targetHeight 270, 이미 있음)를 정식 컴포넌트로 승격. 또는 `Settings/PC_RPAsset.asset` m_RenderScale 0.5→0.25(1080p 만 맞음, 비추천).

2. **세계 표면은 텍셀 네모가 보이지 않게.** 사진 기반 텍스처(지형·벽·도로·바위)는 Bilinear + 밉맵. 내용은 저주파로: 가우시안 σ≈1.5텍셀(32px/m 에서 ≈5cm) 이하 디테일 제거, 대신 0.3~1.5m 크기 얼룩은 남긴다.
   → `tools/asset-gen/retro_clean.py` 에 `edc` 모드(중앙값·팔레트 맞춤 대신 저역 통과 + 대비 축소), `Editor/PitCrewLookMenu.cs` 에 `5 EDC-PS1`(세계 텍스처 filterMode Bilinear·mip on). **D-124 "세계 32px/m 픽셀 질감" 과 충돌 → 도현 확인 필요**(텍셀 밀도 32px/m 저장은 유지, "보이는 네모"만 없앰).

3. **표면 잡음 상한(검사 수치).** 1px 반점 ≤0.3%, 중간/저주파 비 ≤0.6, 1px 색잡음 ≤1.0. 단 **평평 금지**: 저주파(8~40px) std 3~10.
   → `tools/qa/surface_noise.py` 신설(이 문서 `_analysis/regions.py` 를 옮김), 캐처 폴더마다 표 출력. Look4 의 단색 벽(0.48)·도로(0.00)는 이 하한으로 걸린다.

4. **장면 색: 한 색조 + 작은 고채도.** 화면 채도 평균 0.08~0.15(EDC 낮 0.03 은 눈 때문이라 우리는 조금 높게), cover90 색 칸 ≤20(밀집 마을 ≤35). 고채도(채도 >0.5)는 간판·자판기·화분·차 발광·화물 등 사람 물건만, 합쳐서 화면 ≤5%. 라임 밭·원색 초록 금지.
   → 텍스처 팔레트: `retro_clean.py` 공용 팔레트를 시간대 색조로 당기는 단계(채도 ×0.6) 추가. 밭 재질 `BuildBayLoop.cs` Fields() 색.

5. **하늘 = 안개 = 앰비언트(한 색).** 하늘 꼭대기와 지평선 차이 ΔRGB ≤15. 휘도 p5~p95 폭 ≤110.
   → `Editor/MoodSwitcher.cs` BuildDayProfiles: 하늘(스카이박스/카메라 배경)을 fogColor 에 묶는다. 이미 ambient = fogColor×0.7(172행) — 하늘만 따로 노는 것을 막으면 된다.
