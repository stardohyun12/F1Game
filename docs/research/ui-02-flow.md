## 1. 조사 범위와 사실 구분

`docs/qa/evidence/20261023-*.png` 31장을 연락 시트로 훑고, 주문판/전화·포장·주행·정산 대표 원본을 확대 확인했다. [전체 연락 시트](../../art/_review/2026-10-23-ui-flow/audit-all.jpg). 이름에 `board`가 있어도 포장 화면인 파일이 있어 내용으로 분류했다. **이 날짜의 주문판 캡처는 전화가 가린 상태여서, 가려진 카드 전체의 위계·줄바꿈은 [미확인].**

**현행 재현과 변경 제안을 구분한다.** 앞의 표는 제안 와이어프레임이다. 전화 분기·선택 갱신·포장 안의 적재는 현행에서 가져왔다. `Result → Return`과 준비 중 시간 초과 즉시 정산은 새 제안이다. 코드 수정은 하지 않았다.

예외·구현 인계:

- 0초가 되면 보드/전화/포장/주행 어디서든 동일한 ‘시간 초과’ 정산으로 한 번만 진입하는 안. 현재 ‘포장에서 계속 작업 → 출발 즉시 실패’를 바꾸므로 PD 판단 필요. 중간 대화·새 확인 창을 더하지 않는다.
- 기존 `DeliveryManager.Returning`의 **정산 전** 복귀를 신규 단계와 중복 적용하지 않는다. 마지막 배달 성공 시 정산 확정 → 신규 Return은 보상·배달 판정·카운트다운을 멈춘 채 운전만 재개하는 구조를 프로그래밍팀에 요청.
- 실패도 같은 귀로를 제공하는 안. 차량 조작 불가(펑크 등) 때의 복구/차고 이동 방식은 PD·프로그래밍 결정 필요 [미확인]. 실패에 없는 성공 보상을 표시하지 않는다.
- 복귀 중 새 긴급전화·화물 손상 경고·돈 카운트업을 띄우지 않는 안. 차고 도착 시에만 ‘다음 주문 / 차고’를 보여주고 새 주문 선택 시 다음 시계를 시작한다.
- RoutePlanScreen은 코드상 조건부 경로로 남아 있다. 이번 6단계안은 사용자 지정 흐름을 따른다. 향후 활성화한다면 주문판의 경로 상세로 합칠지 별도 단계로 둘지 PD 확인 필요.

사각형 점유율 = 묶음별 글자·선 경계 사각형 합집합 / 960×540. 투명 여백 포함. 잉크 픽셀 = alpha>0인 실제 UI 픽셀 / 화면. 기존 캡처의 17.0%와 목업은 상태·표시 항목이 달라 읽기 성능 향상률로 해석하면 안 된다. [좌표·측정 JSON](../../art/_review/2026-10-23-ui-flow/mockups.json).

1/3의 임시 예산 ‘갈 때 ≤8%, 돌아올 때 ≤3%’를 적용했다. 중앙 60%×60% = **x192~767, y108~431**에는 4장 모두 HUD 픽셀 0개. 목적지 좌상·시계 우상·화물 좌하·속도 우하 고정, 화면 중앙 화살표·상시 트렁크 창을 없앤 제안이다. 상시 트렁크 축소는 PD 승인 대상으로 남긴다.

`직선 240m`는 남은 도로 경로 길이가 아니다. 현재 `CurrentTarget` 위치로 만들 수 있는 직선 정보의 **가상 예시**다. 경로 길이 공급 API는 이번 조사에서 확인하지 못했으므로 ‘남은 거리’로 둔갑시키지 않았다. 최장 목적지명은 위치를 유지한 채 두 줄로 처리하고 24px 아래 자동 축소하지 않는 안. 데이터가 없으면 거리를 숨기고 목적지명만 유지한다.

F1 속도감은 HUD 숫자를 크게 만드는 방식 대신 D-126의 근경 통과·낮은 시점·카메라·엔진/바람 소리에서 낸다. 이번은 UI 비교를 위해 기존 카메라 배경을 유지했다. **정지 목업만으로 속도감·주행 중 시선 복귀·경고 인지를 검증하지 못했다.** 무음에서도 경고는 단어와 모양으로 남긴다. 5Hz 반복 점멸 대신 상태 진입 1회 강조를 제안하되 애니메이션·소리를 제작하거나 시험하지 않았다.

## 5. 글자·색·정수배 적용

선행 조사에서 확인한 [Galmuri 원문](https://github.com/quiple/galmuri), [폰트 안내](https://quiple.dev/font/galmuri), [Pretendard 원문](https://github.com/orioncactus/pretendard)을 따른다. TTF는 Galmuri 1/3 자료와 저장소의 Pretendard 파일을 읽어 사용했고 OFL을 검토 폴더에 동봉했다. 폰트 파일은 수정하지 않았다.

- Galmuri11은 **12px 원형 em**을 단색 마스크로 렌더 → Nearest 2×(24), 숫자 3×(36). Pretendard 비교는 12/18px 단색 마스크 → 2×(24/36); SDF 런타임 품질의 재현이 아니다.
- 실제 폰트로 모든 한글·숫자를 그렸다. 가짜 글자·합성 굵기·기울임·랜덤 노이즈·그라데이션을 넣지 않았다. 픽셀 폰트 마스크에 2px 오른쪽 아래 잉크 그림자. Pretendard의 작은 단색 마스크가 잘 읽히는지는 사용자 가독성 검토 필요.
- 게임 화면 960×540 → 1920×1080은 2×, 2880×1620은 3×. 2560×1440은 2⅔×이므로 Point만으로 동일한 픽셀 폭이 되지 않는다. 정수배 레터박스 또는 별도 출력 정책 필요; 승인된 구현으로 취급하지 않는다.
- 현재 Overlay 1920 Canvas와 연결할 방식(TMP bitmap/SDF, 캔버스 기준 변경)은 프로그래밍 담당. ‘fontSize 숫자를 절반으로 바꿈’만으로 완료할 수 없다. [Unity CanvasScaler 원문](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/script-CanvasScaler.html).
- 정지 화면의 긴 본문에만 Pretendard를 허용하는 D-123을 기본으로 삼는다. HUD는 A안 Galmuri 우선; B안은 가독성 비교 시료이며 전면 채택은 도현 승인 필요.

| D-123 색 | 역할 |
|---|---|
| label `#E4D6BF` | 바랜 종이·주행의 흰 글자 역할 |
| ink `#30362F`, scene_06 `#231F1B` | 종이 위 글자·얇은 선 / 주행 글자 그림자 |
| scene_18 `#677B80` | 바랜 청록 보조 역할, 중요한 작은 글자의 단독 저대비 색으로 쓰지 않음 |
| carton_light `#B89360` | 시간·주의의 작은 표식 |
| stamp `#8A4631` | 긴급·정산 도장용 잉크 |

**UI 오버레이 색은 공용 32색 안에 있음.** 배경 캡처는 실제 게임 조명 색을 유지했으므로 최종 합성 전체가 32색이라는 뜻은 아니다. 멈춘 화면은 이번 단계에서 구조 와이어프레임만 제작했다. 실제 스캔 종이·마모 텍스처, 도장 스프라이트는 아직 제작하지 않았다.

## 6. UI 슬롯 제작 인계 — 크기와 9-slice 초안

**이번에 만든 게임용 스프라이트는 0개.** 다음 표는 슬롯을 빠뜨리지 않기 위한 제작 초안이며 엔진 확정값이 아니다. 원본 크기와 여백은 소스 texel, 순서 L/B/R/T. 소스→960 논리 화면은 2×를 기본으로 검토; 크기가 늘어나는 패널은 모서리 보존·가운데만 늘림. 텍스트는 별도 TMP이며 그림에 굽지 않는다.

| 소유 / 슬롯 | 원본 px | 9-slice 여백 L/B/R/T | 사용 제안 |
|---|---:|---|---|
| UITheme.paperPanel | 128×128 | 8/8/8/8 | 전화·영수증 큰 종이. 원본색·흰 틴트 계약 확인. |
| UITheme.paperCard | 128×64 | 6/6/6/6 | 주문 전표. 직각, 얇은 선. |
| UITheme.slipHeader | 128×16 | 4/0/4/0 | 얇은 머리선. 상태 틴트용 마스크. |
| UITheme.stampRing | 64×64 | 0/0/0/0 (Simple) | 도장 비율 고정. 별도 글자. |
| UITheme.buttonPlate | 128×32 | 6/6/6/6 | 정지 화면 버튼. 튀어나온 만화 외곽 없음. |
| UITheme.enamelPlate | 128×32 | 4/4/4/4 | 유지 슬롯. 기본 주행에 큰 판을 깔지 않음. 필요 시 요청 상세. |
| UITheme.gaugeFill | 64×8 | 2/2/2/2 | 단순 상태선, 틴트·폭 변화 계약 확인. |
| PackingScreen.stampSprite | 128×128 | 0/0/0/0 (Simple) | 정사각 도장. 현행 코드가 흰 틴트, 등급 글자는 별도. |
| PackingScreen.gaugeTrackSprite | 128×16 | 4/4/4/4 | 얇은 면별 보호 트랙. |
| PackingScreen.gaugeFillSprite | 128×16 | 4/4/4/4 | 흰 마스크·재료색 틴트. 현행 anchorMax 폭 축소이며 Filled 방식 아님. |

게이지 0%는 숨기고 극소 폭에서 양쪽 border 합보다 작아질 때 왜곡을 확인해야 한다. 패널 최소 크기·Pixels Per Unit·Sprite pixels per unit multiplier·Canvas 실제 scale은 QA/프로그래밍과 맞춰야 한다. 이 검토 PNG를 `F1/Assets/`로 그대로 임포트하지 않는다.

## 7. 검증과 승인

재생성: `py art/_review/2026-10-23-ui-flow/build.py` → `py art/_review/2026-10-23-ui-flow/verify.py`.

검증 파일: [validation.json](../../art/_review/2026-10-23-ui-flow/validation.json), [브라우저 상단 미리보기](../../art/_review/2026-10-23-ui-flow/preview-top.png), [HUD 섹션 미리보기](../../art/_review/2026-10-23-ui-flow/preview-hud.png). Windows headless에서 긴 페이지의 깊은 스크롤 캡처가 빈 화면으로 나와, HUD 섹션은 같은 HTML/CSS를 검증용 페이지 맨 위에 배치해 촬영했다. 완성 보드의 이미지 로딩·문서 폭은 전체 페이지로 따로 검사했다.

- 제작·정적 확인: 주석 5장(각 4/4/5/5/4개), 와이어프레임 6장과 정보 3개씩, HUD 4장 960×540, 투명 HUD 색·중앙 비움·화면 경계·2×/3× 왕복 일치, 로컬 링크·폰트·이미지 로딩.
- 육안 검토: 원본 캡처·주석·HUD·와이어프레임·HTML 렌더를 확인. 독립된 외부 눈 그래픽 게이트는 미실행이며 자체 점수를 승인으로 대신하지 않는다.
- 미실행: Unity 임포트/Play, 키 입력·시간 초과·결과 지급/복귀 전이, 긴 한글 실제 읽기, 주행 중 인지·음향·F1 속도감, 실제 해안 귀로 장면. **QA/프로그래밍 임포트 필요.**
- **도현 승인 필요:** A 우선 HUD 위계, B 가독성 비교의 허용 범위, 상시 트렁크 축소, 종이 화면 구조, 정산 뒤 귀로. PD 확인 필요: 준비 중 0초 처리·가득 찬 긴급 주문 교체·실패 복귀 정책.
- 승인 뒤: UI 조사 3/3에서 슬롯·텍스트 규격 확정 → 폰트/종이 원화 승인 → 제작 → 미리보기 승인 → 프로그래밍 적용·QA. 이번 작업은 `F1/Assets/` 변경·3D 제작·commit/push 없이 마무리.
