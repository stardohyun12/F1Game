## 🔧 하네스 (작업 검증 체계) 문서

"하네스"는 작업을 제대로 하고 있는지 잡아주는 체계야. 규칙 + 자동 점검 도구 + 헛짚은 기록.

### 영구 규칙 (항상 지키는 것)
- [세션 프로토콜](../project_rules/session.md) — 세션 시작/종료 절차, 검증 3종, 검증 서브에이전트.
- [타협 금지](../project_rules/no-compromise.md) — fix는 검증까지 끝나야 완료, 표층 fix 금지 등.
- [자산/맵 배치 규칙](../project_rules/asset.md) — 타일·프리팹·맵 배치할 때 지키는 것.
- [스코프 관리](../project_rules/scope.md) — MVP 범위·재미 검증·추가 제안 체크리스트.
- [커뮤니케이션](../project_rules/communication.md) — 응답 톤·도현 프로필.
- [거절된 아이디어](../project_rules/REJECTED_IDEAS.md) — F1 프로젝트 한정으로 안 쓰기로 한 것들.

### 자동 점검 도구
- [회귀 점검 코드](../F1/Assets/Editor/_Recovery/HarnessChecks.cs) — 실제로 겪은 버그를 자동으로 다시 단언(재발 방지).
- [회귀 점검 스크립트](../scripts/regression-check.sh) — 위 점검을 돌리는 스크립트(폴리수 예산 포함).

### 헛짚음 기록 & 패턴
- [범용 AI 약점 패턴](../옵시디언/하네스/patterns/) — AI가 자주 놓치는 10가지 + 성공 사례.
- [헛짚음 기록(incidents)](../옵시디언/하네스/incidents.md) — 실제로 틀린 것들 4줄 블록.
- [초안 규칙(draft-rules)](../옵시디언/하네스/draft-rules.md) — 발효 전 규칙 후보.
- [하네스 사용 로그](../옵시디언/창업/harness-usage-log.md) — 세션마다 하네스가 도움 됐는지 한 블록.

## 🤝 팀 운영 (AionUi 팀 모드, 2026-10-18~)

도현이 지휘하고 총괄 PD · 기획 · 아트 · 프로그래밍 · QA 팀원이 나눠 일하는 체계. 기존 역할 분리 모델(roles.md)을 실제 분리된 팀원으로 수행한다.

- [팀 운영 규약](../PIPELINE.md) — 역할 매핑 · 산출물 위치 · 게이트 · 에디터 토큰 · 모델링 파이프라인. 어시스턴트 규칙보다 우선.
- [Codex 팀원 안내](../AGENTS.md) — Codex로 돌아가는 팀원이 읽는 짧은 진입점.
- [역할 분리 모델](../project_rules/roles.md) — 원래의 세 역할과 AionUi 매핑.
- [게이트 판정·버그](qa/) — 기획·그래픽·QA 게이트 결과와 버그 리포트.
- [모델 소스](../art/models/) — 아트팀이 만드는 3D 모델의 생성 스크립트·스펙.
- 어시스턴트 생성 방법은 별도 저장소 [GameStudio](https://github.com/stardohyun12/GameStudio) `setup/SETUP.md`.
