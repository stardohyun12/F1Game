## 0. 한눈에 — 평일 하루 = 배달 한 바퀴

```
 [방]  ->  [정비소]  ->  [작업대]  ->  [카트]  ->  [길]  ->  [문 앞]  ->  [돌아오는 길]  ->  [저녁 방]
 아침     주문 받기      포장         싣기      운전     건네기       노을 해소          일기
          물건 받기                                     (x 2~3건 반복)
```

- 하루에 2~3건 **[가설]**. 1건은 약 4~5분, 하루는 약 15분이다 **[가설]**. 운전 40~90초는 PLAY.md 의 목표값이다.
- 28일 = 평일 20일 + 주말 8일. 평일에 3건씩이면 **방학 동안 60번 포장한다.** 이 숫자가 포장 설계의 제일 큰 조건이다. 60번째에도 지루하지 않아야 한다.
- 이야기는 **물건 하나가 세 번 말하게** 짠다: 포장할 때 보낸 사람의 쪽지 → 건넬 때 받는 사람의 반응 → 밤에 일기 한 줄. **[가설]**

## 2. 포장 다시 기획

### 2-1. 목업 A·B 가 왜 별로였을까 — 가설 3개

도현 원문:
- D-237: "지금 ui는게임과 전혀 안어울림"
- D-240: "4.이건 좀따로 자세히 이야기 해야할듯 둘다별로라서"
- D-243: "택배 포장하는것도 아직 잘 안되어 있으니까"

목업 내용 [확인 `docs/team/reports/programmer-20261101-0429.md:39-41`]: 바탕은 회색 primitive 작업대였다(상자, 신문지 구김, 뽁뽁이 덩어리, 라벨, 선반, 합판 벽). A 는 화면 UI 0 + 주황 집게 커서, B 는 위 가운데에 "바닥 깔기 · 넣기 · 채우기 · 닫기 · 라벨" 단계 글자였다.

| # | 가설 | 근거 |
|---|---|---|
| 1 | **UI 문제가 아니라 "무엇을 하나"가 비어 있었다.** A·B 는 같은 정지 컷에 글자를 얹었냐 뺐냐의 차이뿐이었다. 손으로 무엇을 어떻게 하는지는 한 장으로 안 보인다 | 도현이 "따로 자세히 이야기"라고 했다. 주행·걷기·대화는 그 자리에서 골랐는데 포장만 미뤘다 |
| 2 | **물건도 사람도 없었다.** 상자와 완충재만 있고 "누가 누구에게 무엇을"이 안 보였다. STORY 의 "알아가는 이야기"와 끊겨 있다 | 회색 대역 작업대였다. PACKING-UI §3-1 "물건이 이야기다"가 목업에 안 들어갔다 |
| 3 | **손이 아니라 커서와 체크리스트였다.** 집게 커서(A)와 단계 목록(B)은 둘 다 "도구로 화면을 조작하는" 문법이다. 1인칭 작업대인데 내 손이 없다 | 거부된 옛 포장 화면도 관리·비용 표였다(PACKING-UI §1). B 가 체크리스트처럼 읽힐 위험은 programmer 보고서 이유 3 에 이미 적혀 있었다 |

### 2-2. 서로 다른 포장 방식 3안

참고한 것 [확인, 이번 세션에 원문을 열었다]:
- Unpacking: 개발자 Tim Dawson "Through handling items players are forced to consider each one". 팀은 물건으로 사람을 짐작하는 것을 "empathy through detective work"라고 불렀다 — [Game Developer GDC 2022 정리](https://www.gamedeveloper.com/gdc2022/gdc-2022-unpacking-a-narrative-through-1-000-household-items)
- Wanderstop(차 만들기): 밧줄 당기기, 풀무, 밸브 차기 같은 몸 동작 단계가 있다. 손님은 "will wait for as long as it takes", 실수해도 벌 없이 다시 한다. 반면 리뷰에서 "became monotonous"(Paste), "could feel tedious"(Push Square) — [Wikipedia 요약](https://en.wikipedia.org/wiki/Wanderstop) (2차 요약. 개발자 인터뷰 원문 Escapist 는 403 으로 못 열었다)
- Strange Horticulture: Rob Donkin "every time someone visits your shop, they need a reason for doing so", 냄새·촉감을 보는 "closer inspection" 도구 — [Game Developer 인터뷰](https://www.gamedeveloper.com/design/strange-horticulture---bad-viking)

| | 안 1 「손으로 싼다」 실물 조작 | 안 2 「세 동작」 짧은 손놀림 | 안 3 「물건과 쪽지」 이야기 중심 |
|---|---|---|---|
| 한 줄 | 물건, 완충재, 상자를 하나하나 손으로 집어 놓는다. 물리 그대로 | 화물마다 정해진 3동작(깔기 → 넣기 → 묶기)을 손 제스처 한 번씩으로 | 포장은 고르기 2번(상자, 완충재). 시간은 물건을 돌려 보고 쪽지를 읽는 데 쓴다 |
| 가까운 참고 | Unpacking(손으로 다루니 하나하나 보게 된다) | Wanderstop 차 기계(몸 동작 단계, 타이머 없음) | Strange Horticulture(살펴보기 도구, 손님이 올 이유), Unpacking(물건으로 사람 짐작) |

### 2-4. 추천 [가설] — 안 3 으로 시작하고, 안 1 의 손 조작을 하나씩 더한다

## 4. 도현에게 물을 것 (답은 1A 2B 처럼)

**질문 1. 주문을 어떻게 알게 될까?**
- A 정비소 칠판(평일) + 벽 전화(급한 건) + 편지(주말·단골) — **추천.** 대가: 칠판·전화·우편함 3곳을 만들어야 한다
- B 사장이 말로만(지금처럼) — 대가: 만들 건 적지만 고르는 맛이 없다
- C 편지·우편함 하나로 — 대가: 글이 매일 필요하다

**질문 2. 포장은 어느 쪽으로?**
- A 손으로 싼다(L) — 대가: 제일 오래 걸리고 물리 버그 위험
- B 세 동작(M) — 대가: 60번 반복하면 단조롭다
- C 물건과 쪽지(M) — 대가: 손맛이 약하다
- D C 로 시작하고 A 의 "집어 돌려 보기·흔들어 보기"를 더한다 — **추천.** 대가: 손맛 판정을 두 번 받는다

**질문 3. 배달 결과(돈·평판)는 어디서 보일까?**
- A 문 앞에서 받는 사람 반응 + 작은 도트 돈 글자, 하루 합계는 일기장에 — **추천.** 대가: 정산창을 없앤다
- B 배달 중에는 0, 일기장에서만 — 대가: 잘 쌌다는 순간의 보상이 늦다(TASTE 3 숙련 증명이 약해진다)
- C 지금 정산창을 도트로만 바꾼다 — 대가: 만들기는 쉽지만 메뉴 문법이 남는다

**질문 4. 화물이 깨졌을 때 이야기는?**
- A 반응과 돈만 달라지고 이야기는 늘 이어진다 — **추천.** 대가: 실패의 무게가 가볍다
- B 깨지면 그 회차 이야기를 못 보고 다음에 다시 — 대가: 긴장이 크지만, 이야기를 놓치면 속상하다(TASTE 5 우울 피하기와 충돌할 수 있다)
- C 깨진 것 자체가 다른 이야기 조각이 된다(받는 사람이 웃어넘김 등) — 대가: 회차마다 글이 두 배
