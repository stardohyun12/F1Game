# 작업 방식 v2 — 한 장 (2026-11-03, D-277)

도현: "지금 작업 멈추고 작업방식 다 정리하고 확실하게 가자". 이 문서가 유일한 기준. 다른 규칙 문서(PIPELINE·FLOW·체크리스트)는 이 장과 어긋나면 이 장이 이김.

## 0. 원칙 세 줄
1. 규칙은 **읽히지 않고 강제된다** (훅·검사·테스트). 글로만 있는 규칙은 없는 규칙.
2. 세계의 진실은 **한 곳**(세계 스냅숏 + 불변 조건). 팀원은 코드만 보고 고치지 않는다.
3. 도현은 **방향·플레이 판정·취향**만. 나머지는 PD 가 정하고 끝까지 간다. 묻는 건 2지선다 하나.

## 1. 단위 = 카드 (docs/team/cards/)
- 카드 1장 = 기능 1개 = 수용 기준 3줄("도현이 ○○ 하면 △△가 보인다").
- 단계: 기획 → 그레이박스 → 검증(블라인드) → **도현 한 판** → (아트) → 통합 → 검증 → 완료.
- 일꾼 5: PD · 구현 · 검증 · 아트 · 리서치. 일꾼마다 카드 1장, 동시 진행 3장.
- 3회 불통과 → 멈춤 → 도현 2지선다. (C-002·C-003 이 지금 여기.)
- 아트·리서치·도구는 카드에 묶여서만 생긴다.

## 2. 팀원이 일하는 방식 (Claude Code)
- 시작 때 읽는 것: **브리프 한 장**(카드 + 세계 스냅숏 + 범위 파일 지도). 규칙 문서 전부 읽기 금지 → 7만 자 → 1만 자.
- 같은 카드 안 과제는 세션 이어감(resume). 카드 바뀌면 새 세션.
- 훅이 막는 것: 봇 전체 경로 · 기다리는 검사(sleep/until) · 잠근 파일(ProjectSettings·.mat·.unity·.prefab·차 조작) · 토큰 없는 Play.
- 확인 = 디버그 창 순간이동 + 캡처 1~2장 + "이 변경이 안 됐으면 실패할 검사 1개". 봇 한 바퀴는 PD 가 카드 여러 장 끝에 1회.
- 끝날 때 자동: 컴파일 0 에러 · 불변 조건 검사(위반이면 커밋 안 됨) · 증거 묶음(클립·strip·전후).
- 시간 상자는 상한. 끝나면 바로 마무리.

## 3. 세계 모델 (docs/world/)

- `WorldInvariants` 불변 조건: 지금 10개. 버그가 나오면 **고치고 + 조건 1개 추가**(같은 버그 재발 금지). 조건이 곧 팀의 기억.
- 다음 층: 게임 규칙(배달 단계·돈·파손)을 Unity 밖 순수 C# + 테스트로 → 에디터 없이 1초 검사.
- 그다음: 빌드된 게임에서 검증·봇 → 에디터는 구현 전용(병목 해소).
