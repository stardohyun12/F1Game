## 검증한 것

- GLB 원본 검사 **19/19 PASS**, 별도 임시 폴더 FBX 재임포트 **19/19 PASS**: 실제 삼각형·치수·피벗·양축 텍셀밀도·POT·팔레트 밖0·주요 면 단색0·임베디드 알베도·원본 SHA·출처 장부.
- 기존 `check_asset.py` 계열의 `check_buildings.py` 검사를 재사용한 `check_props2.py`; 이전 소품800tris 정책 2항목만 D141≤1500으로 명시 교체. 검사를 끄지 않았다. `check_props2_fbx.py`는 Blender 실제 GLB/FBX 위치·치수·텍스처 일치를 대조한다. SPEC-checker.md 및 GLB/FBX JSON 참조.
- 32색 검사는 **조명 전 원본 albedo** 기준. 최종 렌더의 조명·AA 색수와 별개. Point 설정은 GLB에서 확인; Unity 텍스처 임포터는 미확인.
- 실제 Blender geometry-only 19종 두 번 생성, geometry/UV/recipe 해시 일치. seed7/8로 탈것·표지 4종 UV 색 선택 변경, tris 동일: `repro-check.json`.
- 새 리뷰어가 의도·이전 점수 없이 PNG만 판정. 예 AND 7점 이상만 투입. 전체 격자·실거리 톤 [별도 판정](../../../art/_review/2026-10-25-bayloop-props2/release-visual-gate.md) 예 8점. 거리에서는 회색 스쿠터·작은 표지·카페 세트 명도 분리가 추가 개선점.
- 원본 파일과 검증 SHA 대조 후 20개 새 파일 복사. handoff 전후 기존338개 바이트 보존. 세션 중 해시 변경이 관찰된 기존 .mat 11개는 복원·덮어쓰기하지 않았다(변경 주체 미확인, 경로는 delivery.json). 이번 생성기/납품은 기존 .mat를 쓰지 않는다.

## 참고·재현·변경

- [Poly Haven Simple Prop Workflow](https://blog.polyhaven.com/simple-prop-workflow/)의 비례 블로킹→구조 확인→사진 표면→검사 순서를 적용. 저자의 원본 모델을 재현했다고 주장하지 않는다. 기존 bicycle 실파일로 검사 계약을 먼저 재현했고, 기존 건물의 metric UV/사진 아틀라스를 재사용했다.
- 차량 비례는 공식 제원 참고(SPEC-vehicles.md). 실존 로고·상표 없음. 기존 bicycle은 재제작하지 않았고 선택 소품은 mailbox_cluster.
- 새 CC0 사진: [asphalt_02](https://polyhaven.com/a/asphalt_02), [rough_linen](https://polyhaven.com/a/rough_linen); 기존 CC0 painted metal/wood/stone 재사용. 공식 API 직접 다운로드·실물 크기 BOX 축소·공용 팔레트 양자화. URL·라이선스·가공·SHA를 `art/provenance.csv`, `*-source.json`에 기록. AI 이미지·모델·검토 배경 생성 0.
- 도로 사진은 보수면만90도 회전·위상 이동해 바탕 무늬 연속을 줄임. 횡단보도 관통 틈을 없애고 측면 칩으로 변경. 정보 기호는 직접 만든 geometry이며 가짜 글자 없음.
- 파라솔은 사진을8bit로 먼저 축소할 때 밝기가 한 값으로 붕괴해 기술 검사 실패. float 밝기 BOX 축소 후 strict median 양자화로 실제 사진 변화 보존, 재검사·새 렌더 독립 판정 수행. 랜덤 노이즈 추가 없음.
- 현재 공유1024² 아틀라스는6장. 이미 검토한 다른 소품을 바꾸지 않도록 수정본을 분리했다. 통합 최적화는 미실시. 각 FBX→PNG 연결은 manifest/납품 목록 기준; 동일한 재질명만으로 일괄 연결하면 안 된다.
