**렌더 — `tools/map/render_plan.py`**
- 출력 파일을 v3 이름으로 바꿨다.
- `features` 기호를 그린다: 점프 = 주황 삼각, 좁은 틈 = 두 줄, 표지 = 보라 마름모.
- `rhythm` 겹침을 그린다: 속도 = 파랑, 기술 = 빨강, 탁 트인 길 = 하늘색 띠, 100 m+ 직선 = 양 끝 꺾쇠.
- 리듬 전용 범례를 더하고 `rhythm-v3.png` 를 출력한다.

## 3. 검증 증거

- 위 명령을 실제로 돌렸다. 결과:
  - v3 는 **FAIL 0**, WARN 3(R9 쌍 시간비)이다.
  - v2 json 에 같은 검사기를 돌리면 FAIL 14 다. R1 48%, R2 164 m, R3 16 m, R4 320 m 로 리서치 §5 의 v2 값과 같다. 주기만 8초로 §5 의 6초와 다른데, 가속 모형 값이 달라서다.
- make_plan 출력: 길 24, 필지 297, 전봇대 55, 교차로 39(차길 T 18).
- 옛 규칙도 다 통과한다:
  - 필지: 못 닿는 0, 길을 덮는 0, 바다에 걸친 0, 경계 밖 0
  - 이유 없는 길 끝 0
  - 경사: 본선 ≤12%, 지름길 ≤16%
  - 반경: 최소 10.1 m (슬라이스 헤어핀)
  - 엇갈림 높이차 위반 0
- 렌더는 2회 했다. 두 번째는 구간 이름만 바꾼 것이다.
- **그림을 직접 열어 보고 판정했다: 「속도 낼 곳·탁 트인 구간이 그림에서 한눈에 보이는가」 — 예.**
  - 서쪽 해안을 따라 굵은 파랑 + 하늘색 띠가 이어지고 「직선 240m」 꺾쇠가 붙어 있다. 지도에서 가장 눈에 띄는 선이다.
  - 북쪽 문 앞 내리막도 하늘색이다.
  - 항구 직선은 보이지만 표지 글자와 겹친다.
- Unity 에디터·플레이로는 검증하지 않았다. 85 km/h 모형 값일 뿐 실제 주행이 아니다.

## 4. 남은 결함 / QA 체크리스트

**남은 결함 (가설 포함)**
1. **4→MART 쌍:** 빠른/순한 시간비가 0.93 이다.
   - 85 km/h 에서는 해안 본선(넓은 굽이와 직선)이 옛길만큼 빠르다. 옛길이 '지름길' 노릇을 거의 못 한다.
   - 그래도 고를 이유는 남는다: 옛길은 내리막 직선과 좁은 틈이 있고, 본선은 경치가 좋고 순하다.
   - 시간 차를 키우려면 둘 중 하나: 곶을 더 바깥으로 내서 본선을 늘리거나, 옛길을 더 곧게.
2. **2→3 쌍(0.96):** 3번 배달지가 곶 가로길로 옮겨 가서 대안 경로가 거의 같다. 1→2 는 0.82 로 경계선이다.
3. **본선 1495 m:** 상한(1500)에 바짝 붙었다. 더 늘릴 여지가 없다.
4. **② 문 앞 내리막 직선:** 100 m 미만이다. 직선 판정 구간이 60~64 m. 「바다가 열린다」 성격은 하늘색 띠로만 산다.
5. **본선 깎기/메우기 최대 8.4 m:** v2 의 10.6 m 보다 줄었다.
6. **③ 비탈 마을의 배달지:** 위 다리 집이 빠져서 ③ 에는 배달지가 없다(3번은 ④ 곶 마을로 갔다).
7. **그림:** 항구 직선 위 「직선 104m」 글자가 크레인·종탑 표지 글자와 겹친다. 섹션 시트 4→MART 패널 제목이 잘린다(v2 부터 있던 결함).
