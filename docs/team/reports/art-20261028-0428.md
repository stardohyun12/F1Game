- `tools/asset-gen/delight.py`: 사진 4점 원근 보정 → linear sRGB 저주파 나누기·평균색 복원 → 재료 명도 순서 → 32px/m → 결정적 팔레트. 합성 노이즈·AI·빛 굽기 없음.
- `art/export/kit-shared-v1/`: wall.png, trim.png, floor.png, roof.png, decals.png(알파), palette.gpl, layout.json, APPLY.md, provenance.csv, validation.json. 5장 모두 512².
- `art/_review/2026-10-28-kit-shared-v1/sheet.png`, index.html: 제공 게임 왼쪽 칸과 시험 집, atlas 5장, 건축 크롭과 수치.
- `art/source/kit-shared-v1/`: 사진별 4점/치수 jobs.json, material-records.json, make_kit.py, verify.py, proof.py, package.py. 시험 집 proof.blend·proof.fbx는 검증용 원본이며 게임 투입물 아님.

팔레트는 garage 기반 40색을 보존하고 재료별 명도 칸을 추가한 135색. 회벽 결 ±3%, 기타 재료 ±4%, 디더 없음. 새 건물마다 다시 그리지 않고 이 PNG만 참조하도록 APPLY.md에 슬롯·UV·재사용 규칙을 적었다.

## 조사 → 적용

- [Thiago Klafke 제작 사례](https://www.thiagoklafke.com/tutorials/modular-environments/): 타일 벽·트림·바닥을 적은 수로 공유하는 구조를 채택. UDK/3ds Max 프로젝트 자체 재현은 하지 않고 Blender UV 조립으로 적용했다.
- [ShaderMap albedo 제작](https://shadermap.com/tutorials/creating-an-albedo-map-from-a-photographic-texture/): 사진의 조명 제거 뒤 재료 밝기를 맞추는 순서를 채택. 그 프로그램을 실행한 것은 아니다.
- [Physically Based 원본 데이터](https://raw.githubusercontent.com/AntonPalmqvist/physically-based-api/main/deploy/v2/materials.json): 값이 **srgb-linear**임을 확인. 아스팔트·벽돌·콘크리트 순서를 테스트했고, 색의 절대값을 사진 sRGB에 그대로 곱하지 않았다. 회벽=콘크리트 계열 목표는 우리 스타일 가정이다.
- Blender Mango 글은 이번 웹 접근이 402로 실패, 내부 조사에 기록된 저주파 보정 설명을 참고했다. 원문을 새로 확인했다고 주장하지 않는다.
- [Embark 원본 README](https://raw.githubusercontent.com/EmbarkStudios/texture-synthesis/main/README.md)는 비신경망·seed/타일 지원을 확인했지만 프로그램은 실행하지 않았다. 이번 다른 크롭/UV 오프셋을 Embark 합성의 재현으로 부르지 않는다.

원본 사진은 PICKS/SOURCES에 이미 CC0 검증된 도현 선택과 보관 중인 ambientCG 재료. 크롭·보정·출처·원본 SHA256을 보존했다. 저주파 제거는 사진 조명의 완전한 역산이 아니므로, 그림자·케이블·창·큰 얼룩 없는 부분을 먼저 잘랐다. A2 벗겨진 칠은 벽 전체에 섞지 않고 별도 국소 데칼 마스크로 추출했다.

## 검증 · 현재 상태

32px/m를 유지하려면 atlas 전체 Repeat가 아니라 지정 칸 안에서 반복해야 한다. 타일 칸은 8×8m, 트림 U 길이 16m, V 폭은 띠마다 다르다. Point/무 mipmap 조건이며 그 외 필터에는 gutter/array 작업이 필요하다. UI 슬롯 작업은 해당 없음.

실행한 검사: 512² 크기, GPL 포함색만 사용, 모든 타일 U/V 경계 및 트림 U 경계 동일, import 함수 vs 실제 delight.py CLI 결과 PNG 바이트 동일, 잘못된 네 점 입력 거절, linear 밝기 순서. 1px 고립점은 첫 출력에서 0.3%를 넘어 주변의 실제 사진색으로 제거하는 고정 단계를 추가했다. 최종 값은 validation.json.

시험 집은 기하 6×5×7m, 창 4·문 1·처마·간판. 기본 표면·트림은 32px/m. 작은 포스터·번지 데칼은 기존 작은 소품 규칙인 64px/m를 사용해 APPLY에 명시했다. 해 1 + 하늘 주변광 근사, EEVEE, 1600×900 → 1280×720 Nearest. 주변광을 보완하는 렌더 전용 재질 혼합은 proof FBX/PNG에 저장하지 않았다. 실제 Unity 조명 검증은 하지 않았다.

1차 독립 리뷰: **아니오 / 5.5점**. 벽 잔얼룩이 고르게 깔려 흐림, 창틀 대비 약함, 상자 실루엣 단조로움. 회벽 결을 ±3%로 낮추고 창틀 청록 대비·처마 두께·사진 기반 국소 모서리 데칼을 수정했다. 상자 집은 과제의 시험 형태라 유지했다. 최종 재검토 대기.

수치 범위는 PD가 숫자를 지정하지 않아 **단색 면 ±5%p, 면 변화 ±20%**를 작업 전 제안했고 아직 답을 받지 못했다. 임시 기준임을 표시하며 최종 승인 기준으로 확정했다고 주장하지 않는다. 아래 빈칸·밝기 폭은 PD 결정대로 제외했다. 전체 화면 수치는 배경 비중이 달라 참고로만, 건축 영역 크롭은 좌표를 미리 고정해 비교한다. 두 크롭을 같은 표시 크기로 놓았지만 실제 Unity 카메라/월드 축척 일치 검증은 아니다.
