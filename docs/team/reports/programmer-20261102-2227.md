# 프로그래머 보고 — 주행감 B 반 페달 오르막 정지 (문제 1)

자체 점수: 해당 없음(주행 수치 과제, 그림 없음). **고쳤다** — 반 페달 봇 막힘 33→7곳, 찻집 운전 254→135초. 달걀 %는 안 좋아졌다(21→14).

## 1. 한 것
원인(실측): 상자 45kg 을 실은 B 에서 **페달 0.5 로는 평지에서도 0 m**. 엔진 힘(0.5×6.9×짐 0.79×저속 0.85 ≈ 2.4 m/s²)이 바닥 마찰(역산 ≈ 2.6 m/s²)과 같아서 순가속이 0 — 오르막만의 문제가 아니었다. 가설: 마찰은 CarLowFriction(0.15) × 바닥 재질 Maximum 결합 때문(재질 값은 직접 안 재봄 — 위 2.6 은 풀 페달 0→40 시간에서 거꾸로 맞춘 값).

해법: 페달을 밟는 동안 **마찰+비탈 몫을 (1−페달) 만큼 되돌려 준다** → 순가속 = 페달 × (풀 페달 순가속). t=1 이면 보정 0 이라 **풀 페달 느낌은 그대로**, 반 페달은 반만큼 나간다. 힘 제한(최고속·핸드브레이크·드리프트)은 기존 분기 안에서 그대로 걸린다.
- `F1/Assets/Scripts/ArcadeCarController.cs:118,120` — `rollAssist`(m/s²)·`slopeAssist`(0~1) 직렬화 필드(기본 0 = A 는 예전 그대로).
- `ArcadeCarController.cs:150,163` — CaptureFeel/SetFeelPreset 에 두 값 연결.
- `ArcadeCarController.cs:549-555` — ApplyThrottle: `rb.mass × (rollAssist + g·max(0, forward.y)·slopeAssist) × (1−t) × clamp01(10t)` 을 앞으로 민다(페달 0.1 미만은 서서히 0 → 살짝 건드려 기어가지 않음).
- `F1/Assets/Scripts/DriveFeel.cs:26,28,68,69` — 값 구조체에 두 필드, **B 만** `rollAssist 2.6 / slopeAssist 1`. C 는 B 를 복사해 쓰므로 같이 켜짐(C 는 안 돌려봄).
- `F1/Assets/Scripts/Debug/DriveFeelProbe.cs` — QA 전용(에디터·개발 빌드): `HalfPedal()`(반 페달 평지 6 s + 10° 비탈, 45kg/빈 차 × 0.3/0.5/0.7), `QaOnlyHalf`·`QaSlopeAssist`·`QaRollAssist` 덮어쓰기 스위치.
- 씬은 안 건드림(값은 코드 프리셋 → 씬 저장 없음). 빌더 재실행 영향 없음.
- 시도했다가 폐기: ① 비탈 보정만(평지 출발이 안 돼서 무의미) ② "저속 토크"(3 m/s 이하에서 페달 0.8 로 취급) — 페달 0.5 평지가 3.8 m 뿐이라 0.8 m/s 에서 다시 섬. 코드 남기지 않음.

## 2. 확인 방법
Play → 디버그 창 B(기본) → 짐 싣고 반 페달 정도로 언덕 찻집 길을 가 본다(도현 판정). 수치 재현: `DriveFeelProbe.QaOnlyHalf=true; DriveFeelProbe.QaRollAssist=0; QaSlopeAssist=0; DriveFeelProbe.Run(dir,1,false)` (끔) / 기본값(켬). 안 맞으면 B 의 `rollAssist` 만 조절(0 = 예전).
