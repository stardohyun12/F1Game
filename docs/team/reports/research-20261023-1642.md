# 리서치 보고 — 두 박자 분위기 (PD 20261023-1642)

근거 원문: `docs/research/2026-10-23-two-beat-mood.md` (링크·[확인]/[2차]/[추정]/[미확인] 표시는 거기)

## 결론 3줄
1. **"일 = 긴장 / 귀가 = 여유"를 개발자가 직접 설계 의도로 밝힌 게임은 못 찾았다.** 확인되는 건 조각뿐: 시간대 색 변화·같은 색 안개(Easy Delivery Co), 하늘이 색을 정함(Firewatch), 조용한 구간을 일부러 둠(Death Stranding), UI 없는 모드(Alto). 두 박자 조합은 우리가 처음 시험하는 것이다.
2. **손잡이 5개 = 해 고도·색온도 / HUD 양 / 음악 층 / 카메라 FOV / 압박 규칙(타이머).** 카메라는 `FollowCamera.cs` 에 FOV 보간이 이미 있어 가장 싸지만 **외부 근거는 없다.**
3. **귀가 최소 기능 = 시간제한 없음 + (화물 없음) + 끝에서 정산/다음 주문이 일어나는 보상 + 길이 상한(30/60/90초 시험)** — 전부 내 추정, 프로토에서 도현이 보고 정한다.

## 프로젝트 규칙 제안
**손잡이 (갈 때 → 돌아올 때)**
1. 해/빛: 높은 흰 빛·짙은 대비 → 낮은 노란 빛·긴 그림자. 앰비언트+안개는 계속 *한 색* (규칙 11 유지).
2. HUD: 타이머·경로·화물 상태 또렷 → 최소.
3. 음악: 리듬 층+효과음 많음 → 층 제거, 조용한 구간.
4. 카메라: 속도 FOV 보간(현 구현) → 상한 낮추고 약간 멀리 [추정, 가장 싼 시험].
5. 압박: 타이머·파손 감시 켜짐 → **꺼짐**.

**귀가 최소 기능**: 타이머 없음 · 끝에서 보상(정산/다음 주문)이 일어남 · 길이 30/60/90초 3안 시험 · 건너뛰기 여부는 도현 결정.

**판정 방법**: 같은 장소 스크린샷 2장(갈 때/올 때)을 1× → 흑실루엣 → 4× 로 도현이 직접 보고 구분되는지.

**형용사 의견(한 줄)**: "따뜻한·바쁜·바랜"은 갈 때 박자와 EDC·기쿠지로 계열에 맞지만, 기우는 노란 빛의 귀가 박자엔 '바랜'보다 '느긋한·황금빛'이 맞다 → 박자별 형용사 쌍으로 쪼갤 것; 금지어 "귀여운"은 팔리는 편안한 배달 게임(Mail Time)의 핵심어라 도현 판단(근거 약함).

## 모르는 것
- 두 박자를 설계 의도로 말한 개발자 1차 발언, 카메라/FOV 로 감정을 가른 사례 — 못 찾음.
- Death Stranding "도착 시 곡 재생" — 출처 없음. Mail Time 의 시간제한 — 확인 안 됨.
