# research 20261102-2255 — UI 레퍼런스: 세상 속 정보 + 최소 화면 UI (D-267)

자체 점수: 해당 없음(리서치, 그림 판 아님) — 앞 판 해당 없음
결과 본문: `docs/research/2026-11-02-diegetic-ui-refs.md` · 커밋 안 함 · 저장소에 이미지 저장 안 함(링크만)

## 결론 3줄
1. **도현의 방향(세상 물건이 정보를 주고 화면 UI 는 최소)은 맞다.** 9게임 중 화면 UI 0 에 가까운 건 Firewatch·Jalopy 둘이고, 배달이 본업인 Lake·Mail Time·EDC 는 작은 화면 UI 를 같이 쓴다. 우리 UI 1판(화살표·[E] 칩·말풍선)은 이미 그쪽이라, 남은 일은 **"읽을 정보"를 손에 든 종이로 옮기는 것.**
2. **뼈대는 "손에 든 종이" 공용 모듈 1개**(들어 올림 → 뒤 세상 보임 → 확대 → 내려놓기, [Firewatch 지도 컷](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/383870/ss_4b9d67ae2af0da570d03731d93b095d0203b973d.1920x1080.jpg)). 칠판 쪽지·전표·일기가 같은 동작을 쓴다. 화면 밖 화자는 **손에 든 무전기**(Firewatch 02·05).
3. **장면별 1안 + 크기: 칠판 주문 M · 전표/길 찾기 M · 화물 상태 S · 대화 S · 하루 끝 M.** D-238·240·242·243 은 그대로. 반면교사는 Death Stranding 의 풀스크린 홀로그램 목록·상시 타이머.

## 1. 한 것
- Steam 공식 스토어 컷 9게임(Firewatch·Jalopy·EDC·Short Hike·DS Director's Cut·Mail Time·Lil Gator·Lake·TOEM)을 컷마다 훑어 ①세상 물건 ②화면에 남긴 것 ③대화 ④우리 장면에 가져올 것으로 정리. Firewatch·Lake 는 이번이 처음(앞 조사는 11게임).
- 우리 5장면(칠판 주문·전표/길 찾기·화물 상태·대화·하루 끝)별 추천 1안 + 클릭되는 공식 컷 URL + 크기(S/M/L).
- 이미 정한 D-238·240·242·243 과 충돌하지 않게 `docs/design/DELIVERY-LOOP.md` 대조.
- **안 한 것**: gameuidatabase.com(CAPTCHA·AI 사용 금지 약관), 이미지 저장, 플레이 영상 시청, 게임 구매·실행.

## 2. 확인 방법
- 컷 번호가 가리키는 물건이 실제로 보이는지: 컷을 내 임시 폴더로 내려받아 접촉 시트로 훑음(저장소 밖, 임시본은 정리 대상).
- 링크 검사: 보고서 속 URL 27개(스크린샷)가 소스 목록 `steam.json` 과 **글자 그대로 일치**하는지 스크립트로 비교 → 일치 27/27. 이어서 HEAD 요청으로 39개 링크 전수 확인.
- 이 조사가 틀렸다면 실패했을 검사(체크리스트 17): "링크 눌렀을 때 주장한 물건이 안 보임" → 컷 URL 이 소스와 불일치하면 걸림. 결과: 불일치 0.
- 깨뜨릴 만한 곳: 링크가 CDN 주소 변경으로 죽는 것(Steam 이 바꾸면 깨짐 — 문서에 대체 방법 적어 둠), 눈대중 %를 4% 상한과 비교하는 부분(±1%p 오차로 표시).
- 새 자리(체크리스트 18): 앞 조사에 없던 Firewatch·Lake 를 새로 넣었고, 컷 중 처음 보는 번호(Firewatch 02·05, Lake 02·03·05·07)를 열어 봄.

## 프로젝트 규칙 제안 (전부 제안 — 승인 전 확정 아님)
1. 읽을 정보는 "손에 든 종이" 하나로 통일(칠판 쪽지 = 전표 = 약도 = 일기가 같은 동작).
2. 화면 밖 화자는 손에 든 무전기, 대면 대화는 지금 말풍선 그대로.
3. 화물 상태는 상자 표면 라벨 + 짐칸 실물, 막대·숫자 상시 표시 없음.
4. 도착 확인은 집 번호·문패, 화살표는 D-243 그대로.
5. 꺼내기 동작은 한 건당 1번(칠판에서 집은 쪽지가 곧 전표).
6. 하단 큰 대화 상자·하단 자막 띠는 쓰지 않는다(D-237 이력).
7. 새 종이 글자 내용은 도현이 정한 것만(레퍼런스 글자는 읽는 방식 참고).
8. 만들기 전 비교 컷: 같은 카메라로 종이 없음/있음 두 장, 종이 뒤로 도로가 보이는지.

## 모르는 것
- EDC 의 주문 받기·목적지 표시 방식(스토어 컷·위키·인터뷰에 없음) → 플레이 영상 필요.
- 개발자 본인의 UI 이유: EDC(80.lv)·Short Hike(PS Blog) 외 Firewatch·Jalopy·Lake·DS·Mail Time 은 못 찾음 — 대부분 화면 관찰.
- 지도·전표를 꺼내는 동작이 60번 반복에서 질리는지 → 회색 상자 프로토로만 알 수 있음.
- 운전 중 종이를 읽는지(Jalopy 지도책·Firewatch 지도) 미확인.
- Lake·Firewatch 화면 %는 눈대중. DS2 요약 주문 화면은 PC Gamer 원문을 못 열음.
- 스토어 컷 편향(HUD 가 빠졌을 수 있음). 80.lv 링크는 이번 HEAD 로 재확인 못 함.

## 4. 남은 이슈
- 도현이 정할 것(제안일 뿐): ① "손에 든 종이" 공용 모듈을 첫 M 로 시작할지 ② 칠판 쪽지 = 전표 한 물건으로 합칠지 ③ 화면 밖 화자를 무전기로 할지.

- 임시 폴더 `C:/Users/rtx40/AppData/Local/Temp/r1`(내려받은 컷·스크립트)는 저장소 밖. **삭제 시도가 권한 거부돼 아직 남아 있음** — 도현이 지워도 되고, 지워도 보고서에 영향 없음.
