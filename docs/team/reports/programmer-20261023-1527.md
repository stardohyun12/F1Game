# 프로그래머 보고 — 20261023-1527 저해상도 렌더 시험

## 0. 결론 먼저
- **현재 씬은 이미 960×540 Nearest 다.** PC_RPAsset `renderScale=0.5`, `upscalingFilter=Point`(enum 2). 후처리 켜진 Main Camera 에서도 Point 가 실제로 먹는다 — 게임 뷰 캡처의 픽셀 쌍을 세면 정확히 2×2 블록.
- 480/640 도 renderScale(0.25/0.333)로 낼 수는 있지만 창 크기에 따라 해상도가 흔들리고 품질 에셋을 바꿔야 해서, 씬 기본값을 안 건드리는 시험용으로 **RT(Point)→화면 방식 시험 컴포넌트 `LowResRenderTest`** 를 만들었다. UI(Canvas)는 원해상도 유지. 씬에는 **꺼진 상태**로 붙어 있다.

## 1. 한 것
- `F1/Assets/Scripts/Debug/LowResRenderTest.cs` (신규) — Main Camera 에 붙는 시험 컴포넌트.
  - `targetHeight`(기본 270). 켜면 카메라를 Point RenderTexture 로 그리고, 정렬 -32000 Overlay Canvas 의 RawImage 로 화면 전체에 깐다 → UI 캔버스(UIRoot)는 그 위에 원해상도로 뜬다.
  - URP renderScale 이 RT 카메라에도 곱해지므로(URP 17.3 `UniversalRenderPipeline.cs:1507-1508`) RT 크기를 `높이/renderScale` 로 잡아 **실제 렌더 해상도 = targetHeight** 가 되게 보정. renderScale 은 리플렉션으로 읽음(PitCrew asmdef 에 URP 참조 없음).
  - 끄면 `targetTexture=null`, 캔버스·RT 파괴. 팔레트/디더 없음.
- `F1/Assets/ComplexTrack.unity` — Main Camera 에 `LowResRenderTest` 추가, `enabled=0`. diff 14줄(컴포넌트만). PC_RPAsset·카메라 값 등 씬 기본값은 안 건드림.
- 시험 스크립트 `docs/qa/tmp/lr-*.cs` (info/add/gv/check/cap/live/kill/prog/get).

## 3. 검증 증거 (실제 돌린 것)
- 파이프라인 확인(`lr-info.cs`, Play·에디트 둘 다): current=quality=default=**PC_RPAsset**, 품질 레벨 "PC", renderScale **0.5**, upscalingFilter **Point**. Main Camera renderPostProcessing=True, AA None. 루트 캔버스 UIRoot 하나(ScreenSpaceOverlay).
- 후처리 + Nearest 실제 동작(`lr-check.cs`, 게임 뷰 1920×1080 캡처, UI 없는 영역 x100~560·y400~1000): 가로 이웃 픽셀 **짝수 시작 쌍 100.0% 동일 / 홀수 시작 쌍 41.9%** → 정확한 2배 Point 확대. 코드 근거: URP `PostProcessPassRenderGraph.cs:2412` 가 Point 필터면 최종 패스에 PointSampling 키워드를 켬(TAA 샤프닝 켤 때만 예외). 크롭: `lowres-current-gameview-zoom8.png`.
- 캡처 4장(`lr-cap.cs`): 같은 프레임(timeScale=0, 운전 시작 지점 camPos (67.0, 2.0, 60.0)), 오프스크린 RT 렌더 → Point 다운 → nearest 업스케일 1920×1080. 산출물 `lowres-{native,960,640,480}.png`, `lowres-compare.png`.
- 프레임 시간 ① GPU 렌더만(오프스크린, 워밍업 3 + 20회 평균, 매회 1px ReadPixels 로 GPU 동기화):
  - native 1920×1080: **7.07 ms**
  - 960×540: **2.96 ms**
  - 640×360: **3.65 ms** (480 보다 느림 → 측정 잡음으로 봄)
  - 480×270: **2.97 ms**
- 프레임 시간 ② 실제 게임 뷰(`lr-live.cs`, 에디터 Play, 1920×1080, 세계 정지, 30프레임 버리고 120프레임 unscaledDeltaTime 평균, 에디터 오버헤드 포함):
  - 컴포넌트 끔(=현재 0.5/960×540): 3.52 ms
  - 1080: 3.17 · 540: 3.14 · 360: 3.16 · 270: 3.06 ms
  - → CPU/에디터 쪽이 병목이라 차이 거의 없음. 빌드 GPU 비용은 ① 이 더 의미 있음.
- 정리: Play 정지, 폰트 SDF 3개 변경 없음(git status 확인), 기존 증거 파일 덮어쓴 것 없음.

## 4. 남은 이슈 / QA·도현 체크리스트
- **가설:** 해상도를 낮춰도 이득은 native→960 구간(7.1→3.0ms)이 대부분이고 960 아래는 성능 차이 없음. 고를 기준은 성능이 아니라 **보이는 느낌**.
- 관찰: 480 에서 전선·먼 디테일이 끊기고, 차는 읽힌다. 640 은 중간.
- **안 한 것:** 팔레트/디더(지시대로), 주행 중 픽셀 기어감(shimmer) 확인 — 정지 프레임만 찍음, 빌드 측정, 회귀 스크립트.
