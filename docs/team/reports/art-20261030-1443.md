# art 20261030-1443 — 뷰 회랑·전망 자리

상태: 정적 계산·저장 파일 검사 완료. 이 작업에서 Unity·게임 파일 수정·commit/push 없음.

## 1. 한 것
- `tools/map/find_vistas.py`: 차길 1m 표본, 양방향 ±15° 팬, 지형 1m 표본 + 건물 AABB 입구/출구의 정확한 교차 거리로 가림각 계산.
- 최신 `placements.yaml`와 `env-buildings.json`의 핵심 4채(우리 집·정비소·보관소·우체국)를 사용. 과거 activeContext의 좌표는 사용하지 않음.
- 출력: `docs/map/vistas.json`, `docs/map/vistas.png`, `docs/map/vistas-V01-section.png`~`vistas-V05-section.png`, `docs/map/vistas-sections.png`.
- 회랑 24개(바다 7·능선 16·보관소 위치 1), 전망 표본 10개. 전망 10개는 동쪽 능선 약 43×29m 안에 모인 5m 간격 표본이며, 서로 다른 10개 지역이라는 뜻은 아님.

## 2. 확인 방법
`py -3.13 -X utf8 tools/map/find_vistas.py` → 재계산, `py -3.13 -X utf8 tools/map/find_vistas.py --check` → 입력 해시·회랑 길이·전망 조건·PNG 무결성 검사.

### 해석·실패 기록 (임의 조건을 숨기지 않음)
- 최초에는 전망에도 300m 거리와 전경 가림 거리 120m를 추가 적용하여 0개가 나옴. 이는 요청에 없는 추가 조건이었음.
- 최종 회랑은 요청 그대로 300m. 전망은 **자료 범위 안 최대 1km**, **전경 30m 동안 눈높이 가림 없음**을 개방의 작업 정의로 삼음. 120°·하향 5~25°·마을과 바다 모두 가시라는 요청 조건은 유지.
- 10m 간격 부분 조사에서 전경 가림 거리 15/30/60/120m일 때 조건 통과 표본은 9/6/3/0개였음. 개방 거리를 늘리면 결과가 줄어드는 민감도이며 최종 수와 혼동하지 않음.
- 전망 선택의 25m 지역 간격도 요청에 없는 조건이라 제거하고, 표본 간 중복 제거만 약 5m로 둠. 따라서 10점이 한 구역에 모인다는 한계를 명시.
- 최초 지도에서 자료 밖 도로가 제목·범례를 덮은 오류를 직접 열어 발견하고 지도 사각형에 잘라 수정. 단면 건물은 지형을 따라 바닥을 표시하도록 수정.
- 계산 중 배치 파일의 보관소·우체국 높이가 갱신됨. 지형·ENV 해시는 동일함을 확인하고 최신 핵심 4채 값으로 회랑만 재계산: 보관소 위치 회랑이 1개 늘어 23→24개. 전망은 해당 건물 치수를 가정하지 않으므로 영향 없음.
- 초벌 JSON 저장에서 NumPy int64 직렬화 오류가 나서 Python 정수 변환·명시적 스칼라 직렬화를 추가. 최종 파일은 재실행 결과임.

## 4. 남은 이슈·승인·다음 단계
- 지형은 원본 8m 격자의 보간이며 Unity의 깎고 메운 노면/실제 메시와 동일하다고 주장하지 않음.
- 해안선 물쪽이면서 지형이 해면 아래인 지점만 바다로 인정. 자료 밖은 미확인으로 처리.
- 핵심 건물은 치수 부재로 위치+1.6m 표지만 검사; 등대 높이 부재로 등대 탑 가시성은 제외. 수목·난간 차폐 미검증.
- 네 핵심 건물의 실제 외곽 상자는 입력에 없어 차폐물로 추가하지 않음. 특히 전망이 핵심 건물 근처이므로 실제 건물이 들어오면 가려질 수 있음.
- `blockers.building_ids`는 해당 방향 팬 300m 안에서 교차한 부분 시야 차폐 후보이며, 목표 전체를 가린다는 뜻이 아님. 나무 자리 후보도 실제 나무가 아니라 수관으로 시야를 막을 위험을 확인할 후속 자리임.
- 도현 승인 필요: 실제 전망 자리 채택·나무 배치 단계. 이번 산출물은 분석 도면이며 제작 에셋이 아님.
- QA/프로그래밍 실제 씬 시야 확인 필요. 임포트할 에셋은 없음; Unity 실행·임포트·Play 미실행.
