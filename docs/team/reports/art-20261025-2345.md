## 후보 차이

| 후보 | 형태·생활의 흔적 | 수치 |
|---|---|---|

실존 상표는 없다. 작은 경주 번호는 Galmuri `7` 한 자리, **번호·스티커까지 32px/m**로 제작했다. 64px/m 예외는 쓰지 않았고 승인 요청도 필요하지 않다. 뒤 번호판은 미세 글자를 억지로 넣지 않은 금속판이다. 콕핏은 빈 좌석·핸들까지이며 캐릭터 모델은 새로 만들지 않았다. 프로그래밍팀이 기존 `driver`를 별도 유지/연결해야 한다. A 짐칸은 비어 있으며 C 방수포는 작은 정적 부착물이다.

## 기존 차와 물리 계약

실제 참조는 `Car_*.mat` 이름으로 추측하지 않고 씬 GUID를 추적했다. 두 씬 모두 **Race.prefab → FormulaGameplayVisual.prefab → CoastalFormula.fbx**다. 씬에서는 driver만 `FormulaRestored.mat`, 나머지는 `FormulaWorn.mat`를 사용한다. 기존 차 비교 렌더에도 이 텍스처를 반영했다. 실제 Unity 셰이더는 실행하지 않았다.

| 항목 | 유지한 값·확인 |
|---|---|
| 외곽 치수 | 폭1.958909 × 길이3.785000 × 높이1.072000m. 기존 FBX를 헤드리스 Blender로 직접 다시 읽어 측정 |
| 원점·방향 | 원점을 bbox 중앙으로 옮기지 않음. Blender -Y 전방/Z 위, GLB +Z 전방/Y 위 |
| 휠 | 4개 별도 메시. 앞반경 .35m/뒤 .375m, 축간2.3m·트랙1.58m, 회전 원점·local X축 유지 |
| 현재 Unity 휠 중심 | FL(-.79,.35,1.2), FR(.79,.35,1.2), RL(-.79,.375,-1.1), RR(.79,.375,-1.1) |
| Visual 부모 | local `(0,.1285497,-.19642855)`, scale1.4285712 × Race .7≈1 |
| 현재 씬 BoxCollider | Race local size `(2.7999997,.9285714,5.407142)`, center `(0,.5928354,0)` — 그대로 유지, 후보에는 collider 없음 |
| 코드·씬 | 씬·prefab·Rigidbody·스크립트·콜라이더·.meta 수정 없음 |

**축 주의:** 기존 Unity FBX 좌표는 Blender/GLB의 X 부호와 다르다. GLB의 left/right X를 그대로 복사하지 말고 인계 계약의 실제 Unity 위치와 역할을 맞춰야 한다. 새 FBX 재임포트는 Blender에서 검사했으며, Unity 임포터·바퀴 애니메이션·물리 불변의 런타임 증명은 아직 없다.

## 검증 증거

- [A GLB 검사](../../../art/_review/2026-10-25-car-candidates/check-A.json), [C GLB 검사](../../../art/_review/2026-10-25-car-candidates/check-C.json): 전 항목 PASS. 실제 export 삼각형 두 주축의 밀도 **31.9976~32.0029px/m**, 팔레트 밖0, POT, Point, 전체bounds·4휠 원점·UV·불투명·출처 SHA 확인.
- [A FBX 검사](../../../art/_review/2026-10-25-car-candidates/fbx-A.json), [C FBX 검사](../../../art/_review/2026-10-25-car-candidates/fbx-C.json): 별도 Blender 재임포트 후 GLB와 position/UV corners·tris·bounds·휠 축 비교 PASS.
- 마무리 중 공유 작업공간의 Map_BayLoop 파일 해시가 바뀌어 해당 차량 계약을 다시 읽었다. Race·Visual 두 인스턴스의 전체 override와 부모 참조는 동일했다(`current-contract-recheck.json`, `changed_physical=false`). 다른 씬 내용은 이번 외형 작업에서 수정하지 않았다.
- 단색 면은 기존 차량 검사 정책(실제 연결된 평면≥.04m², 2색 이상·주색≤98%) 그대로 통과했다. 임계 완화 없음. 8×8 단색창 진단은 별도 기록되며 이를 모든 면에 강제한 검사가 아니다.
- 기존 `check_car.py` 기본값은64px/m·3,000tris 그대로 두고, 명시적 `--density 32 --max-tris 6000` 인자를 추가했다. 기존 검사기 self-test와 추가32px/m 재현 확인 PASS. `check_car_candidates_fbx.py`는 기존 차량 round-trip 검사 알고리즘을 같은 D-142 계약으로 옮겼다.
- **32색 검사는 원본 albedo에 대한 검사**다. 조명·그림자·안티앨리어싱이 있는 최종 렌더를 32색이라고 주장하지 않는다.

재현: `Blender -b --python tools/asset-gen/car_candidates.py -- --variant A` (C도 동일); `py -3.13 tools/asset-gen/check_car.py --model art/models/car_candidates_v01/A.glb --texture art/models/car_candidates_v01/A_Atlas.png --density 32 --max-tris 6000 --out <검사JSON>`.

## 스킬 사용·참고·수정

외부 [blender-skills](https://github.com/arjun988/blender-skills) 로컬 MIT 팩의 director/vehicle-artist를 직접 읽고 **비례 잠금 → 열린 차체·콕핏 → 분리 시스템 → 연결·패널 → 검증** 절차를 적용했다. 휠베이스·트랙·휠직경·오버행은 기존 플레이어 차를 기준으로 잠갔다. MCP는 bpy/실제 export 검사로 대체했고 전역 설치하지 않았다. 높은 텍셀·폴리 예산·PBR 권고보다 프로젝트의32px/m·공용팔레트·사진·6,000tris를 우선했다.

사례 조사: [Porsche 공식 Type804](https://newsroom.porsche.com/en/press-kits/Porsche-Museum/Porsche-Typ-804.html)의 열린 바퀴·단좌 금속 외피 원리와 [FIA의 Fiat Abarth131 자료](https://historicdb.fia.com/car/fiat-abarth-131-rally)의 시대적 랠리 개조 맥락을 참고했다. 차종 치수·상표·리버리를 복제하지 않았다. 검증된 프로젝트의 기하 UV·사진 파이프라인·검사기를 재사용했고, 완성 예제 모델을 원본 조건으로 재현했다고 주장하지 않는다.

실제 사진은 기존 CC0 Poly Haven `rusty_metal_02`, `rubberized_track`, `rough_linen`을 재사용했다. 3.75m 사진 영역→120px→팔레트 양자화, 그림 정보층은 실제폰트·테이프·부품 색으로 분리했다. 첫 판의 큰 카모 얼룩은 사진의 저주파 성분을 제거하고 저대비 변주를 줄였다. 사진결도 화면에서는 반복 얼룩으로 읽힐 수 있어 잔여 결함으로 공개한다.

첫 판 상세 제작 후 시각평가를 했으므로 스킬의 ‘상세 전 별도 블록아웃 승인’ 전체를 재현한 것은 아니다. 효과는 자동적인 품질 상승보다 **물리 계약을 먼저 잠그고, 기능별 부품과 검사 증거를 남긴 점**에 있었다. 독립 리뷰가 발견한 검은 휠은 실제 타이어 막음면이 림을 가린 구조 문제였고, 중앙이 열린 타이어 측면과 분리 림으로 고쳤다.

최종 독립 리뷰는 각각 정면·측면·3/4의 **차량 자체** 판정이다. 마을 합성은 내가 직접 확인했으며 A는 낮은 적갈 차체, C는 밝은 차체와 랠리 장비로 구별된다. **마을 조화가 독립 게이트에서 확정됐다고 주장하지 않는다.** 실제 인게임 캡처에서 두 후보의 조명·타이어 접촉·드라이버·짐칸 위치를 함께 판단해야 한다.

**QA/프로그래밍 임포트 필요.** 통과한 시험 FBX의 외형·재질만 기존 Visual 아래에 붙이고 현재4휠·driver 역할을 연결한 뒤, 동일 마을 위치·동일 카메라로 A/C 실제 인게임 캡처를 받아 도현이 고른다. Unity·Play·런타임 주행·충돌 확인은 실행하지 않았다. 커밋·push하지 않았다.
