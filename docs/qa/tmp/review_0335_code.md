# 0335 코드·캡처 독립 검토

읽기 전용으로 `mesh_parts.py`, `depot_clearance.py`, `build_depot_bpy.py` 변경부, `check_rules.py` overlay 변경부를 검토했다. 원본/FBX/Unity 수정·실행은 하지 않았다. 아래 실제 수치는 부모 작업이 남긴 JSON을 읽은 것이며 이 하위 작업의 재실행 결과가 아니다.

## 현재 결과와 판단

- `rules.json`의 두 WEAR 메시: 각각 약 64 px/m, 투명 픽셀 비율 약 93.7%/93.6%, 불투명 색 1개, baked=0, blobs=0. 현재 두 edge_chip을 글씨 검사에서 제외하는 것은 자료와 일치한다.
- `clearance_final.json`: 상자끼리 0, 상자/고정물 0, 상자 최대 38 tris. `independent_0335.json`: 상자 49개, 분리 전후 기하 보존, 피벗 최대 오차 약 0.00000024m. 수치상 현재 보관소 수정은 목적에 부합한다.
- 최초 검토에서 지적한 overlay 예외 범위와 64px/m 강제 누락은 부모가 수정했고, 최종 diff를 다시 읽어 보완을 확인했다. 아래 실제 수치는 수정 전 검사 JSON이므로 최종 검사 실행 결과는 부모 보고를 확인해야 한다.

## 지적 사항

| 우선 | 위치 | 확인한 문제 / 영향 / 권장 보완 |
|---|---|---|
| 해결 확인 | `tools/art/check_rules.py:237–247,292–295,331–333` | 최초 이름 기반 일반 면제에서 **depot + Q3_decals_WEAR_ 접두 + decals.png + 모든 UV가 edge_chip 셀 내부 + alpha 비율 ≥50% + 불투명 색 1개**로 한정됐다. alpha/색 조건 실패 시 text 검사로 복귀하고, overlay의 baked/blob 검사도 복구됐다. 현재 두 단색 투명 칩에만 grain/flat/colors 예외를 주려는 의도와 일치한다. 실제 alpha 비율은 기존 정의인 alpha<250 픽셀 비율이며, 색 측정은 alpha≥128 픽셀 대상으로 서로 다른 기준이라는 제한은 남는다. |
| 해결 확인 | `tools/art/check_rules.py:267` | board의 32/64 허용 분기 뒤 overlay에는 별도로 `abs(dv/64-1)<=0.25`를 적용한다. 따라서 32px/m overlay는 더 이상 통과하지 않는다. 현재 실제 두 칩은 64였다. |
| 중간 | `tools/art/mesh_parts.py:69–76` | 이름 허용목록 + 2cm AABB 접촉 병합이라 닿아 있는 별개 소품/게시물은 다시 한 그룹이 된다. 1.5cm 떨어진 평행 스티커 두 장도 병합되고, `KEYS_01`/`BOOKS_01`처럼 이름 목록 밖의 소품은 보지 않는다. 현재 `Q3_decals`는 잘 분리했지만 일반적인 '별개 물건이면 낱개' 규칙을 완전히 구현한 것은 아니다. 의미상 분리해야 하는 물건 목록/생성기 그룹 정보를 우선하고 접촉 병합은 프레임·부품 조립체에 한정할 필요가 있다. |
| 중간 | `tools/art/depot_clearance.py:63–78,124–127,134` | solver는 선반 전체 bbox와 높이로 row를 고르고, 일반 후보 지지는 중심점 하나만 검사한다. 체크 모드의 `audit()`는 관통만 검사하며 지지는 검사하지 않는다. 따라서 지지가 없어도 관통 없는 상자는 통과하고, 구멍 있는 선반/가느다란 받침에서는 매달린 배치가 통과할 수 있다. 현재 별도 `independent_0335.json`의 지지 증거는 있으나 이를 지속 회귀 검사로 연결하지 않으면 누락된다. |
| 낮음 | `tools/art/depot_clearance.py:29–33` | 고정물은 연결 섬 AABB 중 세 축 두께가 0.5mm를 넘는 것만 검사한다. 열린 ㄷ자 물체의 bbox 내부 빈 공간도 고체로 볼 수 있어 오탐 가능, 두께 없는 벽면은 누락 가능. 현재 축정렬 상자·선반 보드에 대한 보수적 검사라는 범위를 보고에 유지해야 한다. |
| 낮음 | `tools/art/build_depot_bpy.py:51–61,147–156` | WEAR 분류는 UV 평균점의 edge_chip 셀 포함 여부만 확인하고 UV 보정은 최종 아틀라스 160px를 상수로 사용한다. 현재 결과는 맞지만 셀 경계를 넘는 면/혼합 그룹 또는 아틀라스 해상도 변경 시 분류나 밀도가 틀릴 수 있다. 모든 UV의 셀 포함과 실제/설정된 최종 텍스처 크기를 사용하면 개선된다. |
| 낮음 | `tools/art/check_rules.py`의 `m.sum() < 16` 조기 반환 | 기존 empty 행 경로가 alpha/색 조건 검증보다 먼저 반환하므로 극히 작거나 완전히 투명한 표본은 texel/uvcollapse만 남는다. 이는 새 변경이 만든 일반 기능은 아니지만, 향후 칩이 전부 사라진 경우도 PASS할 수 있다는 기존 제한이다. 현재 두 칩의 mask 면적과 불투명 픽셀 수는 충분해 해당하지 않는다. |

하부 벽 검사가 담당할 수 있는 것은 하부 벽 재질의 결·색·조명 굽기다. 위에 합성한 칩 자체의 그림자/얼룩 형태까지 하부 재질 검사로 보장할 수는 없으며, 최종 변경은 그 때문에 baked/blob를 다시 검사한다. 반대로 검증된 단색 투명 칩 자체에 벽과 같은 최소 4색을 요구하는 것도 오탐이므로 grain/flat/colors 예외의 취지는 타당하다.

## 캡처 판단 — 점수 없음

대상: `docs/qa/evidence/studio-depot/s10_split_in.png`, `s10_split_front.png`. 부모가 제공한 설명대로 마지막 WEAR UV 변경 전 캡처이며, 그 이후 외관 검증으로 대체할 수 없다.

| 질문 | 판단 | 관찰/제한 |
|---|---|---|
| 두 캡처에서 상자가 선반 기둥을 명백히 뚫고 나오는가? | 아니오 | 보이는 오른쪽·후면 선반에서는 상자 앞면과 기둥이 구분된다. 가림과 원근 때문에 숨은 면의 관통 0은 캡처만으로 확정 불가. 위 JSON 검사와 함께 봐야 함 |
| 게시물 전체가 사라지거나 눈에 띄게 깨졌는가? | 아니오 | 정면 창 왼쪽·오른쪽 종이와 위 간판, 실내 상자 라벨은 남아 있다. 단일 프레임으로 z-fighting 없음은 확정 불가 |
| 낱개 오브젝트 선택·피벗을 이 이미지로 검증할 수 있는가? | 아니오 | 외관 캡처는 분리 구조를 드러내지 않는다. `names.json`/독립 기하·피벗 검사 근거가 필요 |

이 캡처에서 추가로 확정한 새 외관 결함은 없다. 새 WEAR UV 적용 후 캡처와 기존 캡처의 쌍대비교 또는 도현 판정이 남는다. 숫자 점수와 도현 승인 대체 판정은 하지 않았다.
