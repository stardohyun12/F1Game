# 도현 눈 예측 판정 — JUDGE (2026-10-27)

처방 근거: `docs/research/2026-10-27-art-internal-audit.md` §4-②. 결론부터 말하면 **10점 점수제와 체크리스트 판정은 버린다.** 쓰는 것은 **A/B 쌍대비교(②c) + 양 순서 + Sonnet 판정자**뿐이다.
앵커 `anchors.json`·`anchors.png`, 프롬프트 `prompts/`, 원 출력과 집계 `runs/2026-10-27/`(summary.json), 실행 도구 `judge_pair.py`.

## 1. 검증 결과 (도현 반응을 모르는 새 판정자, 앵커 21장 — 긍정 7·부정 14)

판정자는 `claude -p`로 돌렸다. Read 만 허용했고, 사용자·프로젝트 설정을 꺼서 CLAUDE.md·TASTE 가 안 들어간다. 이미지는 익명 이름(X..)으로 바꿨다.
쌍은 긍정 7장 × 부정 4장씩 28쌍이고, 각 쌍을 L/R 두 순서로 물었다.

| 방식 | 판정자 | 도현과 일치 | 비고 |
|---|---|---|---|
| ① 점수형 10점 (p1) | Sonnet | 7점 게이트: 긍정 **0/7** 통과, 부정 14/14 거부. 순위 AUC 0.66 | 전부 1~6점에 몰림. 최고점은 **부정** X35(v5 정비소 장면) 6점 |
| ①b 점수형 + 도현 앵커 예시 | Sonnet | AUC 0.76, 7점 넘은 건 X35(부정) 하나 | 감사가 짚은 문제가 그대로 다시 나옴 |
| ③ 결함 판별형 (p3) | Sonnet | 21장 **전부 거부** (긍정 0/7) | 정보 없음 |
| ③b 결함형 + 앵커 예시 | Sonnet | 긍정 1/7 통과, 부정 12/14 거부 | 통과 3장 중 2장이 부정(X73·X35) |
| ② 쌍대비교 (p2) | Sonnet | 한 번 물음 44/56 = **79%**, 양 순서 다 맞음 20/28 = 71% | L 쏠림 없음(28/56) |
| ② 쌍대비교 (p2) | Opus | 38/56 = 68%, 양 순서 17/28 = 61% | 판정자 모델을 바꾸면 떨어진다 |
| ②b 쌍대 + 도현 앵커 예시 | Sonnet | 37/56 = 66%, 양 순서 14/28 = 50% | **앵커를 보여 주면 오히려 나빠짐** |
| **②c 쌍대 + PICKS 가져올 것/안 가져올 것 + 금지 목록** | **Sonnet** | **45/56 = 80%, 양 순서 20/28 = 71%** | 채택 |

②c 를 더 어려운 조건에서 따로 쟀다.
- 쉬운 부정(도현 직접 스샷 4장)을 뺀 20쌍: 30/40 = 75%, 양 순서 13/20.
- PICKS 직전 판들(정비소·고카트 v0~v5, 장면 A)과 붙인 10쌍: 16/20, 양 순서 7/10.
- 도현의 **상대 판정** 2쌍을 각각 2회 × 양 순서로 물었다: Opus v1 > v2("퀄리티가 더 낮아진 것 같아"), v5 장면 > 장면 A 텍스처("바로위 그림 보면 퀄리티가 더 낮아진것같음"). **8/8 맞힘.** 옛 판정은 v1 5점 → v2 6점으로 방향이 반대였다.

읽기:
- 점수형과 결함형은 무엇을 주든 "부족함"으로 모은다. 도현이 받아들인 컷도 다 떨어뜨리고, 가장 높은 점수는 PD 가 "쨍한 레고"라 한 v5 에 줬다. [추정] 판정자가 "따뜻하고 깔끔한 아늑함"을 좋게 보는 기본 취향이 도현과 반대다.
- 쌍대비교는 절대 수준을 묻지 않아서 그 쏠림을 피한다. ②c 의 "다른 게임으로 치는 것" 목록이 v5(X35)형 실수를 줄였다(②: X16·X62 대 X35 둘 다 틀림 → ②c: X16 맞힘, X62 반만 틀림).
- 도현 앵커를 예시로 보여 주면(②b·③b) 판정자가 겉모양이 닮은 앵커를 따라간다. 예: 무드 시안(부정)이 슬라이스(긍정)와 같은 거리라서 긍정 쪽으로 끌려감. 앵커가 2주에 걸친 서로 다른 기준을 섞고 있어서 생기는 일이다. **그래서 앵커는 판정자에게 보여 주지 않는다. 판정자 자격 시험과 게이트 비교 상대로만 쓴다.**

## 2. 절차 (팀 과제에 그대로 붙임)

```
[아트 판정 — JUDGE.md ②c]
1. 판정 그림 = Unity 게임 카메라 캡처 1장 (720 Nearest). 시트·블렌더 렌더 금지. 시트 안에 기준 화면을 넣지 않는다.
2. 직전 판과 비교:   python docs/qa/judge/judge_pair.py <새컷.png> <직전컷.png>
   - 양 순서 모두 이김 = 좋아짐 / 모두 짐 = 나빠짐 → 되돌림 / 갈림 = 판정 불가(같은 수준) → 다음 판 금지, 도현에게 방향 판정.
3. 게이트:           python docs/qa/judge/judge_pair.py <새컷.png> --gate
   - 부정 앵커 3장(X35 v5 정비소 장면 · X32 Opus v2 · X65 Look4 거리)과 차례로 붙인다.
     3승 = 도현에게 보냄 / 1패라도 있으면 돌려보냄 / 패 없이 갈림만 있으면 도현에게 30초 판정으로 보냄 [추정 기준, §5].
4. 10점 점수·체크리스트 판정은 쓰지 않는다. 보고에는 "직전 판 대비 승/패/갈림 + 게이트 3전 결과 + 진 쪽 차이 한 줄"만 쓴다.
5. 판정자 모델·프롬프트를 바꾸면 먼저 자격 시험:  python docs/qa/judge/judge_pair.py --qualify --model <모델>
   - 앵커 30쌍 중 양 순서 모두 맞힘 70% 이상이어야 쓴다 (Sonnet 2026-10-27: 28쌍 기준 71%. Opus 61% → 불합격).
```

비용과 시간: 한 번 물을 때 Sonnet 으로 약 15~30초다. 비교 1건 = 2회, 게이트 = 6회. 자격 시험 = 60회(병렬 4, 약 5분).

## 3. 프롬프트 원문 (②c, `prompts/p2c_pair_picks.txt`)

```

Read 도구로 아래 파일만 열어 본다(다른 파일·폴더는 열지 않는다).

기준 화면(실제 출시 게임 스크린샷 3장):
- img/REF1.png (A Short Hike) — 가져올 것: 화면 도트(낮은 렌더 해상도 계단), 큰 덩어리 나무·바위, 늦가을 색 / 안 가져옴: 귀여운 동물 캐릭터
- img/REF6.png (Easy Delivery Co.) — 가져올 것: 마을 길 + 작은 차 + 전신주 + 상자 화물 + 낮은 해상도 / 안 가져옴: 회색 겨울·어둠
- img/REF12.png (Crow Country) — 가져올 것: 물건·차의 또렷한 저해상도 블록 디테일(텍스처도 블록) / 안 가져옴: 어두운 올리브 색
이 게임에서 "다른 게임"으로 치는 것: 쨍하고 깨끗한 장난감·레고 디오라마·모바일 캐주얼, 사진 점무늬로 더러운 면, 그림판처럼 빈 단색 면, 움직이면 지글거릴 화면, AI 일러스트 같은 매끈한 예쁨.

후보 두 장:
- L = img/{L}.png
- R = img/{R}.png
(게임 캡처일 수도, 에셋 검토 시트일 수도 있다. 형식 차이는 판단 근거가 아니다 — 표면·색·형태·공기의 계열만 본다.)

질문: L 과 R 중 어느 쪽이 기준 REF1·REF6·REF12 와 "같은 게임"처럼 보이나?
```

실행 조건 (이게 바뀌면 자격 시험부터 다시 한다):

- 작업 폴더 = 임시 폴더 하나. 그 안에 `img/REF1·REF6·REF12.png`(①⑥⑫ `_1.jpg`) + 후보 2장을 익명 이름으로 둔다.
- 같은 쌍을 L/R 바꿔 두 번 묻는다. 두 번 다 같은 쪽을 골라야 결과로 친다.

## 5. 한계

- **표본이 작다.** 긍정은 7장이지만 근접 묶음으로 보면 실제로는 4종(슬라이스·원화 / 차 A·C / 언덕 / 건물 시트)이다. 80% 의 오차 폭은 ±10%p 이상이다 [추정].
- **긍정이 전부 PICKS(D-165) 이전이다**(10-13~10-26, 여름 한낮 색·AI 원화 포함). PICKS 이후 도현이 받아들인 컷은 아직 0장이다. 그래서 "지금 기준에서 무엇이 합격인가"는 검증되지 않았다. 쌍대비교가 맞힌 것은 "도현이 거부할 쪽 고르기"다. **도현이 새 컷을 받아들이면 바로 긍정 앵커에 넣고 자격 시험을 다시 돌린다.**
- 남은 오답 유형: 해안 위 차 v1(X73, 부정)이 슬라이스·건물 시트를 이김 / Opus v2 시트(X32)가 언덕 캡처를 이김. 형식 차이(시트 vs 캡처)와 시트 안에 끼워 넣은 기준 화면이 판정자를 흔든다 → 판정 그림은 캡처 1장으로만.
- 판정자는 Claude 계열 하나(Sonnet)다. Opus 는 61% 로 떨어졌고, Codex 판정자는 시험하지 않았다. 모델이 바뀌면 결과도 바뀐다.
- 쌍대비교는 "어느 쪽이 나은가"만 말한다. 도현이 받아들일 절대 수준은 말하지 못한다. 게이트(부정 앵커 3전)는 바닥을 거르는 장치다. 도현 판정을 대신하지 않는다.
- **게이트 기준(3전 3승)은 검증하지 않았다 [추정].** 시험 삼아 도현이 합격시킨 슬라이스의 다른 컷(`docs/qa/evidence/slice-start.png`)을 넣어 보니 1승 2갈림이었다(처음 규칙 "3승만 통과"였으면 돌려보냈을 것 → 갈림은 도현에게로 고침). 3승 문턱은 엄격한 쪽이다. 긍정 앵커가 쌓이면 기준을 다시 정한다.
- 도현 스샷 4장(위 시점·디버그선)은 쉬운 부정이라 전체 일치율을 부풀린다. 그래서 그 4장을 뺀 75% 를 따로 적었다.
- 반응 인용 중 D-097·D-096 은 결정 로그 요약에서 가져왔다(원 대화는 이번 조회 범위 밖). 나머지는 Hermes 대화 기록(state.db) 원문이다.
