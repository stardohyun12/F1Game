9회차: 첨부 일부가 업로드에 실패했는데 성공한 파일만 보내지는 결함을 재현해 수정했다. 입력창에 실패 원인·재시도를 제공하고 실패 해소/제거 전에는 일반 보내기와 /goal을 막는다. 390/1440에서 재시도 파일 바이트·부분 성공 보존·전송 실패 보존, 기존 실제 이미지 업로드 한도/중복/시간 초과 회귀를 확인했다. 독립 검토 후 비교 상태 문구 동기화·재시도 더블클릭의 다른 요소 클릭 차단·목표 설정 창의 첨부 제외 안내와 실패 차단을 보완했고 두 너비의 root 시험을 통과했다. 후속 교차 검토, 한 번 관찰된 Markdown 초기화 오류의 원인 확인, 전체 게임 제작 회귀·운영 실행 서비스 전환은 남아 있다. 근거: `../../.ai_logs/pitcrew-audit/round9-failed-attachment-result.md`.

8회차 실제 관찰: ComplexTrack의 Play 시작 화면을 새로 캡처하고 종료·씬 SHA 보존을 확인했다. 390/1440 격리 UI에서 새 PNG 비교·실 업로드·실제 현재 콘솔 삽입·전송 실패 후 초안/첨부 보존을 검증했다. 편집 카메라와 Play 화면은 수정 전후가 아니며 대화 기록은 수동 fixture, AI send는 차단했다. 실제 화면의 주문 버튼 뒤 안내 가림을 후속 검토 대상으로 삼았다. 게임 수정과 회귀·생산성 실측·운영 backend 전환은 남아 있다. 근거: `../../.ai_logs/pitcrew-audit/round8-live-evidence-result.md`.

비교 화면에 ‘비교 두 장을 요청에 첨부’를 추가했다. 비교할 때 읽은 복사본을 그대로 첨부하고 패널을 유지해 콘솔 관찰까지 연속으로 모을 수 있다. 기존 PNG와 합성 콘솔을 쓰는 같은 격리 과제에서 준비 클릭이 모바일 12→7회, 데스크톱 10→7회로 줄었다. 두 첨부의 원본 해시와 전송 실패 후 초안 보존을 확인했다. 이는 자동화된 UI 과제이며 실제 게임 제작 시간 절감률이 아니다. 기존 단일 첨부의 한도·실패 교체·중복·시간 초과 회귀도 두 너비에서 통과했다. 후속 교차 검토도 완료했으며 묶음 안내 1회, 동일 내용 합침 안내, 합성 프로젝트 전환 시 첨부와 초안 분리를 확인했다. root의 입력 거절 9종도 통과했다. 근거: `../../.ai_logs/pitcrew-audit/game-evidence-bundle-result.md`.

7회차: 도구 종료의 초록 체크를 중립 상태와 출력 미리보기로 바꾸고 320/390/1440에서 검증했다. MCP 원형 이미지가 Codex에서 base64 텍스트가 되고 ACP에서 누락되는 결함을 재현해 공용 파서로 보완했다. 독립 검토에서 찾은 반복 이미지의 고아 파일과 Windows 동시 쓰기 충돌도 재사용·원자 저장·잠금으로 수정하고 실패 사유를 구분했다. 최종 58개 테스트와 3개 어댑터 × 2개 화면의 실제 PNG 비교·격리 업로드 해시 검사를 통과했다. 잠금 보완의 독립 대조 시험도 완료했다(잠금 없음 112/120라운드 실패, 있음 120/120 정상). 화면 파일은 운영 GET과 일치하지만 새 이미지 파서는 운영 반영 전이다. 실제 AI/Unity 제작 주기·생산성 비교는 남아 있다. 근거: `../../.ai_logs/pitcrew-audit/round7-result.md`.

캡처 경로 후속 검토에서 남은 `/local-image`의 사전 파일시스템 조회를 보완했다. 외부/UNC 후보를 resolve 전에 거절하고, resolve 후 링크 경계 검사도 유지한다. 관련 32개 시험과 두 화면 너비의 실제 이미지 비교·격리 첨부 회귀를 통과했다. 독립 검토 25가지 입력과 실제 HTTP 보강 시험도 확인했다. 해당 결함은 해소됐으며 운영 서버에는 아직 반영하지 않았다. 근거: `../../.ai_logs/pitcrew-audit/local-image-boundary-result.md`.

최신 콘솔 확보를 보완했다. 설치 connector의 오래된 첫 50행 조회 대신 고정 exec probe로 최신 오류·경고부터 최대 50개를 읽는다. 표시 필터를 일시 변경한 뒤 원래 값으로 복원하고 대조하며, 탐색/표시 한도와 일부 범위만 읽은 경우를 화면·초안에 남긴다. Unity 6000.3 원본 API 및 Coplay의 필터 복원 접근을 비교해 적용했다. 최종 자동 시험 10개, 390/1440 격리 UI, 실제 Unity의 설정 복원 확인을 마쳤고 peer가 찾은 분류·예외 처리 결함도 수정 후 재검토됐다. 실제 로그는 0개였으며 다량 로그는 모의 시험이다. 운영 적용과 실제 게임 제작 전체 주기 검증은 남는다. 근거: `../../.ai_logs/pitcrew-audit/latest-console-result.md`.

6회차는 게임 제작 문맥의 이동을 줄였다. 결과물 패널에서 실제 Unity 씬·오류/경고를 읽고 확인 시각과 함께 기존 초안에 넣는다. 프로젝트 규칙의 `Screenshot: 경로`와 코드스팬 이미지도 결과물 수집→두 장 비교→첨부로 이어진다. 단계 판정은 ‘보고상 완료’로 구분한다. 원리는 Unity AI/Coplay의 에디터 문맥 제공에서 가져왔고, 새 패키지 대신 설치된 unity-cli connector를 재사용했다. 실제 Unity가 연결된 격리 앱에서 조회→초안까지 검증했지만 실제 게임 수정/Play/회귀/새 캡처 전체 주기와 생산성 비교, 운영 backend 활성화는 남았다. 근거: `../../.ai_logs/pitcrew-audit/game-console-round6-result.md`, `game-capture-path-result.md`, `game-capture-handoff-root.json`.

운영 전환 점검에서 잘못된 목표 API 동작값이 중단으로 처리되는 결함을 재현해 수정했다. 명시적인 start/retry/stop 외 요청은 400으로 거절하며 목표와 기준을 보존한다. 시스템 Python·venv의 runtime/웹 proxy 시험이 각각 8개 통과했다. 독립 검토 및 운영 반영은 남아 있다. `../../.ai_logs/pitcrew-audit/runtime-maintenance-handoff-review.md` 참조.

현재 검증 경계는 `../../.ai_logs/pitcrew-audit/game-workflow-acceptance-current.md`를 따른다. 아래 과거 완료 표기는 당시 화면 개선 범위이며, 현재 요청인 게임 제작 전체 흐름과 운영 backend 활성화 완료를 뜻하지 않는다.

결과물 크게 보기의 첨부 재시도·실패 안내·새 응답/승인 알림을 보완하고 독립 검토했다. 이어 오래된 목표의 긴 저장 보고에 본문 찾기·이전/다음·강조 표시를 추가했다. 실제 임시 DB 25개 목표와 15,550자 합성 보고를 웹→런타임 경로로 조회했고, 네 화면 크기에서 검색으로 끝의 실패 기록에 접근했다.
