36: ## 4. Root Cause 찾을 때까지 표층 fix 금지
37: 
38: 증상 ≠ 원인. 같은 증상 반복 = 원인 못 짚은 것.
39: 
40: 세션 27 사례:
41: - 차 박힘 → spawn Y 변경 4회 (0.3, 1.5, 2.5, 0.5). 모두 실패. **root cause = 운전 중 wheel collider/도로 mesh 어긋남일 가능성, spawn 문제 X**. 진단 안 하고 표층 값만 만짐.
42: 
43: 룰: **같은 증상에 같은 종류 fix 2회 실패 → 그 라인 중단, root cause 진단 dispatch**.

45: ## 5. 진단 분해 — 큰 dispatch 1회 → 작은 5회
46: 
47: 진단 subagent에게 "차 박힘 원인 찾아"라고 큰 prompt 주면:
48: - 12분+ hang 위험
49: - 결과가 부정확 (subagent도 ad-hoc 측정 반복)
50: 
51: 해결: 진단을 **명시적 단계**로 분해:
52: 
53: 1. "차 GameObject hierarchy + Rigidbody 모든 필드 dump"
54: 2. "차 모든 Collider 종류·bounds·radius dump"
55: 3. "WheelCollider × 4 suspension/radius/spring dump"
56: 4. "도로 prefab 생성 코드 (BuildingPlacer/RoadBuilder) Read 후 mesh Y 결정 로직 요약"
57: 5. "Play 시작 후 0초/5초/10초 시점 carY + isGrounded + rb.velocity screenshot 첨부"
58: 
59: 각 단계 30초~2분. 합쳐 15분. 한 번에 큰 거 dispatch 시 12분 hang보다 빠름.

112: ## 10. "아직 어색한 거 하나" — 화면 변경 commit 의무 (game-craft-upgrade ①, 2026-05-20)
113: 
114: > 문제: 코드는 통과하는데 사람이 보면 어색한 걸 자체 발견 못 함 (핀 범위·툴팁 위치·공포톤 등 전부 <USER>이 manual play로 발견).
115: > 원인: "컴파일 0 + 에러 0 = 완료" 본능. 자기 결과물을 한 번도 안 봄.
116: > 해법: "느껴봐" X / "안 보면 못 넘어가는 상황 강제" O. commit body에 어색한 점 1개를 의무로 적게.
117: 
118: **언제**: commit이 화면 관련 파일을 건드릴 때 — `.cs`(UI/Camera/Marker/Canvas/HUD/Screen/Tooltip 키워드 포함) / `.unity` / `.prefab`.
119: 
120: **무엇**: commit body에 아래 한 줄 의무. 빈칸·"없음"·형식만 채우기 금지.
121: 
122: ```
123: Feels-off: <지금 이 변경에서 아직 어색하거나 아쉬운 점 1개 — 구체적으로>
124: ```
125: 
126: - "다 좋음" / "없음" 보고 금지. 무조건 1개는 찾는다. 진짜 없으면 "더 나아질 수 있는 점 1개"라도.
127: - 빈약한 답("색이 칙칙함" 같은 모호한 것) 대신, 다음 commit 후보가 될 만큼 구체적으로.
128: - Stop hook이 화면 변경 commit에 `Feels-off:` 없으면 block (자동 강제).
129: - 사소한 docs/markdown/hook-only commit은 해당 X (`[skip-verifier]`와 별개로 화면 파일 안 건드리면 자동 면제).
130: 
131: **왜 이게 핵심**: 매 화면 commit마다 자기 결과물을 한 번씩 강제로 째려보게 만드는 게 목적. 검증 셋(§1)이 "통과/실패"라면 §10은 "더 나아질 여지"를 항상 1개 끌어낸다.
132: 
133: ### §10-③ 스크린샷 강제 (game-craft-upgrade ③, 2026-05-20)
134: 
135: 화면 변경 commit은 `Feels-off:`에 더해 **실제 스크린샷 1장**도 의무. "적어"보다 강한 "보게 만들기".
136: 
137: **방법**:
138: 1. Play 중 `unity-cli menu "PitCrew/Capture/Auto Screenshot"` 실행 → `docs/screenshots/auto/auto_XXXX.png` 생성 (ScreenCapture라 overlay UI까지 잡힘).
139: 2. commit body에 경로 명시:
140:    ```
141:    Screenshot: docs/screenshots/auto/auto_20260520_103000.png
142:    ```
143: 3. Stop hook이 경로 누락 또는 파일 부재 시 block.
144: 
145: **왜 메뉴인가**: `unity-cli screenshot`은 ScreenSpaceOverlay UI를 못 잡음 ([[reference-unity-screenshot-overlay]]). ScreenCapture.CaptureScreenshot만 인게임+UI 둘 다 잡음. Play 중에 찍어야 의미 있음.
146: 
147: **찍고 끝이 아님**: 찍은 png를 실제로 열어 보고, 어색하면 §10 `Feels-off:`에 반영. 사진은 보라고 찍는 것.
