  • 플레이하면서 "오 좋네" 느낌
  • 다른 게임에 비해 떨어지지 않음

→ "느낌" 기반 — 측정 어려움

해결: 룰 자체에 "느낌 기반 보고" 강제

P0S (30m)no-compromise §11 후보

↔️ 도현이 나를 더 잘 쓰는 법 iter 4 · 방향 반전 — 사용자측 개선

"내가 못 하는 것"의 절반은 도현이 정보를 안 줘서. 한 줄 추가로 결과물이 크게 달라지는 패턴들.

U1 · 작업 시작 전 reference screenshot 1장

도현 머릿속에 있는 "이런 느낌" 이미지 1장 던지면 톤 미스 80% 줄어듦.

패턴: "차고 UI 만들어줘 — 이런 느낌(Pacific Drive)" + 스크린샷 1장 첨부.

지금: "차고 UI 만들어줘" → 내가 추측 → 톤 미스

U2 · "이렇게 되면 좋겠다" 1줄 결과 정의

spec보다 "결과 1줄" 먼저. spec은 그걸 만족하는 수단.

패턴: "처음 보는 사람이 차고에 들어가서 5초 안에 '엔진 사면 빨라지겠네' 알아채야 됨."

결과 정의 → 내가 그걸로 자가검증 가능

U3 · manual play 후 "왜 이상한지" 1줄

"이상함" 만으론 부족. "X 때문에 Y 느낌" 형식이 최고.

좋은: "툴팁이 핀에서 100px 떨어져서 시선이 점프됨" → 즉시 root cause 파악
덜 좋은: "툴팁 위치 이상함" → 추측 시작

U4 · 자기 영역 / 내 영역 명시

"이건 너가 결정해" vs "이건 내가 픽할 거니까 옵션만"이 분명하면 막힘 0.

패턴: "톤은 내가 picking 할 거니까 다크/라이트 2버전 만들어줘" — 결정 위임 명시.

이미 no-compromise §6/§8에 박혀 있음 — 사용자도 패턴 인지하면 시너지

U5 · "한 commit에 한 가지만"

UI 폴리시 + 시스템 추가 같이 박으면 어디서 잘못됐는지 분리 못 함.

패턴: 큰 작업 부탁할 때 "단계 나눠서 각 commit 어떤 한 가지인지" 명시.

M1 hook도 이걸 가정함. 한 commit 시각 변경 1건이어야 screenshot 의무 의미 있음.

U6 · 진단 우선 / 구현 후순위

"X 안 됨" 보고할 때 "고쳐줘"보다 "진단부터" 한 단어가 사이클 1번 줄임.

패턴: "차 박힘 — 진단부터" → no-compromise §4 즉시 발동 → 표층 fix 안 함.
"차 박힘 고쳐줘" → 내가 자체 판단 → spawn Y 또 만짐 위험.

U1~U6 6개 중 즉시 적용 추천: U1 + U3 + U5. 도현 머릿속 reference 1장 + manual play 1줄 + commit 한 가지. 3개만 해도 효율 큰 폭 상승.

1. 클릭 영역 손가락 안 들어갈 만큼 작지 않나? (≥44px or ≥3 world units)
2. 텍스트와 배경 contrast 충분? (UITheme.colorText vs panel bg)
3. 처음 보는 사람이 "뭐 해야 되지" 5초 안에 알 수 있나?

5. 변경 안 한 다른 부분이 이 변경 때문에 더 이상해 보이진 않나?

// F1/Assets/Scripts/UI/ErgoConstraints.cs
using UnityEngine;

[CreateAssetMenu(menuName="PitCrew/UI/ErgoConstraints")]
public class ErgoConstraints : ScriptableObject {
    [Header("Click target (Apple HIG 기준)")]
    public float minClickTargetPx = 44f;
    public float minWorldHoverRadius = 3f;  // DeliveryPointMarker 등

    [Header("Tooltip")]
    public float minTooltipDistancePx = 12f;
    public float maxTooltipDistancePx = 40f;

    [Header("Text")]
    public float minContrastRatio = 4.5f;     // WCAG AA
    public float minTextSize = 14f;

    [Header("Color tone")]
    public float maxVignetteForDay = 0.25f;   // 데이 톤이면 ≤0.25
    public float minExposure = 0.0f;          // 너무 어두우면 음수
}

// 사용 예: DeliveryPointMarker.cs OnValidate()
void OnValidate() {
    var ergo = Resources.Load<ErgoConstraints>("ErgoConstraints");
    if (ergo == null) return;
    var hover = GetComponentInChildren<SphereCollider>();
    if (hover != null && hover.radius < ergo.minWorldHoverRadius) {
        Debug.LogWarning(
          $"[Ergo] {name} hover radius {hover.radius:F2} < min {ergo.minWorldHoverRadius:F2}",
          this);
    }
}

# .claude/hooks/stop-screenshot-check.ps1
$staged = git diff --cached --name-only

# UI/Camera/Marker 파일 변경 감지
$visualKeywords = 'UI/|Camera|Marker|Canvas|HUD|Screen\.cs|Tooltip'
$visualChanged = $staged | Where-Object { $_ -match $visualKeywords }

if ($visualChanged) {
    # 직전 1시간 안에 docs/screenshots/auto/ 에 PNG 있는지 확인
    $cutoff = (Get-Date).AddHours(-1)
    $hasShot = Get-ChildItem 'docs/screenshots/auto/*.png' -EA SilentlyContinue |
               Where-Object { $_.LastWriteTime -gt $cutoff }

    if (-not $hasShot) {
        Write-Error @"
M1 위반: visual 파일 변경에 최근 screenshot 없음.
변경 파일: $($visualChanged -join ', ')
unity-cli editor play --wait → screenshot → 다시 commit.
"@
        exit 2  # block commit
    }
}

exit 0
