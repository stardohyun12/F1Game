🎮 왜 클로드는 게임의 어색함을
못 느낄까 — 그리고 어떻게 고칠까

코드는 잘 돌아가는데, 사람이 딱 보면 "이거 이상한데?" 싶은 걸 클로드가 못 잡는 문제. 왜 그런지 + 어떻게 고칠지를 도현이 보기 쉽게 정리했습니다.
2026-05-20 · 자는 동안 정리
먼저 결론: 작업 끝낼 때마다 "아직 어색한 거 하나"를 무조건 적게 하는 규칙 — 이거 하나만 켜도 시작입니다.
5분이면 됩니다. "그거 OK" 한 마디면 다음 작업부터 바로 적용. 나머지는 천천히 하나씩 늘리면 됩니다.

1. 무엇이 문제인가

클로드가 게임을 만들면 코드는 멀쩡히 돌아가는데, 사람 눈으로 보면 바로 어색한 부분을 놓칩니다. 어제 있었던 일들이 전부 그랬습니다.

어제 일어난 일누가 발견했나
핀에 마우스 올리는 범위가 너무 좁아서, 정확히 안 올리면 설명이 안 떴음도현이 플레이하다 발견
설명 팝업이 커서에서 한참 떨어진 곳에 떴음도현이 발견
화면이 공포게임처럼 어두웠음도현이 발견
차가 도로에 박혀서 운전됐음 (5번 고쳤는데 계속 실패)도현이 발견

공통점: 클로드는 "컴파일 됐고 에러 없으니 끝!" 하고 넘어갔습니다. 그런데 도현이 보면 바로 이상한 것들이죠. 즉, 클로드가 자기 결과물을 한 번도 눈으로 안 보고 끝낸 겁니다.

2. 왜 그럴까

사람은 자기가 만든 걸 보면 자동으로 "음, 이거 좀 별론데?" 하고 느낍니다. 그런데 클로드는 그 감각이 없어서, 숫자만 확인하고 화면은 안 봅니다.

🔍 어제 게임을 점검해보니

숫자로 확인하는 건 클로드가 이미 잘하고 있었습니다. 차가 안 박혔는지, 에러가 없는지, 부품들이 연결됐는지 — 전부 통과.

딱 하나, "눈으로 보고 느끼는" 확인만 빠져 있었습니다. 발견된 문제 8개 중에서 숫자로 잡히는 5개는 이미 다 통과했고, 눈으로만 보이는 3개를 못 잡은 거죠.

3. 어떻게 고치나 — 핵심 아이디어 한 줄

클로드한테 "느껴봐"라고 말해봤자 안 됩니다.
대신 "안 보면 못 넘어가는 상황"을 강제로 만들어야 합니다.

예를 들어 "스크린샷을 꼭 찍고 commit해라"라고 규칙을 박으면 — 찍는 순간 이상한 게 눈에 들어옵니다. 안 느끼고 싶어도 보게 되는 거죠. 아래 방법들이 전부 이 원리입니다.

4. 구체적인 방법들 (쉬운 것부터)

① "아직 어색한 거 하나" 적기 5분

작업을 끝낼 때마다 "이거 아직 좀 별로다" 싶은 점 하나를 무조건 적게 만듭니다. 비워두면 작업을 마칠 수 없게요.

→ "다 좋아요" 하고 넘어가는 게 불가능해집니다. 매번 자기 결과물을 한 번씩 째려보게 됩니다.

② 크기 자동 검사 1시간

"버튼은 최소 이만큼 커야 함 / 마우스 올리는 범위는 최소 이만큼" 같은 기준을 미리 정해두고, 어기면 경고가 뜨게 만듭니다.

→ 어제 핀 범위 좁았던 문제 같은 게 자동으로 잡힙니다.

③ 스크린샷 강제 2시간

화면(UI·카메라)을 바꾸면 스크린샷을 꼭 찍어야 commit 되게 만듭니다.

→ 찍는 순간 팝업 위치가 이상하거나 색이 어두운 게 바로 보입니다.

④ "처음 30초" 자동 테스트 2시간

게임 첫 30초를 자동으로 굴려서 중간중간 사진을 찍게 합니다. (메인화면 → 주문 → 출발까지)

→ 스팀 데모에서 제일 중요한 게 첫인상이라, 이게 가장 값집니다.

⑤ "처음 보는 사람" 시점 검토 1시간

다른 AI(또는 별도 검토역)에게 "이 게임 처음 보는 사람이라 치고, 5초 보고 첫인상 한 줄"을 받습니다.

→ 만든 사람(클로드)은 자기 의도를 알아서 못 보는 걸, 모르는 시점이 잡아냅니다. 도현이 물어봤던 "코덱스 같이 쓰기"가 바로 여기 자리입니다.

⑥ 실수하면 자동 기록 1시간

도현이 "이거 이상해"라고 하면 그 내용이 자동으로 기록되고, "어떤 점검이 있었으면 미리 잡았을까"를 적게 합니다.

→ 같은 실수를 반복하지 않게 됩니다.

5. 도현이 한 줄만 더 주면 확 좋아지는 것들

클로드만 고치는 게 아니라, 도현이 작업 줄 때 살짝 더 얹어주면 결과가 크게 달라지는 것들입니다.

참고 이미지 1장

"이런 느낌으로" 하면서 비슷한 게임 스크린샷 한 장 던져주기.

→ 톤이 안 틀립니다. (공포게임처럼 어두워지는 일 방지)

"왜 이상한지" 한 줄

"이상해" 말고 → "팝업이 핀에서 멀어서 눈이 왔다갔다 함" 처럼.

→ 클로드가 추측 안 하고 바로 원인을 잡습니다.

"한 번에 한 가지만"

큰 작업은 "단계 나눠서" 부탁하기.

→ 어디서 잘못됐는지 분리가 쉬워집니다.

6. 만약 이 방법들이 어제 있었다면

핀 범위가 너무 좁았던 문제

실제로 일어난 일

클로드가 만들고 → 숫자만 확인 → "됐다" → 도현이 플레이하다 발견 → 다시 진단 → 수정.

총 30분 + 도현 시간 소모.

"② 크기 자동 검사"가 있었다면

만드는 순간 "범위가 기준보다 좁음" 경고가 뜸 → 바로 수정 → commit.

총 5분, 도현 손 안 감.

팝업이 멀리 떴던 문제

실제로 일어난 일

위치 계산 버그 → 숫자로는 통과 → commit → 도현이 발견.

"① 어색한 거 적기 + 스크린샷"이 있었다면

끝내기 전에 스크린샷 비교 → 100px 떨어진 게 바로 보임 → 수정.

7. 그래서 지금 결정할 것

1
제일 작게 시작 — "① 어색한 거 하나 적기" 규칙만 켜기. (5분)
피곤하면 이것만 "OK" 해도 충분합니다.
2
여유 있으면 — ① + ② 크기검사 + ④ 처음 30초 테스트. (반나절)
스팀 데모 준비 기준으로 가장 효율 좋은 조합입니다.
3
그리고 게임 자체 할 일 — 차고 흐름(정산 → 차고 → 부품 복원 → 재출발)을 아직 한 번도 직접 플레이 안 해봤습니다. 자동으로 굴려볼지, 도현이 직접 해볼지 정해주세요.
한 마디로: "① 규칙 켜줘" 라고만 해도 바로 시작합니다. 더 보고 정하고 싶으면 위에서 골라주세요.

8. 솔직히 확신 못 하는 점

  • "어색한 거 적기"가 진짜 효과 있을지 — 클로드가 형식만 채우고 "색이 좀 칙칙함" 같은 빈약한 답으로 빠져나갈 수도 있습니다. 몇 번 해보고 봐야 압니다.
  • "처음 30초 자동 테스트"는 생각보다 오래 걸릴 수 있음 — 2시간으로 예상했는데, 게임 조작을 자동으로 흉내내는 게 까다로워서 더 걸릴 수도 있습니다.
  • 다른 AI(코덱스) 같이 쓰는 게 정말 나을지 — 같은 클로드로 "처음 보는 사람" 역할만 분리해도 비슷할 수 있어서, 실제 해봐야 압니다.

그래서 한 번에 다 박지 말고, ①번 하나부터 켜고 효과 보면서 늘리는 게 맞습니다.
