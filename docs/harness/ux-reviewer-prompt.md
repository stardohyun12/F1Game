# 외부 눈 UX 리뷰어 — 재사용 프롬프트 (하네스 M6)

> 왜: 시각 incident 6건이 전부 "작성자(나)는 합리화하고, 남의 눈(도현)만 잡음". 작성자=검증자가 시각을 못 본다는 게 일관된 사례. → 도현 자리에 **컨텍스트 0인 다른 에이전트**를 앉힌다.
>
> 언제: 화면 바꾼 commit 직전 (맵·UI·카메라·마커·HUD·화물 룩 등). no-compromise §10의 자동 강제판.
>
> 핵심 규칙: 리뷰어에게 **"무엇을 의도했는지" 절대 말하지 않는다.** 스샷 경로 + "이게 뭐로 보이나"만. 의도를 알면 같이 합리화한다.

## 절차

1. Play 중 스샷: `unity-cli menu "PitCrew/Capture/Auto Screenshot"` → `docs/screenshots/auto/auto_XXXX.png`.
   (씬 룩 검증이면 `unity-cli screenshot --view scene/game --output docs/screenshots/review.png`)
2. 아래 프롬프트로 **fresh general-purpose 에이전트** dispatch. `{스샷경로}` / `{이게뭐여야}` 만 채운다.
3. 리뷰어가 끝에 자기 판정을 피드에 직접 게시 → 대시보드에 👁 빨간 줄로 흐름.
4. 리뷰어 판정 받고 → 깨진 점 fix → (필요시) 재촬영·재리뷰 → 클린해지면 commit.
   **작성자(나)가 "괜찮다" 단독 판정으로 commit 금지.**

## 프롬프트 템플릿

```
너는 이 게임 화면을 처음 보는 사람이다. 무엇을 의도했는지 나는 일부러 안 알려준다.
스샷만 보고 솔직하게 판정해라. 좋게 봐줄 필요 없다 — 결함을 찾는 게 네 임무다.

스샷: {스샷경로}   (Read 도구로 이미지를 직접 열어서 봐라)

보고 (한국어, 짧게):
1. 첫인상 한 줄 — 이게 뭐로 보이나? (장소/물건/화면)
2. 가장 깨지거나 어색한 점 3개 — 구체적 위치와 함께
3. 이게 "{이게뭐여야}"처럼 보이나? 예/아니오 + 한 줄 이유
4. 10점 만점 몇 점, 그 점수인 이유 한 줄

마지막에 네 한 줄 판정을 피드에 게시:
  cd <repo루트> && python .claude/hooks/activity-log.py --post --kind review --who UX리뷰어 --text "<3번 예/아니오 + 핵심결함 한 개>"
```

## 주의

- 리뷰어는 코드/의도/이전 대화 컨텍스트가 없어야 한다 (fresh agent, 이 프롬프트만).
- 점수 자체보다 "예/아니오 + 깨진 점 3개"가 본질. 점수는 추세용.
- 리뷰어가 "좋다"고 해도 그게 끝이 아님 — 결함 3개를 다음 commit 후보로.
- 게임 화면(.cs/.unity/.prefab) commit인데 이 리뷰 안 거쳤으면, 내가 자체 판정한 것 = §10 위반.
