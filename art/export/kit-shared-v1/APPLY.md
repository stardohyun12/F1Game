## UV — 32px/m 유지

**여러 재질이 들어간 atlas 전체에 Repeat를 걸면 다른 재료가 섞인다.** 아래 지정 칸 안에서 반복해야 한다. Point/무 mipmap 조건이며, 선형 필터·mipmap을 쓰려면 별도 gutter 또는 texture array 작업이 필요하다.

- wall/floor/roof는 256×256 칸 네 개. 위왼쪽 `(0,0)`, 위오른쪽 `(256,0)`, 아래왼쪽 `(0,256)`, 아래오른쪽 `(256,256)` 순서가 슬롯 표 순서다. 각 칸은 8×8m.
- 면이 8m를 넘으면 메시를 8m 이내 조각으로 나눠 **같은 칸**에 UV를 다시 시작한다. 칸마다 U/V 양쪽 경계 픽셀이 일치한다. roof F3의 원근 보정한 2×4m 표본은 해당 칸 안에서 반복된다.
- 픽셀 좌표는 좌상단 원점. 칸 시작 `(x,y)`와 안쪽 위치 `(s,t)`가 있을 때 `u=(x+32*s)/512`, `v=1-(y+h-32*t)/512`. 정확히 경계 위를 샘플링하지 않도록 끝점은 안쪽 반 텍셀 범위로 제한한다. 재질 좌표는 `layout.json`이 기준이다.
- 트림은 U 방향만 반복한다. 길이 16m마다 면을 나눠 같은 띠로 돌아온다. V를 띠 밖으로 반복하지 않는다. 긴 세로 문틀·홈통은 UV를 90도 돌려 긴 축을 U에 둔다. 좁은 부품은 띠 전체를 압축하지 말고 실제 폭×32px만 사용한다.

|트림|상단 y / 높이 px|전체 띠의 실물 폭|
|---|---:|---:|
|처마|0 / 16|0.5m|
|창틀|16 / 16|0.5m|
|문틀|32 / 16|0.5m|
|걸레받이|48 / 16|0.5m|
|홈통|64 / 16|0.5m|
|셔터|80 / 48|1.5m|
|유리|128 / 128|4m|
|나무 문|256 / 256|8m|

데칼 사각형은 `layout.json`의 rect_px를 그대로 참조한다. 텍스트 포스터·번지처럼 가까이 보는 작은 인쇄물은 기존 작은 소품 규칙의 64px/m를 사용하고 제작 보고에 기록한다. 시험 집은 표면·트림 32px/m, TEA 표지는 약 32px/m, 포스터·번지 64px/m다. 데칼을 벽 전체에 늘리지 않는다. 빗물/모서리 마스크는 국소 부착만, 면적 합계 12% 이하.

## 색 · 변형

palette.gpl = 기존 garage 기반 40색 + 사진 재료별 가까운 명도 칸, 총 135색. 청록으로 회색 재료를 대체하지 않는다. 회벽 세 색은 같은 A2 결이며 명도 결 ±3%, 기타 재료 ±4%. 디더·합성 노이즈 없음. 원래 사진의 밝은/어두운 재료 경계는 약한 결로 압축했고, AO로 별도 사용하지 않는다.

연속 여섯 건물에는 색·UV 시작점·트림 길이·데칼 조합을 달리한다. 같은 부품은 두 채까지라는 기존 규칙 유지. Embark texture-synthesis는 이번에 실행하지 않았다. 다른 크롭/UV 오프셋은 예시 기반 합성의 재현 결과로 부르지 않는다.

개별 사진 처리: `py -3.13 tools/asset-gen/delight.py art/source/kit-shared-v1/example-job.json`. 네 점은 원본 사진 픽셀 TL→TR→BR→BL. physical_m×32로 크기가 결정된다. 저주파 나누기와 평균색 복원은 linear sRGB에서 처리하고, 사진 결·팔레트는 sRGB에서 제한한다. 의존 버전은 validation.json 참조. 사진에서 조명을 완전히 역산할 수는 없으므로 큰 그림자/얼룩 없는 크롭을 먼저 고른다.

검증 집은 `art/source/kit-shared-v1/proof.blend`와 proof.fbx(제작 검증용). 생산용 새 건물은 아니며 export 폴더에는 PNG/GPL/규칙만 공급한다. 최종 승인 및 실제 게임 셰이더 검증은 별도다.
